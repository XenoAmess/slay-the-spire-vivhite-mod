# sts2-ascend 大模型复盘报告

## 2026-08-22 13:58 — 第 1~2 局大复盘（每 10 局例行，提前触发）

### 一、归因分析

**样本**：2 局，0 胜，最高 11 层，均死于进阶 0 第一幕。

1. **主要死因趋势：血量慢性流失后的"补刀死"**
   - 第 2 局最具代表性：F6 小怪 -21、事件【真理石板】连续解读累计 **-34 HP**、F8 精英 -18，到 F11 进战斗时已近空血，被红宝石掠夺者组合 1 点伤害补刀（"掉血1（阵亡）"）。真正的死因不是最后一战，而是前三段的血量管理失败。
   - 第 1 局仅 3 次决策就到 F9 并阵亡于 BYGONE_EFFIGY，样本噪声大，但同样指向"Unknown 节点产出致命遭遇"。

2. **打法缺陷：事件探索在无经验区盲目放血**
   - 真理石板是多页事件，每一页的"解读/继续解读"都是独立 option_key（n=0），贪心分值全为 0.0，探索率 0.24 又不断随机点未采样选项，导致连点三次解读、单事件 -34 HP。`event_option_value` 本身学习机制正常（DECIPHER_4 已记录 -34），但多页事件经验收敛慢，短期必须靠规避 Unknown 节点解决。

3. **卡组构建问题：两局共拿 2 牌，输出/防御双缺**
   - 第 1 局 0 拿牌（可能含跳牌，但 3 次决策样本太小无法确认）；第 2 局拿 SPITE + SHRUG_IT_OFF，SHRUG_IT_OFF 全场 0 次打出——初始 4 打 4 防之外几乎没有构筑成型，F8 精英战时卡组强度不足以快速减员。
   - 卡牌样本量全部 < 4，未到 reflect.py 自动调 bias 的门槛，且 SPITE（11 分/1 局）还高于全局均值，本次不做任何 bias 修改。

4. **地图路线问题：精英门槛过低 + 从不休息**
   - elite_min_hp_pct=0.55 让 F8 精英在"血量充足（≥55%）"判定下被选中，但 55% 对进阶 0 的初始卡组过于激进；打完精英后 F9~F11 路线（Unknown→Treasure→Monster）没有篝火，rest_urgent_hp_pct=0.35 太低，等触发"急需休息"加权时已无篝火可走。
   - 两局 RestSite 访问 0 次，room_weights 中 RestSite=1.0 明显偏低。

### 二、本次调整（policy.json，逐项保守微调，均在 BOUNDS 内）

| elite_min_hp_pct | 0.55 | 0.65 | F8 精英后连锁失血致死，进阶 0 需更保守的精英进场线 |

- **stats.json 卡牌 bias**：不修改。所有卡牌 picked < 4，样本不足以支撑人工偏置，避免污染统计学习。
- **policy.py 代码**：不修改。通读全文件未发现明确逻辑缺陷：事件 -34HP 是探索机制的既定代价且经验已在累积（DECIPHER_4 已记录负收益）；选路、战斗、篝火、删牌逻辑均与参数表一致工作。死因可用参数调整解释，不动代码。

### 三、新沉淀的经验知识

1. **"掉血1（阵亡）"要回溯归因**：致死战的掉血量接近 0 时，真正死因是此前 2~3 个节点的累计失血，复盘必须看完整 combat_notes 链而非只看死因敌人。
2. **多页事件是经验学习的盲区**：每一页 option_key 独立，探索率会反复尝试"新的一页"，等效于持续放血。短期对策是降低 Unknown 权重，长期等 DECIPHER 系列键全部收敛为负值后贪心自然回避。
3. **进阶 0 的精英线不能低于 0.6**：初始卡组强度下，55% 血进精英的期望收益为负。
4. **篝火是路线规划资源而非紧急按钮**：rest_urgent 触发时往往已无篝火可选，应提高基础权重 + 提前 urgent 线双管齐下。
5. **拿牌过少（<2 牌/局）本身就是危险信号**：卡组强度跟不上层数，后续若仍跳牌严重，需下次复盘检查 card_pick_threshold 是否过高（本次样本不足，暂不动）。
