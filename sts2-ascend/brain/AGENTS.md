# sts2-ascend Brain 工作规则

本目录继承上级与仓库根 `AGENTS.md`。修改 Brain、GLM 复盘宿主、Git 事务或 runner 时必须遵守：

- 没有用户明确需求、真实故障、可复现测试、日志或数据证明必要性，就不得花费模型额度继续考虑或实现新的安全边界。
- 写任何新拒绝条件、固定名单、恢复门禁或防御分支前，先给出必要性证据与收益；证明不了就不做。
- 假设性的 symlink、gitlink、prompt 篡改、路径逃逸不是默认任务。仅在已发生、可复现、用户明确要求，或面临迫近且不可逆的数据损失/凭据泄露时处理。
- 优先相对安全、可观测、可记录、可回退的最小改动；宁可后续运营调整或撤回，也不要为追求绝对安全消耗大量额度、拖延功能闭环或严格限制复盘模型。
- 维护 AI 是 Brain/复盘链的架构师，GLM 是具体复盘执行者。GLM 做错或挂起时必须先诊断机制缺口，并改进输入证据、反馈、自检、进度心跳、失败保全、重试与提交闭环，让后续 GLM 自己完成；不要用维护 AI 长期代写策略代码掩盖机制错误。
