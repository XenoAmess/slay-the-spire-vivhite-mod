# sts2-ascend Brain 工作规则

本目录继承上级与仓库根 `AGENTS.md`。修改 Brain、GLM 复盘宿主、Git 事务或 runner 时必须遵守：

- 没有用户明确需求、真实故障、可复现测试、日志或数据证明必要性，就不得花费模型额度继续考虑或实现新的安全边界。
- 写任何新拒绝条件、固定名单、恢复门禁或防御分支前，先给出必要性证据与收益；证明不了就不做。
- 假设性的 symlink、gitlink、prompt 篡改、路径逃逸不是默认任务。仅在已发生、可复现、用户明确要求，或面临迫近且不可逆的数据损失/凭据泄露时处理。
- 优先相对安全、可观测、可记录、可回退的最小改动；宁可后续运营调整或撤回，也不要为追求绝对安全消耗大量额度、拖延功能闭环或严格限制复盘模型。
- 维护 AI 是 Brain/复盘链的架构师，GLM 是具体复盘执行者。GLM 做错或挂起时必须先诊断机制缺口，并改进输入证据、反馈、自检、进度心跳、失败保全、重试与提交闭环，让后续 GLM 自己完成；不要用维护 AI 长期代写策略代码掩盖机制错误。
- 同一职责边界明确适用于 Luna：维护 AI 不得逐行审计、手工修补、代写或代为合并 Luna 的策略/复盘代码；Luna 必须自行操作隔离仓、自行复核 diff、解决冲突、运行自检、修复失败并完成合并。失败时维护 AI 只修运行器、提示、证据、反馈、自检、队列、提交与自愈机制，再把完整失败证据交还 Luna 闭环。
- 任何失败合入在宿主机制修复后都应重新进入 GLM 工作流；任务必须把原失败包与当前主树差异交给 GLM，让它自己复审、选择性补合、解冲突、跑自检并提交。宿主负责可靠重投和验收，不把“人工补合”当默认终点。
- Brain 的所有自动 Git 事务必须经 `autogit` 统一添加 `[brain:auto] ` 提交标题前缀；维护 Agent 自己完成的额外架构/功能/修复提交使用 `[agent:task] `。保持旧提交兼容，不为此增加会拒绝用户 Git 操作的 hook 或门禁。
- runner-aware 复盘链必须保留完整失败亲和性：模型已实际开始工作后，runner/model/variant/reasoning/审批/sandbox 全部随失败包和队列耐久恢复；只有 provider 尚未开始工作时才可顺位 fallback。生命周期只能识别项目受管 clone 的调用形状，不能绑定 Luna、GLM 或某个审批开关。
