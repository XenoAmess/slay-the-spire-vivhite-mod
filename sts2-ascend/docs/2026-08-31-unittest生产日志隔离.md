# unittest 生产日志隔离

## 问题与修复

完整 `unittest` 会导入并调用 Brain、runner 与 quipper 的日志函数；旧实现把路径在模块导入时固定到生产 `knowledge/`，因此测试会改动 `brain.log` 和 `tts_quipper.log`。

现在三者统一通过 `brain/runtime_paths.py` 解析日志根目录。正常进程仍使用仓库内真实 `knowledge/`；标准 `unittest` 入口会创建进程级临时目录，并用 `STS2_ASCEND_TEST_KNOWLEDGE_DIR` 传给测试启动的子进程。这样无需每个测试分别 monkeypatch 日志对象。

## 验证注意事项

- 回归测试同时调用三条真实日志函数，并比较生产日志的存在状态、字节数、纳秒 mtime 与 SHA-256。
- 完整测试前后也应执行同一元数据比较，不能通过清空、回滚或恢复生产日志来伪造通过。
- 若测试工具自行启动 Python 子进程，应保留继承环境；显式覆盖 `STS2_ASCEND_TEST_KNOWLEDGE_DIR` 时必须指向测试专用目录。
