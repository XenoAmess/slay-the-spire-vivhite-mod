# Native save barrier 异常旧局旁路修复

## 问题

Brain 原先在 API 突然返回新 `run_id` 时，把仍未终局的旧局直接按失败调用
`_finalize()`。这条路径没有经过 `GAME_OVER` 的原生 progression/unlock
物理存档验证，因此会错误增加角色局数、推进 4:1/1:1 轮换并把样本送入 LLM
复盘。

## 修复

- 活动自动局被新局替换，或在主菜单/选人页消失时，不再推断失败。
- 旧局进入 `awaiting_native_save`，以 `in_progress` 增量日志保存旧 `run_id`、
  替换 `run_id`、界面和首次观测时间。
- 等待期间保留轮换账中的旧活动身份，禁止对新局发送动作；重复通知只更新同一
  份证据，不统计、不翻转、不复盘。
- 如果同一旧局恢复到普通游玩界面，判定为暂时状态断流，清除等待标记并继续该局。
- 如果同一旧局恢复到 `GAME_OVER`，只有严格的
  `summary_ready + save_status=verified + save_verified=true + 无 save_error`
  才允许进入普通终局事务。
- 终局日志保存规范化的、绑定 `run_id` 的原生存档证明；跨进程补发轮换时也必须
  验证这份证明，不能再只凭 Brain 自己的统计和终局日志猜测成功。
- 重启时从轮换活动身份和对应增量日志恢复等待上下文。证据缺失或损坏时保持阻塞，
  不会把 API 中的另一局冒充成旧局，也不会无限重复翻转。

## 测试注意

所有会计入统计的 `_finalize()` 定向测试都必须显式提供匹配当前 `run_id` 的已验证
原生 `GAME_OVER` 状态。人工接管排除和残缺局清理仍可以在无证明时关闭，因为这些
路径不会写自动统计、消费轮换配额或进入 LLM 复盘。
