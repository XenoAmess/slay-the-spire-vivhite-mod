## 08 候选评分污染火线记忆

  同一 decision 的全部候选共享决策前 `_sticky_t` 快照（policy.py 原 21140 段）。

  统一沿既有回执链推进：`_combat` 实际选牌后随 play_card 决策挂
  `("focus_commit", target, flip, kill, multi)` 标签；Agent 只在 HTTP 成功后把
  tags 追加进 `credit_tags`，`_sync_action_handshakes` 按列表身份+游标恰好
  消费一次入账。失败/回执丢失不推进任何一项；击杀不翻线、不粘（仍推进
  played 记忆，与旧收口一致）；单敌战斗不推进 played/flips（沿用旧多敌门控）。

## 09 逐 hit 原生限伤与剩余额度

- 原生结算次序（rules_commands.jsonl:12 / powers.jsonl:115/138/254）：
  ModifyDamage（无实体封顶 1，在格挡之前、与滑溜无关）→ 格挡 →
  ModifyHpLostBeforeOsty（硬化外壳钳到本回合剩余额度）→ AfterOsty
  （滑溜把正 HP 损失钳到 1）→ LoseHp → AfterDamageReceived（滑溜仅在
  UnblockedDamage>=1 时掉层）。
- `_attack_outcome` 逐段结算重写：无实体封顶提前到格挡前且不再以
  `slippery<=0` 为条件；硬化外壳改为先钳本 hit 的可扣血量再判定滑溜破层
  （外壳钳到 0 时 UnblockedDamage=0，不掉血不破层）；额度耗尽后保持 0，
  后续 hit 不恢复全额。
- 新增 `_enemy_hardened_shell_remaining`：消费原生可选字段
  `CombatPowerPayload.display_amount`（PowerModel.DisplayAmount 直读，本回合
  剩余 HP 伤害额度）。0 是有效读数；缺失/显式 null/不可读均为未知（None），
  不回填总额度 Amount。未知时评分按总额度封顶做保守上界估计，但击杀结论
  保持未知（不判「可击杀」）。
- **未完成项（跨卡剩余额度正式 API 消费未落地）**：display_amount 由
  STS2-Agent 侧隔离分支提交 3a708e2ce9261093a45041177c0f4c7281f69460 实现并
  通过其 67 项测试，**尚未部署**；Brain 消费者已就绪，但本机 fork
  GameStateService.cs 当前只输出 Amount，生产载荷暂不会携带该字段——线上
  效果等同「未知」口径（保守、不精确斩杀）。不得宣称原生 API 部署已完成。
- 维护方独立反例 test_policy_native_damage_order.py 两项通过。

## 10 拿牌入口遗漏 current_hp

- `_card_selection` 通用奖励排序（原 24889）补传 `current_hp`（读
  `run.current_hp`），与 REWARD 端既有调用一致；同一 offer 两入口评分不再
  分叉。同函数内白绮子选择（置顶/回收/复制）、升级分支，以及 `_bundle` 与
  原生目标直选（升级/移除语义）同步补传，保持各奖励/商店/选择入口上下文
  一致。删牌 badness 的空卡组口径与战斗献祭分支不动。

## 19 固定可用供给估算

- 新增纯 helper `_fixed_supply(entries, energy)`：0/1 背包（能量轴取
  min(预算, 正费成本合计)，有界确定），0 费牌全额计入不占预算，X 费按
  eval_reward_card 的原生三能量名义基线 3 计，负费/不可出牌值剔除。
  精确装箱保证单调：增加可选牌不会降低供给。
- `deck_burst`/`deck_block_burst` 共用该 helper，死牌/坏牌排除口径不变。
- 新增边界契约：X 费名义基线、普通正费精确装箱、负费非供给。

## 20 商店删牌两阶段一致

- `_card_selection` 的 removal badness 与 `_shop` 入口共用同一底线证据：
  未升级基础防御的 40 分优先删除只在删掉后仍守住 `min_block_cards` 时生效；
  同名 ≥3 张注水候选按溢出张数 +6.0/张加价（与商店端 `_copies>=3` 付费资格
  同一判据），冗余攻击先于底线防御被删。强制选择无其他候选时排序仍给出
  合法选择，不新增阻塞门禁。

## 21 沉睡药水斩杀计格挡

- `_maybe_potion` 沉睡闸由 `block < dmg < hp` 改为未格挡口径
  `0 < dmg - block < hp`：穿透格挡真实斩杀与全格挡（UnblockedDamage=0 不
  唤醒）放行，打不死又唤醒才拦截；自然苏醒前最后一回合原有放行不变。
