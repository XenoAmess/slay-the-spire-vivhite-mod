# 战士恢复原版皮肤与白绮资源独占

## 目标与结论

原版 `IRONCLAD` 已从 Vivhite 的外观替换链中移除。Mod 不再为战士注册白绮资源，也不再覆盖
战士的角色选择／转场音频；只有独立 `Vivhite` 角色拥有并校验当前白绮 V3 五页资源 profile。

## 根因

此前 `Entry.Initialize()` 主动调用 `IroncladReplacementAssets.TryRegister()`，后者通过
`RegisterCharacterAssetReplacement(VanillaCharacterIds.Ironclad, profile)` 把完整白绮 profile
注册到原版战士，同时用 Harmony 前缀覆盖战士的角色选择和转场音频。独立白绮又从同一 provider
读取 profile，所以“共享皮肤”不是目录命名造成的，而是明确的运行时注册行为。

## 实现

- 删除入口中的 Ironclad replacement 注册。
- 将 provider 重构为 `VivhiteCharacterAssets`，保留严格 V3 五页、scene、UI、Spine、音频和
  multiplayer 校验，只供独立白绮调用。
- 删除针对原版战士音频 getter 的 Harmony patch。
- 独立白绮继续局部覆盖自己的 energy counter 与 card trail。
- 保留 `res://Vivhite/skins/ironclad/` 物理目录和全部创意资源。该路径是历史打包契约，不再
  表示战士拥有或消费白绮资源；没有移动、重绘或回退任何图片、atlas、Spine 或 scene。

## 自动门禁

新增静态测试覆盖三条不变量：

1. Vivhite C# 源码不得再次出现 Ironclad replacement 注册、旧 provider 或战士虚拟音频补丁。
2. 独立白绮必须直接取得已验证 V3 profile，并保留能量计数器和卡牌轨迹局部覆盖。
3. V3 combat atlas 必须保持 neutral、death、attack、attack-heavy、cast 精确五页顺序，相关
   战斗、商店、休息、选人、UI 和多人资源必须存在。

验证结果：

- `dotnet build Vivhite.Tests/Vivhite.Tests.csproj`：0 warning、0 error。该项目是
  `OutputType=Exe` 的自托管验收程序，不使用普通 xUnit runner。
- `dotnet run --project Vivhite.Tests/Vivhite.Tests.csproj --no-build`：`63/63` 通过。资源相关
  门禁现已验证原版 Ironclad 无 replacement 注册／音频 Harmony 覆盖，Vivhite 独占 V3
  scene、UI、Spine、multiplayer、音频和角色局部 card trail；92 文件库存与 PCK 合同也通过。
- `python -m unittest discover -s tools/art/tests -p 'test_*.py' -v`：`8/8` 通过。
- `dotnet build /p:RunPckExport=false /p:CopyModOnBuild=false`：0 error；34 文件、4 套 Spine
  和 Godot 资源合同通过；最终复跑为 0 warning、0 error。

主线程首次复核发现旧验收仍反射已删除的 `IroncladReplacementAssets`，说明只构建生产项目不足以
证明独立验收工程可用。现已把 `SharedAssetsAcceptanceTests`、`VivhiteCardTrailAcceptanceTests`
与 `RuntimeArtInventoryAcceptanceTests` 全部改到 `VivhiteCharacterAssets`／Vivhite-only 所有权；
删除期待 `TryRegister`、`PrefixIronclad*` 和 Harmony 音频覆盖存在的断言。Python 门禁也不再全局
禁止任意 `HarmonyLib` 或 `TryRegister()`，只拒绝本需求涉及的 Ironclad replacement 具体符号。

## 踩坑与处理

D 盘在编辑期间曾无剩余空间，导致一次补丁写入失败。只清除了工作区内可重新生成的
`Vivhite/bin`、`Vivhite/obj` 和 `Vivhite/.godot/mono/temp` 缓存；所有源文件、创意素材和用户改动
均保留。编辑探针 `Entry2.cs`、`ModEntry.cs`、`apply-patch-probe.tmp`、`tmp_ModEntry.cs` 已删除，
最终树只保留正式实现文件。后续遇到补丁异常时应先检查磁盘空间，再验证目标文件内容，不能把
零字节写入误判为源码问题。

统一启动的第一次尝试还暴露了环境继承问题：新 PowerShell 未在 `PATH` 中找到已安装于
`%LOCALAPPDATA%\Microsoft\dotnet` 的 SDK。为本次验证显式设置 `DOTNET_ROOT` 与 `PATH` 后，
同一个统一入口即完整成功；启动器自动发现修复由独立子任务跟进。
