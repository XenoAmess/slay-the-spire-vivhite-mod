# sts2-ascend 复盘门禁拆除与失败补合

## 问题复盘

`1b492fc`（2026-08-26 10:03:36 +08:00）引入了真实仓“全仓指纹”门禁。它把工作树、index、HEAD/refs、Git 配置以及 ignored 路径的任何变化都纳入复盘前后比较。隔离复盘持续几十分钟时，直播对局提交、正常 push、文档提交和运行日志必然变化，因而 ox-alpha 即使在隔离 clone 中完成了合法修改并通过自检，也会在最终合入前被误判作废。

这套门禁的问题不是检测不够精细，而是验收对象选错了：模型只在无 remote、无 hardlink 的临时 clone 中工作，真实仓的并发变化不等于模型逃逸。继续增加指纹豁免只会形成不断扩张、仍会误杀的规则表。

## 本轮处理

- 完整删除 `workspace_fingerprint`、`fingerprint_changes`、`unsafe_workspace_changes` 及其调用和测试。
- 复盘安全边界回归局部、可证明的链路：隔离 clone、exact allowlist、隔离自检、二进制 patch、私有 index 和 compare-and-swap 提交。
- 复盘期间在线 checkpoint 正常 commit + push，不再等待复盘窗口结束。
- 优先模型与兜底模型超时统一为 480 分钟；长输出只在内存保留 256 KiB 尾部，正常换行事件继续写直播流，病态超大单事件有界截断。
- `review_queue_max` 和 `max_runs_in_packet` 统一为 100；只限制单批规模，持久队列不截断。

## 失败成果保全

超时、非零退出、自检失败、allowlist 拒绝或最终提交冲突时，在删除隔离 clone 前执行 `git add --all --force`，因此 ignored 文件也会进入全量失败快照。宿主随后原子发布：

```text
knowledge/code_backups/review_salvage/<时间-批次>/
  files/                 # 所有仍存在的变更文件，包含越界/ignored 文件
  file_states.json       # 文件、删除、symlink、特殊路径状态
  wip.patch              # 全部变更的 binary/full-index patch
  report.md              # 模型复盘报告（若有）
  model_output_tail.txt  # 失败输出尾部（若有）
  raw_sandbox/           # 捕获异常/拒绝时的完整 sandbox_root（含 repo/.git 与同级越界文件）
  captured_snapshot/     # 热停后异步补齐的完整快照（若有）
  manifest.json          # 基线、模型、局号、失败原因、全部/允许/拒绝路径和大小摘要
```

“保存全部”和“允许自动合入”必须严格分开：补合包保留全部现场以便未来分析；自动提交仍只接受 allowlist 内、通过自检的 patch。补合包不会被程序自动应用。

隔离 clone 与快照从创建起就位于项目 ignored 的 `knowledge/code_backups/review_work/`，不再依赖系统 TEMP。若热停撞上大文件复制，宿主会先在补合包原子发布指针；新 Brain 再从这个项目内受管目录异步补齐。这样 Stop 临界区不搬大文件，指针与原始字节又都留在项目范围内。

## 长期规则

禁止重新加入全仓指纹、全仓脏状态或 refs 变化门禁。若要加强安全，应加强隔离 clone、精确路径验收、自检和提交事务本身，不能让真实仓的正常直播活动成为复盘失败条件。
