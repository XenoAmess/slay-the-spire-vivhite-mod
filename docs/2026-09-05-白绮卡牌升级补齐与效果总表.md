# 白绮卡牌升级补齐与效果总表

## 本次修复

按实际注册的 61 张卡牌逐一核对 `OnUpgrade`、出牌结算、延迟 Power 与中英文本地化，发现两张升级没有实际收益：

| 卡牌 | 基础效果 | 补齐后的升级 |
| --- | --- | --- |
| 色彩守恒 | 0 费罕见能力；謦欬 4；汲取实际回复多少生命，便获得多少格挡 | 謦欬 **4→2**；仍为 0 费，格挡转换比例仍为 1:1 |
| 无限画布 | 3 费稀有能力；謦欬 16；每张通过汲取实际回血的攻击，使本场汲取率永久增加 4 个百分点 | 能量费用 **3→2**；謦欬仍为 16，每次成长仍为 4 个百分点 |

色彩守恒缺少 `OnUpgrade`。无限画布虽然区分基础与升级 Power，但二者均按每次 4 个百分点结算，且升级没有改变其他数值，因此此前升级没有实际效果。修复选择降低启动成本，不改变既有转换和成长规则。

色彩守恒的中英文描述均从 `LifeCost` 动态变量读取费用，实际謦欬支付也读取同一变量；无限画布使用原生 `EnergyCost.UpgradeBy(-1)`，费用变化显示在牌面能量处，无需在正文重复标注。

## 回归与维护要点

- 升级审计不能只检查 `OnUpgrade` 是否非空。星算追猎、无穷星序、守恒递归的升级通过 `OnPlayAfterLifePayment` 中的 `IsUpgraded` 分支生效。
- 能量升级测试必须走 `UpgradeInternal()` 并读取 `EnergyCost.GetWithModifiers(CostModifiers.None)`，再确认 `FinalizeUpgradeInternal()` 后仍保持。`EnergyCost.Canonical` 保留原始费用，不能据其不变而把正常的降费牌误报为升级无效。
- 区分升级 Power 的类型也不能证明效果不同；无限画布的旧实现就是反例。必须追踪到实际结算系数或成本变化。
- 能量升级测试必须读取 `EnergyCost.GetWithModifiers(CostModifiers.None)`；`Canonical` 是原始费用，升级后仍保持初始值。本次首轮新增测试因误读 `Canonical` 报 3，核对本地原生 `CardEnergyCost` 源码后纠正测试口径。
- 两张修复牌的回归使用原生 `UpgradeInternal`；无限画布同时检查升级预览高亮和 `FinalizeUpgradeInternal` 后的减费保留。
- 新增全卡池升级差异检查，以及两张修复牌的精确基础/升级回归断言；固定謦欬数值表同步接纳色彩守恒 4→2，既有 58 张牌的动态费用绑定检查继续覆盖其实际支付入口。
- 旧设计总表混有早期抽牌、汲取与归纳法阵数值。本次只修正其中两张问题牌，并提供本页完整的当前升级表；不可把历史半值重新写回生产代码。
- Brain 静态目录存放两张牌的基础值，本次基础值未改；运行时评估从 API 的 `LifeCost` DynamicVar 与 `energy_cost` 读取当前费用，因此无需改写策略或在线学习记忆。
