# 2026-08-22 战斗"有能量不打牌"决策 bug + 一次回滚事故

## Bug 现象与根因（用户真机发现）

很多回合手里还剩能量却不打牌直接结束回合。日志显示大量
"手牌未就绪，等待稳定（4/4）→ 确认无牌可出（可能无能量），结束回合"。

**实测数据**（连续轮询 mod API）：回合过渡窗口可达 **5 秒**
（空手 → 能量回满 → 手牌逐张浮现 → `play_card` 才出现在 available_actions），
而大脑的耐心只有 4 次×0.6s≈2.4s → **手牌还没抽完就被判"无牌可出"，整回合手牌被白白扔掉**。

## 修复（policy.py `_combat`）

新增 `_saw_playable_this_turn` 回合计忆：
- 本回合**已进入过**可出牌状态 → 现在没的出 = 真出完了，2 次短确认即结束（不拖节奏）
- 本回合**从未进入**可出牌状态 → 还在过渡动画里，长等 15 次（≈9 秒）才允许结束
- 兜底：真全诅咒手牌（play_card 永不出现）会在 9 秒后结束，只慢不错

关键认知：`playable=false` 在过渡期是**不可信的**（能量未回满时全报 not_enough_energy），
不能拿它当结束回合的依据。

## 同期事故：回滚吞掉并发修改（操作教训）

排查中发现修复曾被"神秘还原"。根因链：
1. 我手动触发 `llm_review.py --now`（复盘第 26 局），复盘完成写了 `pending_restart.json`；
2. 随后我改了 policy.py 并**直接 kill 大脑**触发重启；
3. runner 见"大脑非正常退出 + marker 存在" → 按设计 `git reset --hard 复盘前备份点` →
   我的修复、复盘产出的威胁感知评分改进（d93fbd6）、JSON 直播翻译器全被回滚吞掉。

**教训（操作纪律）**：
- 大脑进程携带 `pending_restart.json` 时，kill 它 = 触发 runner 回滚。
  要安全重启大脑：先 `agent.py` 正常流程消化 marker，或确认 marker 已删，或先 commit 再动手。
- 不要在复盘 agent 工作期间并发编辑 `brain/` 同一批文件（它读的是旧快照，写回会覆盖你）。
- 被吞的复盘改进留在提交 `d93fbd6`（威胁感知 `_score_play`），需要时可 cherry-pick 恢复。
