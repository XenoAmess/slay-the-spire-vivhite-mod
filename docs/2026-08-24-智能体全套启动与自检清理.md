# 2026-08-24 智能体全套启动与自检清理经验

记录一次"整套智能体没完全启动"的盘点、清理、重启全过程。
核心是**组件清单 + 乱象根因 + 标准重启流程**三件可复用的东西。

## 一、整套智能体的组件清单（自检起点）

| 组件 | 形态 | 拉起方式 | 自检方法 |
| --- | --- | --- | --- |
| 游戏+mod | SlayTheSpire2.exe | launch_vulkan.bat | `:8080/state?verbose=0` 有响应 |
| runner | `py -3 -u brain\runner.py` | 手动（Start-Agent.ps1） | 进程存在且**唯一** |
| 大脑 | `python -u -m brain` | runner 的子进程 | 进程唯一 + brain.log 在滚动 |
| 吐槽员 | uv 拉起 `tts/quipper.py` | 大脑启动时自动 | `voice_quipper.lock` + tts_quipper.log |
| 复盘+查看器+朗读 | opencode / review_viewer / edge_speaker | **按需**（复盘时自动） | 非常驻，没有不等于缺失 |
| 直播窗 | review_viewer.py 绘制 | 复盘时拉起 | ASCEND-VISION 叠加窗 |

**要点：非常驻组件（复盘链）不在跑 ≠ 没启动；常驻组件必须单实例。**

## 二、发现的乱象与根因（自检清单的反面教材）

1. **review_viewer.py 泄漏**：每次复盘拉起一个直播窗进程，结束后不退出——
   攒了 8 个。属于设计缺陷（拉得起、死不掉），后续应给 viewer 加退出条件。
2. **双 brain 同时驾驶游戏**：旧 brain 没死透又起了新的，两个都在发点击——
   最危险的一种残留（互相抢操作）。runner 只保证"有 brain"，不保证"只有一个"。
3. **陈旧 review_active.flag**：复盘 opencode exit≠0（失败）时 flag 没清，
   残留 49 分钟——会挡住后续复盘调度。判活不能只看 flag，要看
   review_live.stream 的 LIVE-END + review_queue.json 的 reviewing 字段。
4. **uv 拉起的包装 python 有可见控制台**：agent 用 DETACHED_PROCESS 起 uv，
   但 **uv 不给自己的子进程传 CREATE_NO_WINDOW**——Windows 给包装 python
   新分了可见黑窗。上次修的是语音进程*内部*的子调用，这次才是常驻窗的根。
   治法和上次不同：进程启动后自隐藏
   `ctypes.windll.user32.ShowWindow(GetConsoleWindow(), SW_HIDE)`，
   与启动器无关、永远有效（已加进 quipper/edge_speaker/speak_once/speaker 四个脚本）。

## 三、标准清理重启流程（本次实证，顺序重要）

```powershell
# 1. 判活：复盘真在跑吗？（LIVE-END 有 + queue 空 = 空闲，flag 是陈旧）
Get-Content knowledge\review_live.stream -Tail 2; Get-Content knowledge\review_queue.json
# 2. 杀套件：按命令行匹配，宁可多杀不可误杀——
#    "opencode serve" / 裸 "opencode" 是用户会话，绝不能碰
Get-CimInstance Win32_Process | ? { $_.Name -match "python" -and $_.CommandLine -match "sts2-ascend|brain\\runner|-m brain|quipper|review_viewer" } | % { Stop-Process -Id $_.ProcessId -Force }
# 3. 清锁：voice_speaker.lock / voice_quipper.lock / review_active.flag / voice_*speaking/busy.flag
# 4. 验 dll：mods\STS2AIAgent.dll 长度 715776 = fork 构建（715776 以下 = 被 Deploy-Mod 覆盖回上游，需重拷）
# 5. 起 runner（隐藏窗），15s 后验：runner×1 + brain×1 + quipper×1 + brain.log 滚动
# 6. 验证游戏在推进：连取两次 /state，screen/floor 在变化
```

## 四、地图假死（MAP limbo）的识别与恢复

- **症状**：screen=MAP 但 `available_nodes` 空、`is_travel_enabled=False`、
  `is_traveling=False`，大脑反复"地图：无可走节点"——房间该载入没载入。
- **恢复**：调一次 `save_and_quit`——会触发待进入房间完成载入
  （本次直接载入出一个 EVENT 屏，无需走主菜单）。比杀游戏温和，run 不掉。
- **后续**：值得把这个恢复手法加进大脑看门狗（MAP 屏 N 次无动作 → save_and_quit）。
