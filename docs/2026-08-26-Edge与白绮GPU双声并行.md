# Edge 与白绮 GPU 双声并行

日期：2026-08-26

## 问题

把 `llm.tts_mode` 改成 `indextts` 后，复盘启动器只会拉起 `speaker.py`，整段正文都提交给
IndexTTS，`edge_speaker.py` 根本没有启动，所以表现为“Edge 不读了”。这不是 Edge 服务故障，
而是模式路由互斥造成的。

直接把配置改回 `edge` 也不完整：旧 Edge 进程在 `LIVE-END` 后只会退出，不会把最终短结论交给
白绮声音。另外，宿主先写 `LIVE-END`，再把隔离复盘 patch 应用到真实工作树；此时读取全局
`review_conclusion.txt` 会与 patch 合入竞态，可能读到上一场内容。

## 最终路由

```text
复盘实时正文 ──→ Edge TTS（网络失败时仅该句回退 SAPI）

白绮碎碎念 ─┐
             ├──→ 唯一 quipper.py / IndexTTS-2.5 / cuda:0
复盘最终结论 ─┘        （GPT FP16，其余模块 FP32，内部串行）
```

Edge 和白绮声音按用户要求允许同时播放，因此没有增加跨引擎互斥。IndexTTS 自己仍只有一个
GPU owner；最终结论以最高优先级排到等待中的碎碎念前，但不会抢断已经开始的一句。

## 关键实现

1. 生产配置及代码缺省统一为 `tts_mode=edge`，`clone_engine=indextts` 和 `cuda:0/fp16` 保持不变。
2. 隔离复盘完成后，仅当结论文件确属本次 allowlist 变更、已过 selfcheck 且 patch 成功导出时，
   才在临时 clone 删除前读取；同时拒绝 symlink 和越界路径。
3. 结论压成单行后直接放进本场 `LIVE-END` JSON。Edge 不再靠固定 sleep 或全局文件 mtime 猜
   哪一段是本场结论。
4. `LIVE-START/END` 携带唯一 `review_id`；Edge 用有界场次记录去重，并用单一 FIFO worker 保证
   连续复盘的结论不会因多个线程同时等待 GPU owner 而倒序。
5. Edge 收到结束哨兵后，用轻量标准库客户端异步提交 `source=conclusion`；它继续播放已经合成的
   正文，所以两种声音可以同时出声。GPU owner 不可用时只记日志和跳过，绝不加载第二模型或回退 CPU。
6. Edge 清空正文后先释放自身 narrator 锁，再等待白绮结论线程，避免 GPU 结论阻塞下一场 Edge 进程。
7. `speaker.py` 的兼容模式也优先消费哨兵内结论，避免旧的 mtime 竞态。

## 踩坑与注意事项

- `tts.clone_engine` 只是配置声明，真正决定实时复盘进程的是 `llm.tts_mode`；两者不能混为一谈。
- `LIVE-END` 只代表模型输出流结束，不代表真实工作树已经得到 sandbox patch。
- Index 优先级只能重排尚未开始的任务，不能中止正在执行的碎碎念。
- Edge 网络失败允许回退 SAPI；Index 失败不允许回退 CPU。两条失败策略故意不同。
- 不要让 Edge 或一次性脚本 import 并构造 IndexTTS 模型；6GB 显卡只能保留 quipper 的单实例。

## 回归重点

- 默认模式实际拉起 `edge_speaker.py`，而不是 `speaker.py indextts`。
- 新式 `LIVE-END` 只使用内嵌的本场结论；空结论不会拿流尾冒充，旧文件 mtime 会被拒绝。
- Edge 提交的 Index 请求必须恰好使用 `source=conclusion`，owner 未就绪时不得调用合成或 CPU 兜底。
- Edge 正文和白绮碎碎念不互相置 busy/lock；双声重叠是预期行为。
