# 白绮 PCK 四层只读门禁

`tools/test/Verify-VivhitePck.ps1` 将最终 PCK 验收固化为可重复执行的只读流程：

1. 运行现有 Godot 美术事实源，确认源码侧仍为 89/89。
2. 在隔离 PowerShell 子进程中运行现有 `Validate-IroncladSkin.ps1`，检查 Godot 4.5.1、PCK format 3 和 V3 五页 Spine 契约。
3. 按源码字节哈希检查英中每种语言 289 个玩家运行时本地化键，并拒绝旧术语、原始 key 回显及 `NOPE` 文本。
4. 在空临时 Godot 项目中挂载 PCK，逐项读取 61 张卡图、19 个 Power 图标、孤高冠冕 2 图和 7 个能量资源；同时检查专属 import 目标、尺寸及实际解码。

脚本在验证前后比较 PCK SHA-256。空临时项目是必要隔离层：若直接从仓库 Godot 项目加载资源，源码文件可能掩盖 PCK 中真实的资源缺失。仓库 `.tmp` 而非 `%TEMP%` 也避免了受限自动化环境中 Godot 无法看到跨沙箱临时项目的问题。

## Windows PowerShell 5.1 进程与编码契约

不能用 `& $GodotExe` 加 `$LASTEXITCODE` 作为门禁：Windows PowerShell 5.1 对 GUI 子系统可执行文件不会稳定地等待退出。三个外部阶段统一使用 `System.Diagnostics.Process`，关闭 shell execute、重定向 stdout/stderr、先异步排空两条管道，再显式调用 `WaitForExit()`；只有子进程真正退出后才读取退出码和进入下一层。

两份 PowerShell 脚本和本文档均保存为 UTF-8 with BOM。原因不是 Godot 需要 BOM，而是 Windows PowerShell 5.1 会把没有 BOM、包含中文字面量的 `.ps1` 按本地 ANSI 代码页解释，进而在生成 `verify_pck.gd` 前就把“謦欬 / 余裕”损坏。临时 Godot/JSON 文件仍以严格 UTF-8 无 BOM 写入；面向人工取证的日志和 JSON 使用 UTF-8 with BOM，重定向输出则显式按 UTF-8 解码。

## 临时目录与失败证据

每次运行分离两处目录：

- `RepoRoot/.tmp/vivhite-pck-work-<run-id>`：空 Godot 项目、manifest 与运行时校验脚本；
- `RepoRoot/.tmp/vivhite-pck-gate-<run-id>`：输入、控制台日志、哈希与 `failure.json`。

所有临时目录创建、临时文件写入和清理操作都记录到追加式 `RepoRoot/.tmp/vivhite-pck-gate-events.jsonl`。工作目录创建失败时，独立证据目录仍可写入 `failure.json`；成功验证后的工作目录或证据目录清理失败时，该失败本身会成为失败结果，并在生命周期日志和重新建立/保留的证据目录中落盘。只有验证、不可变性检查和两段清理全部成功，门禁才输出最终 PASS。若连 `.tmp` 或生命周期日志都不可写，脚本会把结构化 `[EVIDENCE-FAIL]` 记录写到 stderr，而不会吞掉原始异常。

## 行为测试

`tools/test/Verify-VivhitePck.Tests.ps1` 不依赖 Pester，也不修改 `Vivhite.Tests/Program.cs`。测试会在仓库 `.tmp` 下生成一个合成仓库和一个编译为 Windows GUI 子系统的假 Godot，不读取或修改真实游戏：

1. 给两个假 Godot 阶段加入真实延迟，要求门禁总耗时和完成标记证明两次进程均已退出；
2. 从 Windows PowerShell 5.1 启动门禁，检查生成的 GDScript、捕获日志和失败 JSON 中“謦欬 / 余裕”逐字未损坏，并检查脚本与文档 BOM；
3. 用同名文件真实阻断工作目录创建，验证生命周期日志和 `failure.json`；
4. 用不共享删除权限的真实文件句柄阻断 `Remove-Item`，验证清理失败不会被误报为成功且证据仍在。

这些是可执行行为断言，不再以搜索若干源码字符串代替等待、编码和失败证据验证。测试结束只删除自己创建且已校验位于仓库 `.tmp` 下的 GUID 目录。

该工具消除了已知的 DLL/PCK 撕裂导致的资源型红色 `NOPE` 前提，但不能替代同批 DLL、JSON、PCK 部署后的 Vulkan 真机观察。
