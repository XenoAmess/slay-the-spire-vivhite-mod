# NEOW 多选牌回执确认修复

## 现象

对局 `6D0T5BPUDMG6` 在 NEOW 的“删除两张牌”界面第一次执行
`select_deck_card` 后，Brain 连续记录 11 次“丢失回执”，达到第 12 次轮询阈值后才
释放 pending action 并重新评分。

## 证据与结论

- Brain 日志显示第一次选择的是“白绮的变身式”，释放重评后第二次选择“闭域映射”。
- Godot 日志显示第一次 `POST /action` 在约 10.058 秒后返回 HTTP 200，响应并未丢失。
- 第二次提交时，游戏日志明确记录两张已选牌：
  `VIVHITE_CARD_VIVHITE_TRANSFORMATION` 与
  `VIVHITE_CARD_CLOSED_DOMAIN_MAPPING`。
- 当前牌组也同时缺少上述两张牌，证明第一次点击已经生效。

因此根因是正常的两张牌选择流程缺少协议层进度确认：第一次选择后 UI 合理地停留在
同一 `CARD_SELECTION` 阶段，但 Agent 的牌组选择状态固定报告
`min_select=1`、`max_select=1`、`selected_count=0`，且动作实现等待整个选择界面关闭，
最终把“已完成第一步、等待第二步”报告成 `pending`。MCP 只转发 Agent 状态与动作，
不是本次故障源。

## 最小修复

- 从 `NDeckCardSelectScreen` 的原生 `_prefs` 与 `_selectedCards` 读取最小/最大选择数、
  当前已选数量及确认状态，并写入 selection payload。
- 对尚未达到最小选择数的中间点击，只等待 `selected_count` 增加或界面切换；最后一张
  仍沿用原有确认与界面完成流程。
- Brain 原有 pending-action 判定已经支持用 `selected_count` 增量确认成功，无需修改
  决策或 MCP 转发协议；补充回归测试固定该契约。
