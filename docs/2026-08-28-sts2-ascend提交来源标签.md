# sts2-ascend 提交来源标签

## 问题

`sts2-ascend` 同时存在两类提交：运行中 Brain 自动产生的存档、复盘、失败包恢复/拒合清单提交，以及用户交给维护 Agent 的额外架构、功能和修复任务。只看 `feat/fix/chore/docs` 无法稳定区分这两种来源。

## 方案

新提交采用“来源标签 + 语义类型”两层标题：

- Brain 自动提交：`[brain:auto] chore(sts2-ascend): 第900局存档`
- Brain 复盘代码提交：`[brain:auto] fix(sts2-ascend): 修正能量使用策略`
- 维护 Agent 额外任务：`[agent:task] feat(sts2-ascend): 接入三级复盘链`

`[brain:auto]` 由 `brain/autogit.py` 在所有自动存档和复盘 patch 的公共提交入口统一注入，并保证重试时不重复加前缀。`[agent:task]` 由项目各层 `AGENTS.md` 约定，不依赖 Brain 运行时。

## 兼容性与边界

- 不重写历史；旧的无前缀存档提交仍能被机器接管恢复逻辑识别。
- 不增加 Git hook 或强制拦截；用户自己的临时提交不会因缺少标签被卡住。
- `feat/fix/chore/docs` 仍保留，因为来源标签不替代提交内容的语义分类。
- 标签只表示“谁/什么链路触发了这个提交”，不表示代码质量或审核结论。

## 验证

自动化测试覆盖：存档提交自动标记、复盘 patch 提交自动标记、前缀幂等，以及新旧存档标题同时被历史恢复逻辑识别。
