## 上游清单版本陷阱

官方 v0.9.1 release 和对应源码中的 `STS2AIAgent/mod_id.json` 仍写着 `version: 0.5.4`，而
`mod_manifest.json` 与 DLL 的 `/health.mod_version` 为 `0.9.1`。这是上游双清单未同步造成的显示
差异，不能据 `mods/mod_id.json` 单独判定实际 Agent 版本。

本地验收应优先使用：

1. `/health.data.mod_version`；
2. 官方 release 三件套 SHA-256；
3. fork `main` 的正式 tag/commit。

不要为让文本看起来一致而手改游戏目录中的 `mod_id.json`，否则会破坏与官方 release 的逐字节
对应关系。

## 后续开播行为

`Start-BilibiliLive.ps1` 按既定生命周期调用 `Start-Agent.ps1 -SkipDeploy`，因此会复用上述已经验收的
v0.9.1 安装，不会在开播临界区重新覆盖 DLL。普通冷启动与部署脚本的默认 release 版本也已从
`0.9.0` 更新到 `0.9.1`；本地 fork `main` 当前同样精确对应官方 `v0.9.1`。

若以后切到尚未上游的 feature/fix 分支做真机验证，结束后必须先切回 fork `main` 并重新部署正式
版本，再进入开播流程。
