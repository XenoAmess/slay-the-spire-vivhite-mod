# 2026-09-01 Python 运行时完整性预检

## 背景

一次统一启动期间，`py -3` 解析到了一个只有 `python.exe`/DLL 的复制目录。该解释器虽然退出码为 0，却输出 `Could not find platform independent libraries <prefix>`，并把 `sys.prefix` 锚到当前工作目录；这会让 runner/Brain 在导入阶段失败，不能把“可执行文件存在”当成 Python 可用。

## 当前契约

`sts2-ascend/scripts/Start-Agent.ps1` 在部署、启动游戏或创建 runner 之前执行 `Get-PythonRuntime`：

1. 从 `py -3`、`py -0p`、PATH、Python 注册表和环境变量收集候选解释器/安装目录；候选路径只来自本机发现，不写死账户名或盘符。
2. 对每个组合临时设置候选 `PYTHONHOME`，清空 `PYTHONPATH`，使用 `-S` 导入 `encodings`、`json`、`pathlib` 和 `sysconfig`，并验证标准库与 `encodings` 的真实文件路径位于该 home 内。多行探针以 Base64 传递，避免 Windows PowerShell 5.1 的原生参数引号破坏。
3. 仅接受 Python 3.10+ 且标准库探针完整的组合；全部失败立即抛错，保持 fail-closed，不启动游戏、runner 或 Brain。
4. 启动 runner 前将已验证的 `PYTHONHOME` 注入进程环境并清除 `PYTHONPATH`；runner 的 Brain 子进程通过继承环境使用同一个 home。会话审计记录 `python_exe`、`python_home`、`python_stdlib`、版本和解析来源。脚本退出时恢复调用方环境。

## 证据与验证

本机 `C:\Python314\python.exe` 的完整标准库实际位于 Python 注册表 `PythonPath` 指向的安装目录。预检会拒绝复制目录自身，随后绑定到探针确认的完整 home；未执行 GUI、UAC、Steam 或直播操作。回归测试位于 `sts2-ascend/tests/test_start_agent_python_preflight.py`，覆盖标准库来源约束、环境恢复、fail-closed 文案和 runner 环境审计。

## 后续门禁

若预检失败，必须先修复或安装完整 Python，再重新运行统一入口；不得通过人工点击、复制存档、临时改名或绕过 `Start-Agent.ps1` 启动 Brain。任何后续修改都应继续保持“可执行文件存在 ≠ 运行时完整”的探针证据链。
