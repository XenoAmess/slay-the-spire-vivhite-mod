# SteamMode off 原生模组同意只读预检

## 背景

`--force-steam off` 只跳过 Steam 初始化，并不会替用户完成游戏原生的“加载模组”确认。实际游戏代码在 `SettingsSave.ModSettings == null` 时显示 `NConfirmModLoadingPopup`；未确认时会记录 `user has not yet seen the mods warning`，并跳过 `STS2AIAgent`、RitsuLib 与 Vivhite，因而不会有可用的 8080 API。

实机证据：本地模式使用独立的 `user://default/1` 命名空间，对应 Windows 用户目录 `%APPDATA%\SlayTheSpire2\default\1`。当前该 profile 的 `settings.save` 中 `mod_settings` 为 `null`；Steam profile 的同名设置则已有非空 `mod_settings`，两者不能互相继承。

## 规则

统一入口在显式 `-SteamMode off` 的冷启动、部署或启动游戏之前，只读检查：

1. `%APPDATA%\SlayTheSpire2\default\1\settings.save` 是否存在且可读；
2. JSON 是否有效；
3. `mod_settings` 属性是否存在且非空（这是当前原生弹窗已确认的持久标记）。

任一条件不满足即 fail-closed：不启动游戏、不部署、不复制或改名任何 Steam/本地存档，不写 `settings.save`，不点击 GUI，也不请求 UAC。终端信息会说明需要用户在该本地 profile 亲自启动一次并接受原生模组确认；确认后退出游戏，再重新执行统一入口。`settings.save.backup` 不能替代主文件，避免用陈旧备份伪造同意。

该检查是启动前的诊断门槛，不是 Steam Cloud 修复，也不迁移 Steam profile 数据。即使 marker 存在，仍须由后续真实 `/health`、`/state`、`connected`、`applied` 和连续进展门禁证明训练有效；缺少真实对局证据时保持 Brain/直播 fail-closed。

## 验证

`sts2-ascend/tests/test_start_agent_steam_consent.py` 使用临时 `%APPDATA%` fixture 验证缺失、`null`、畸形 JSON 均拒绝，非空 `mod_settings` 才通过，并检查预检函数不含写文件/启动进程操作。测试不触碰真实 `knowledge/`、`.runtime/` 或游戏存档。
