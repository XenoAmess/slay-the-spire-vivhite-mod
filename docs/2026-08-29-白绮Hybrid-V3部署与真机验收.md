# 白绮 Hybrid V3 部署与真机验收

日期：2026-08-29

## 1. 结论

`hybrid_v3_final` 已发布为正式 `v3-five-page` 运行时，构建出的 DLL、manifest、PCK 三件套已部署到
Slay the Spire 2 v0.111.0，并通过 Source、Godot/Spine、PCK 结构、Vulkan 启动日志和有范围的真机
验收。原版 `IRONCLAD` 槽位现在实际消费白绮 V3；战士玩法、卡组、敌人交互和独立白绮角色没有被
本次发布改写。

本次可以写成“V3 已部署，已完成本轮真机测试”，但还不能把整个战士替换项目写成无条件发布
完成：自然地图路径中的 `map_marker`、双客户端多人手势端到端尚未覆盖；第一幕休息后的
`light_off` 也未在真机观察到。后者已有基础游戏 consumer 调用顺序证据，当前不是图片或 atlas
缺失的证据。

本轮没有付费生成，没有新 Prompt、图片、Alpha 修补或 atlas 像素重编码；部署的五张页图仍是
已验收供体的逐字节副本。

测试结束后已返回主菜单并重新选择 1 号档；主菜单显示原对局仍可“继续游戏”。随后使用统一入口：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\sts2-ascend\scripts\Start-Agent.ps1 -SkipDeploy
```

复用现有 Vulkan 游戏并恢复完整栈。收尾时 session 为
`04da1e639db044c089ba7740d2d3e459`，runner PID `53748`，游戏 PID `51328`，本地 API
`127.0.0.1:8080/health` 返回 `status=ready`。本轮没有操作 Bilibili 直播姬。

## 7. 经验与下一道门禁

- 部署前必须同时备份正式源 runtime、游戏三件套、依赖 Mod 与日志；只备份 PCK 不能还原完整
  现场。
- 真机缩略图出现复杂人体轮廓时，应先放大核对头、躯干和四肢，再结合 atlas region、slot 与
  场景实例数判断；本轮把两条腿误读成第二人，不能据此浪费生成额度或扩张 validator。
- 调试 `room`/`act` 跳转适合快速验证场景消费者，但不能替代自然地图当前位置、事件抽取和多人
  同步路径。
- 下一轮只补有证据的缺口：自然地图 marker、双客户端多人手势，以及在基础 consumer 顺序修复
  或游戏版本变化后复验 `light_off`。当前没有证据支持重新生成任何 V3 人物页。
