# MOSS 本地诊断工具与仓库清理

日期：2026-08-31

## 结果

`sts2-ascend/third_party/MOSS-TTS-Nano/` 是本地语音合成依赖，不是游戏 MCP/HTTP Mod。
此前该目录被根仓意外记录为没有 `.gitmodules` 的孤立 gitlink，导致约 1 GiB 的本地模型和临时
benchmark 文件持续被 Git 客户端报告为嵌套仓库改动。根仓现已解除该 gitlink；目录内容继续由
`sts2-ascend/.gitignore` 保留在本机，不删除模型，也不纳入 Vivhite 主仓版本历史。

四个有复用价值的本地诊断脚本已从第三方工作树迁入正式工具目录：

- `sts2-ascend/tools/benchmark_moss_gpu.py`：CUDA、DirectML 或 CPU 合成测速；
- `sts2-ascend/tools/benchmark_moss_nano.py`：加载一次模型后连续合成的基础测速；
- `sts2-ascend/tools/benchmark_moss_cached_prompt.py`：缓存参考音频编码后的边际耗时；
- `sts2-ascend/tools/dump_moss_onnx_metadata.py`：读取并打印 ONNX 元数据中的紧凑标量和列表长度。

这些工具都从脚本自身位置解析 `sts2-ascend`、模型和参考音频路径，不依赖启动时的当前目录；
可以从仓库根目录或 `sts2-ascend/` 目录启动。迁移时同时修复了原临时脚本中的乱码注释和示例文本。

## 边界

- 本地模型、权重、生成音频和第三方仓库元数据继续留在被忽略的第三方目录；
- 主仓只跟踪可复用诊断工具，不复制约 1 GiB 模型；
- 这项语音仓库清理与 `STS2-Agent` 的终局分数、解锁和 MCP 行为无关；后者位于
  `sts2-ascend/third_party/STS2-Agent/`，由自己的 fork 和提交历史维护。
