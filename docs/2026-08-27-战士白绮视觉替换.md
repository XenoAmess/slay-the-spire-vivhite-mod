# 原版战士 → 白绮完整视觉替换

## 当前实现状态

本阶段只接入原版 `IRONCLAD` 的白绮视觉替换；现有独立角色
`VivhiteCharacter` 的注册、卡池和现有静态资源没有改动。

仓库已经具备完整的提取、AI 美术迁移、发布、构建校验和 RitsuLib 运行时
重定向链路；白绮成品已发布到仓库内运行时目录，并通过离线 Source/PCK 校验。
直播期间没有把成品复制到游戏 `mods` 目录，也没有重启当前游戏。
为便于直接开始制作，从游戏 v0.111.0 提取的 34 项原版战士模板与校验清单
保留在受 Git 跟踪的 `assets/ironclad-v0.111.0/`。这个目录是制作源，
不是 Mod 运行时目录。若运行时成品目录被移除，日志会说明皮肤未发布并继续
使用原版战士；若成品不完整，则整套替换不注册，不会加载一半白绮、一半原版。

## 1. 提取原版制作模板

在仓库根目录执行：

```powershell
py -3 -B .\tools\art\extract_ironclad_assets.py --clean-output
```

工具只读打开游戏的 `SlayTheSpire2.pck`，默认更新仓库中受 Git 跟踪的：

```text
assets/ironclad-v0.111.0/
├─ combat/
├─ merchant/
├─ rest_site/
├─ character_select/
├─ ui/
│  └─ multiplayer/
└─ manifest.json
```

它会完成以下转换：

- `.spskel` 还原为 Spine 可编辑/导入的 binary `.skel`；
- `.spatlas` 的 `atlas_data` 还原为纯文本 `.atlas`；
- `.ctex`、`.s3tc.ctex`、`.bptc.ctex` 通过 Godot 4.5.1 的
  `Texture2D.get_image().save_png()` 解码为 RGBA PNG；
- S3TC/BPTC 的块压缩填充会裁回逻辑尺寸，选人图应为 `3713 × 2427`；
- `manifest.json` 记录游戏/PCK 版本指纹、原路径、PCK payload、MD5、输出
  SHA-256、图片尺寸及必须保留的动画契约；不记录本机绝对路径或生成
  时间，因此同版本重新提取不会制造无意义的 Git diff。

工具只允许将输出写入精确的 `assets/ironclad-v0.111.0/` 制作源根。
`--clean-output` 也只会清理这个受限范围，不能删除仓库或其他目录。再次提取
会重置模板，已开始绘制后应先提交当前修改。

## 2. 在哪里修改

### 战斗与商店

编辑：

```text
assets/vivhite-ironclad/custom/combat/ironclad.atlas
assets/vivhite-ironclad/custom/combat/ironclad*.png
assets/vivhite-ironclad/custom/merchant/ironclad_shop.atlas
assets/vivhite-ironclad/custom/merchant/ironclad_shop*.png
```

`combat/ironclad.skel` 是仓库保留的只读制作模板，不进入 Mod，也不应在当前
texture-only 流程中修改。运行时精确引用游戏 PCK 内的
`res://animations/characters/ironclad/ironclad.skel`。商店继续共享这份骨骼，
只使用自己的私有 shop atlas，并播放 `relaxed_loop`。

战斗骨骼必须保留以下动画：

```text
idle_loop
low_health_loop
relaxed_loop
attack
attack_heavy
cast
hurt
die
```

还必须保留：

```text
slots:  slash_mesh, eye_attach_slot
events: attack_slash_start, heavy_slash_start, cast_eyes_start, clear_vfx
skin:   default
```

这些 slot/event 是原战士攻击效果、眼部效果及清理 VFX 的挂点和触发器；本换皮
保留事件名，但贴图语义已改为紫蓝晶蝶魔法。改名或删除后，
人物本体可能仍能动，但攻击特效会错位或不触发。

### 篝火

编辑：

```text
assets/vivhite-ironclad/custom/rest_site/restsite_ironclad.atlas
assets/vivhite-ironclad/custom/rest_site/restsite_ironclad.png
```

`restsite_ironclad.skel` 同样只作为仓库内只读模板；运行时引用游戏 PCK 内的
`res://animations/rest_site/ironclad/restsite_ironclad.skel`。

必须保留：

```text
glory_loop
hive_loop
overgrowth_loop
_tracks/light_off
_tracks/light_on
skin: default
```

发布器会沿用提取场景里的 `ControlRoot/SelectionReticle/Hitbox/`
`ThoughtBubbleLeft/ThoughtBubbleRight`。当前 texture-only 流程不会修改模板场景；
若以后确实需要调整缩放、碰撞框、选中框或气泡锚点，应另建白绮私有场景制作源，
不要覆盖 `assets/ironclad-v0.111.0/` 模板。

### 选人背景

编辑：

```text
assets/vivhite-ironclad/custom/character_select/characterselect_ironclad.atlas
assets/vivhite-ironclad/custom/character_select/characterselect_ironclad.png
```

运行时引用游戏 PCK 内的
`res://animations/character_select/ironclad/characterselect_ironclad.skel`；仓库内
同名 `.skel` 仍只用于检查布局与动画契约。

必须保留动画 `animation` 和 skin `default`。位置与缩放可在同目录
`scene.tscn` 中查阅；当前发布器只读该模板，不会要求覆盖它。

### UI 与多人手势

替换以下九张图：

```text
assets/vivhite-ironclad/custom/ui/icon.png
assets/vivhite-ironclad/custom/ui/icon_outline.png
assets/vivhite-ironclad/custom/ui/select.png
assets/vivhite-ironclad/custom/ui/select_locked.png
assets/vivhite-ironclad/custom/ui/map_marker.png
assets/vivhite-ironclad/custom/ui/multiplayer/point.png
assets/vivhite-ironclad/custom/ui/multiplayer/rock.png
assets/vivhite-ironclad/custom/ui/multiplayer/paper.png
assets/vivhite-ironclad/custom/ui/multiplayer/scissors.png
```

保持原图画布尺寸通常最稳妥，尤其是四张多人手势。透明背景必须是真正的 PNG
Alpha，不要只把背景涂成黑色或白色。

## 3. Texture-only 编辑约束

- 当前方案不需要 Spine Editor，也不重新导出骨骼；三个跟踪的 `.skel` 只作为
  v0.111.0 制作模板保留在仓库；
- 运行时复用原版的精确版本：combat/merchant 4.2.43、rest-site 4.2.37、
  character-select 4.2.40；
- atlas/PNG 使用 straight alpha（非预乘 Alpha）；
- 保留固定页名和页数：combat 4 页、merchant 4 页、rest-site 1 页、
  character-select 1 页；
- 必须保持 atlas 的 region 名、坐标、旋转、尺寸与原骨骼 attachment/UV 契约
  一致；只替换这些 region 内的白绮像素；
- 不要把 Godot `.import`、`.godot` 缓存、原版 UID 或任何 `.skel/.spskel`
  拷入 Mod 运行时目录。

## 4. 发布到 Mod 私有路径

全部素材修改/重新导出完成后，在仓库根目录执行：

```powershell
py -3 -B .\tools\art\publish_ironclad_skin.py
```

发布器会：

- 从 `assets/ironclad-v0.111.0/` 只读取得 manifest、场景和 skeleton-data 模板，
  从 `assets/vivhite-ironclad/custom/` 取得白绮 atlas、PNG 和 UI；不会要求覆盖模板；
- 严格解码 RGBA8 PNG，拒绝尺寸变化、损坏数据以及仅无损重编码但解码像素仍等于
  提取原件的图片；
- 强制白绮 atlas 文本与 v0.111.0 模板逐字节相同，保护页名、bounds/rotate/offset；
- 保留 `assets/` 下的 `.skel` 模板原件，但绝不复制到运行时目录；
- 将 `.atlas` 包装为运行时 `.spatlas`，并把 `source_path` 改为 Mod 私有路径；
- 重写四份 skeleton-data，使其组合“游戏 PCK 的原版 `.skel` + Mod 私有 atlas”，
  并重写三个场景的私有引用、移除原版 UID；选人场景的红橙渐变/灯光改为紫蓝，
  原战士 `ash2/ash3` 粒子默认隐藏；
- 将目标目录清理并精确镜像为下列 30 个运行时资源，陈旧 `.import`、调试图或旧
  skeleton 不会被静默带入包：

```text
Vivhite/Vivhite/skins/ironclad/
├─ spine/
│  ├─ combat/
│  ├─ merchant/
│  ├─ rest_site/
│  └─ character_select/
├─ scenes/
├─ ui/
└─ multiplayer/
```

Godot 运行时路径统一是：

```text
res://Vivhite/skins/ironclad/...
```

仅验证格式转换、但不触碰可发布目录时，可执行：

```powershell
py -3 -B .\tools\art\publish_ironclad_skin.py `
  --destination .\.work\ironclad-runtime-preview `
  --allow-unchanged
```

`--allow-unchanged` 被硬限制在 `.work/` 下，不能借此把未修改原版素材放进
Mod。

## 5. 构建并让替换生效

必须执行完整构建：

```powershell
cd .\Vivhite
dotnet build
```

完整构建会：

1. 检查源目录恰好对应 30 个逻辑资源，且运行时目录/PCK 中不存在额外私有文件
   或 `.skel/.spskel`；
2. 检查 19 张 PNG 的精确尺寸、`.spatlas` 页/bounds、私有引用以及每套原版骨骼
   的精确 Spine 版本；
3. 以不覆盖 Mod 文件的方式挂载 `SlayTheSpire2.pck`，再使用游戏自带 Spine
   GDExtension 实际加载四套 skeleton-data，检查动画、
   `default` skin、slot 和 event；
4. 在目标目录导出唯一的 staging PCK，确认它是本次新产物且非空；
5. 检查 staging PCK 中没有 `bin/`、`tools/`、`.work/`、原版覆盖路径、复制的
   skeleton 或缺失资源，并直接读取 PCK payload，确认 `.tres/.tscn` 仍为文本且
   原版 skeleton 与私有 atlas 引用均未在导出中丢失；通过后才在同卷原子替换旧 PCK；
6. PCK 完成验收后再将 DLL 和 JSON 部署到游戏 `mods/Vivhite/`。

导出或后验失败时，staging/备份会清理，旧 PCK 保持不变，也不会提前复制
新 DLL/JSON。`RunPckExport=false` 仍保持原有的仅 DLL 构建行为。

校验使用的本地 Spine editor GDExtension 会从游戏 DLL 复制到 Git 已忽略的
`Vivhite/bin/`，并被 export preset 明确排除，不随 Mod 发布。

`dotnet build /p:RunPckExport=false` 只能更新 DLL，不能更新图片、场景或 Spine
资源；视觉修改后不能用它代替完整构建。

需要在直播期间做不部署的离线编译时，同时使用
`/p:CopyModOnBuild=false /p:RitsuLibAutoCopy=false`。项目也会在 no-copy 模式下
自动关闭 RitsuLib transitive auto-copy，避免它绕过本 Mod 的复制开关写入游戏目录。

构建成功后要彻底退出游戏，再通过游戏根目录 `launch_vulkan.bat` 或带
`--rendering-driver vulkan` 的 Steam 启动项重启。PCK 已加载时热更新文件不会
可靠生效。

## 6. 运行时接入方式

`Entry.Initialize()` 会调用 `IroncladReplacementAssets.TryRegister()`：

- 未发布 `combat_skeleton_data.tres` 时，不注册替换，原战士保持完整原版；
- 有素材但任一必要资源加载失败时，聚合记录错误且不注册任何字段；
- 运行时会逐一加载全部 30 个逻辑资源（包括四套 atlas 及十张页图），而不是只
  检查 Profile 直接引用的 13 项；
- 资源完整时，通过 RitsuLib 0.5.14 的
  `ModContentRegistry.For("Vivhite").RegisterCharacterAssetReplacement(...)`
  注册到 `VanillaCharacterIds.Ironclad`。

Profile 只填写本阶段批准的字段：combat skeleton-data、merchant/rest/select
场景、五张 UI 以及四张多人手势。战斗仍使用原版 `ironclad.tscn`，因此保留
原 Bounds、CenterPos、IntentPos、血条/意图锚点和 `NIroncladVfx` 逻辑。

## 7. 真机验收与排错

逐项检查：

- 选人：动态背景、普通/锁定图；
- 战斗：普通攻击、重击、能力、受伤、死亡、低血待机及 relaxed；
- VFX：紫蓝魔法弧和眼部法术出现、位置正确、结束后能清理，手中没有武器；
- 商店/伪商人：`relaxed_loop`；
- 三章篝火：三个章节循环与 light on/off 轨道；
- 顶栏、地图标记、多人四手势；
- 独立白绮仍能选择，战士玩法/卡池/能量球/声音不变。

日志位置：

```text
%APPDATA%\SlayTheSpire2\logs\godot.log
```

常见问题：

- `Ironclad skin is not published`：尚未运行发布器，或 runtime 根没有 combat
  skeleton-data；
- 构建报告 `Missing asset`：只复制了部分文件，重新检查五个 authoring 域并
  再运行发布器；
- `missing animation/slot/event/default skin`：Spine 导出契约被改名或遗漏；
- `atlas ... page`：atlas 页名/页数与 PNG 不一致；
- `No loader found`/贴图不显示：必须完整构建，让 Godot 导入 PNG，并确认
  `.spatlas source_path` 位于相应私有目录；
- 游戏仍显示旧素材：确认完整构建确实更新了 `Vivhite.pck`，然后彻底重启
  Vulkan 游戏；
- 与别的战士皮肤冲突：RitsuLib 的后注册非空字段优先，禁用另一个 Ironclad
  replacement Mod 后复测。

## 经验与踩坑

- 游戏包中的 Spine 文件不是可直接编辑的扩展名，但 `.spskel` payload 本身
  就是 binary `.skel`；`.spatlas` 则是包含 atlas 文本的 JSON wrapper；
- 游戏只附带 Spine template-release DLL，没有官方 editor importer DLL。实测
  该运行时 GDExtension 仍能在 Godot 4.5.1 editor/headless 中加载“已挂载游戏
  PCK 的原版 `.skel` + Mod 私有 `.spatlas`”，因此 texture-only 发布链不依赖
  缺失的 importer，也不分发原版 skeleton binary；
- 新 PNG 必须先让 Godot 导入，才能由 Spine atlas loader 解析；构建校验会自动
  完成这一步；
- 角色选择的 S3TC payload 带块压缩 padding，直接按 payload 尺寸会多出边缘；
  应使用 `Texture2D.get_image()` 返回的逻辑尺寸；
- 需要长期保留的制作源应放在仓库根 `assets/`，而不是 Git 忽略的
  `.work/`；`assets/` 又位于 Godot 项目根 `Vivhite/` 之外，所以会被版本控制
  保留，却不会泄漏进 PCK 或触发运行时换皮；
- Godot GUI 程序在 Windows 上可能在调用方未等待时就返回，导出必须优先启动
  同目录的 `_console.exe`；同时要将本地 .NET 9 路径传给 Godot Mono；
- PCK 不应直接写最终文件后再验证，否则失败构建可能覆盖上一份可用包；
  现在使用同目录 staging + 验证 + `File.Replace` 完成事务式更新；
- Godot 默认会在导出时把 `.tres/.tscn` 转成二进制并提前解析外部依赖；独立 Mod
  PCK 此时看不到游戏 skeleton，可能生成损坏 wrapper。项目固定设置
  `editor/export/convert_text_resources_to_binary=false`，后验也拒绝 `.remap` 代替
  这些文本资源；
- 不采用原版同路径 PCK 覆盖，避免覆盖碰撞，也为以后独立白绮角色的自有资源
  留出清晰命名空间。
