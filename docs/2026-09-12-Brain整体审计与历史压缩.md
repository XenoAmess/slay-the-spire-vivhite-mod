# Brain 整体审计与历史压缩（2026-09-12）

本轮目标是减少历史数据与复盘上下文的持续膨胀，修复实际存档故障，并检查决策、持久化、统计展示、复盘和生命周期之间的边界。所有基准均来自本机只读扫描或离线测试，不表示游戏胜率改善。

## 审计基线

当前活动目录约有 1,800 份局档、587 MB 原始 JSON；训练运行中，数量随新局增加。

| 路径/调用 | 修改前实测 |
| --- | --- |
| Ironclad 根目录 | 1,025 份局档，226,942,281 字节 |
| Vivhite Profile | 773 份局档，359,823,535 字节 |
| Ironclad 最近 10 局 | 读取 1,025 份、226,982,997 字节，5.914 秒 |
| Vivhite 最近 10 局 | 读取 773 份、359,823,535 字节，11.806 秒 |
| 楼层统计冷启动 | 全 Profile 约 22.70 秒；热刷新仍扫描约 1,800 个文件 |
| 复盘原始报告 | 根目录 936 KB，Vivhite 242 KB |
| 逐局 lessons | 根目录 1.41 MB，Vivhite 2.11 MB |

当时最近提示文件分别约 149,883 / 127,684 字符，没有宣称每次请求都超预算。预算缺陷来自可复现的超大输入：旧函数只依次裁三次，之后仍可能超过声明预算；被删的失败决策也未同步计数与完整性标签。

所有已扫描的当前原始局档均无代码版本/commit/boot 戳。因此不能把日期等同具体版本，更不能补造某局使用的代码版本。本轮以显式日期区分历史工作集，原始证据仍可精确恢复。

## 架构判断

- 决策由 `agent → client/policy → action receipt` 驱动，学习与终局写盘、异步复盘、驾驶舱分离，方向合理。保留 POST 不透明重放、人工接管排除学习、Profile 隔离和原生存档证据语义。
- `llm_review.py` 约 11,924 行、295 个函数，同时管理上下文、队列、模型、临时仓库、失败包和 Git 合入；`agent.py` 约 4,687 行；`knowledge.py` 约 2,842 行。继续把可独立测试的上下文/历史维护职责提取成小模块，避免一次重写全部运行器。
- `policy.py` 约 9,993 行、`selfcheck.py` 约 13,258 行，存在长期策略迭代累积。此次不代写已委托复盘模型的具体策略成果，不以缩行数替代行为验证。
- 模型上下文、展示用统计与原始局档应分别消费有界摘要、可缓存投影和按需取回的完整 JSON。原始局档不应每次取最近记录时全量解析。

## 已落实的第一批修复

1. `compact_knowledge.py` 增加 `--archive-before YYYY-MM-DD`。历史正常局不再仅因深层/胜利/最长轨迹永久常驻；默认旧参数行为兼容。保留最近 N、进行中、人工接管、排除学习、孤儿、异常和日期不可信记录。
2. 归档扫描排除 `profile_reset_archives`。本机确实存在该备份子树且原扫描会误认其为在线 Profile，不能为了压缩而二次改写统计重置的原始备份。
3. 新 catalog 投影标记版本，保留原始 `profile_run_number`、真实存在的版本/boot 字段，并区分“卡牌归因未记录”和“明确为空”。
4. 最近局读取按文件名倒序，到足够的合格样本便停止；精确批次继续按原始身份查找，缺失批次的近期背景仍明确标记。归档目录可直接按成员 SHA-256 取证，不为每局重复解析整个 manifest。
5. `_save_run_progress` 仅在真实写盘成功后更新 `_rlog_mark`。注入一次 `OSError` 后，相同快照下一轮立即重试，不再误判为刚刚保存而延后到下一批 15 条决策/换层。

首轮相关归档回归 39 项通过；新增历史读取测试 5 项通过；存档重试及原生恢复相关测试 8 项通过。

读取优化后、尚未实施生产归档时，同样取最近 10 局：Ironclad 只读 10 份、3.04 MB、0.1082 秒；Vivhite 只读 11 份（跳过进行中）、4.69 MB、0.1690 秒。耗时受文件缓存与在线负载影响，主要可靠指标是读取文件数和字节数大幅下降。

## 剩余架构债与边界

- `client.py` 的异常 POST 先做串行端口重发现再交回 Agent。虚拟时钟复现最坏链为 30 秒 POST + 5×3 秒发现 = 45 秒，超过统一停止 40 秒协作窗口；这是故障条件下的延迟上界分析，不是当前直播实测停顿。
- 前台每 20 秒的 `refresh_policy` 与自动 Git 网络 push 共用仓库事务锁；慢 push 的 30 秒超时可能阻塞动作循环。已确认源码依赖，尚无本轮当前会话慢 push 的运行证据。后续应把网络推送移出共享锁，而非减少存档校验。
- 原生身份、统计、学习、轮换配额、失败重审亲和性不因历史压缩而重算。直播和训练继续驻留；代码验证与下一次进程实际加载需要分别报告。
