## 踩过的坑（后续维护必读）

1. **autogit 高频持锁**：训练栈运行时 `.git/index.lock` 被 autogit 事务高频占用，
   人工 git 操作要在间隙重试；commit 时用 `git commit -- <pathspec>` 精确提交，
   避免带走 autogit staged 的运行态文件。发现 stale lock（无 git 进程、锁创建
   时间固定超 15 分钟、autogit 日志反复撞锁）时可删除恢复——autogit 的
   preflight 自愈会处理 pending-sync。
2. **json.dump 重写运行库 policy.json 是格式污染**：sort_keys 重排造成 179 行
   全文件 diff。运行库配置修改必须用文本行级编辑（Edit 工具），不做序列化重写。
3. **大段提取用行级手术脚本**：200+ 行的代码搬移，edit 工具的 oldString 易错；
   按验证过的行号剪切 + AST/文本双通道校验自由变量与导出变量 + 逐行 diff 校验
   段内容零差异。注意从 `if X:` 内层剪出时**降 4 空格缩进**（首次手术因此
   IndentationError）。
4. **selfcheck 是长链状态机**：reflect 的多批次接替链场景（3zt/3zu）用精确净额
   断言串行状态。新增回收/减免通道会注入净额变化——不要脑算，写脚本复刻
   finalize_run 调用序列拿实际值，断言附注净额构成（接替+X / 回收-Y 对账）。
   显式顶格前提的场景（③-bis/③-s 封账）在新通道加入后必须显式重置顶格值。
5. **knowledge 默认绑定 ironclad**：冒烟验证白绮路径要显式构造
   `CharacterProfile(profile_id='vivhite', ...)` 指向临时目录，否则静默走铁甲。
6. **全量 unittest 在栈运行时的环境噪音**：test_test_log_isolation 对日志 mtime
   敏感，偶发失败单独重跑即过；判定标准是看单独重跑而非全量并行结果。
