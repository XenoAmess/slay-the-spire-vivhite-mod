# 白绮素材逐项跑通

## 顺序原则

从静态、小尺寸、无场景依赖的素材开始，每次只完成和验收一项，再进入下一项。
当前顺序为：

1. 顶栏头像 `icon.png`；
2. 顶栏头像轮廓 `icon_outline.png`；
3. 地图标记；
4. 选人按钮；
5. 多人手势；
6. 选人动画；
7. 篝火动画；
8. 战斗与商店动画。

战斗放在最后，因为它同时涉及三分之四侧身视角、人体骨链、多顶点网格、权重、
八个动画和四个 VFX 事件，不能用正面立绘或四顶点平面代替。

## 教训：先识别 atlas 与雪碧图

`characterselect_ironclad.png` 不能被当作一幅完整的选人场景插画。它虽然在肉眼预览中
像四个大块拼在一起，但相邻 `characterselect_ironclad.atlas` 实际声明了 10 个 region：
`bg`、`fire`、`bod`、`back arm`、`top arm`、`hair 1`、`hair 2`、`hair 3`、
`lil hair` 和 `eye shine`。Spine 在运行时按骨骼、slot 和动画重新组合这些区域。

以后处理任何游戏 PNG 时，必须在付费生成前同时完成素材结构分析与源码消费分析：

1. 查找并读取相邻 `.atlas`、`.spatlas`、Spine JSON、`.tres`、manifest 或布局文件；
2. 枚举 page、region、bounds、rotate、offset 和 Alpha 岛，区分完整画面与 packed page；
3. 检索 C#、GDScript、场景文件和可用反编译代码，定位实际加载者与资源重定向入口；
4. 核对 region/slot、动画与事件名、节点锚点、缩放、材质、混合模式、UV 和尺寸约束；
5. 若为 atlas/spritesheet，按“原版素材布局 + 源码消费契约”拆出人物主体、前后肢体、
   头发、特效和背景等语义素材清单；
6. 各语义源逐项生成、验收和分件，最后才确定性打包回 atlas；
7. 禁止把 packed atlas 直接作为一幅画交给模型重绘，也不得把图集页称作单张场景图。

源码暂时不可获得时，要把缺失的消费证据明确列为风险，不能用肉眼推测代替。原战士素材
只说明“文件里有什么”，源代码才说明“游戏如何使用它”；两者必须相互印证。

这一检查不仅适用于 Spine，也适用于普通帧动画、UI spritesheet、tile sheet 和任何把多个
独立图块装进一张 PNG 的资源。
