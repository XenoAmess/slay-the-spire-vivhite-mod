# Workshop 0.2.1 物料版本与预览门禁

本次创意工坊评论复盘把发布物料推进到 `0.2.1`。公开描述的中文和 English
段落都包含同一版号的 `更新日志 / Changelog`，记录了生命支付在 Tungsten Rod /
Buffer 减伤下继续结算、Event Loop 生成牌的战斗内临时/0 费/出牌后 Exhaust，
以及 `public-beta`、`v0.111.0`、Vulkan 的实机验证范围。OpenGL3 和 D3D12
仍明确标为未完成 Mod 专项验收，不作兼容承诺。

## 物料契约

- `workshop/workshop-item.json` 的顶层 `version` 是发布版本；`preview` 对象记录
  当前预览图版本、完整 SHA-256、字节数、尺寸、批准源图哈希和受 Git 跟踪的
  `history_dir`。
- `tools/workshop/New-VivhiteWorkshopPreview.ps1` 只从 metadata 读取版本并绘制
  版本芯片，不再硬编码旧版本。替换生产预览前，先按
  `preview-v<version>-sha256-<full-sha256>.jpg` 归档旧图，并写同名 JSON sidecar；
  哈希冲突或旧图哈希与 metadata 不一致都会 fail-closed。历史目录追加保存，
  不覆盖或自动清理旧证据。
- `tools/workshop/Publish-VivhiteWorkshop.ps1` 无论是否传 `-SkipPreview`，都会核对
  描述中英版号、双语 Changelog、当前预览实际 SHA/尺寸/源图哈希和全部历史
  sidecar；还会从同一 BBCode Changelog 生成运行时 Steam change-note 文件并传给
  uploader。`-SkipPreview` 只跳过重绘，不能绕过陈旧或未登记预览门禁。


本地 `Publish -SkipBuild -PrepareOnly` 在旧 `.runtime/content` 三件套上会停在既有
PCK 内容门禁（旧缓存的 localization hash 与当前源码不一致）；这属于正确的
fail-closed 行为。必须先用当前 `Vivhite/Vivhite.json` `0.2.1` 重新构建同批三件套，
再做最终 PrepareOnly/上传。该流程不自动启动 Steam、游戏、直播或 UAC 授权。
