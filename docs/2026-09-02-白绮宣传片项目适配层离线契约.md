# 白绮宣传片项目适配层离线契约

## 目的

`tools/promo/` 是白绮仓库的项目侧生产层。它把 STS2/白绮的内容、镜头和语义证据投影到 `xar_promo_toolchain` 的通用结构接口；不会把游戏控制、OBS、OCR、Brain、直播或上传实现带入 xAR 核心。

## 已落地边界

- `vivhite_promo.capture_contract` 读取并校验 `vivhite-promo-capture-v1`：相对路径、字节数、SHA-256、单调 marks、clean spans、证据角色和 Vulkan/1080p60 清洁画面门禁；同时固定游戏、Mod、PCK 与 `STS2-RitsuLib 0.5.14` 身份，防止跨构建批次取景。
- 合同可选地绑定 `audio_stems`（例如 `game`、`bgm`、`sfx`）的字节和 SHA-256。只有同一 run 已经准备好旁白且 xAR 版本支持 `AudioMixSpec` 时，composer 才启用多轨混音；否则保留旧的单旁白 ABI，不会静默丢失旁白。
- `VivhiteAdapter` 负责白绮版本/Mod 身份和十个固定 shot 的 span 绑定；`to_xar_receipt()` 通过显式转换输出 xAR canonical `CaptureReceipt`，不把 `natural`、卡牌或 HP 语义传给通用层。
- `VivhitePreset` 固定中文旁白、中英字幕、1920×1080/60 FPS、约十分钟横屏目标和失败尝试保全策略。
- 旁白沿用天朝一期的 `zh-CN-XiaoxiaoNeural`；首片明确 `BGM=disabled`，不在项目侧偷偷加入曲目。
- `pipeline.compose` 遵守 xAR `PipelineComposer` ABI。`validate_only=True` 只创建内存中的 invocation，不解析真实媒体、不启动游戏/录屏器/OCR/TTS/FFmpeg；正式 build 必须先有已验证 contract、旁白和媒体 probe sidecar。
- `claims/claims.json` 只保存主张、镜头、证据角色和待执行 validator 的结构绑定。`status=pending` 不等于语义证明或发布批准。

## 离线 fixture 的限制

`fixtures/minimal_capture/` 中的媒体和证据是极小的合成字节，仅用于路径/哈希/时间线/拒绝逻辑测试，不是可播放录像，也不应进入成片。每次真实录制都必须使用新的 `run_id`/attempt，保留 raw、partial、日志和失败报告，不覆盖旧证据。

The checked-in minimal fixture binds only `game` and `sfx` stems.  The default
preset keeps `include_bgm=false`; `test_vivhite_promo_audio_policy.py` injects a
temporary `bgm` binding and verifies that the adapter rejects it before any
build dependency is resolved.  An authorized BGM must use a new config/run.

## 验证命令

从仓库根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\promo\preflight.ps1 -RunTests
py -3 -B -m unittest discover -s .\tools\promo\tests -p 'test_*.py' -v
```

`-RequireExternalTools` 只在正式取景前使用；未找到有效 OBS 或 FFmpeg 缺少 xAR 所需
`tpad` 能力时必须保持失败关闭。当前机器的 OBS 已由 `configure_obs.ps1` 以精确
Game Capture、1920×1080/60 FPS 配置并验证；预检和 `validate_only` 均不得调用
`Start-Agent.ps1`、直播入口或游戏进程。

## 后续生产门

1. 由白绮侧 producer 写入真实 contract、分轨音频和状态/动作证据，并立即复核哈希。
2. 安装并固定 xAR `0.2.x` release，记录 `ffmpeg-lock.json` 中 FFmpeg/ffprobe 工具指纹；不要依赖私有 checkout 作为发布输入。
3. xAR technical audit、白绮语义 validator、人工 1.0× review 和显式 signoff 全部通过后，才允许 export/平台发布。
