# 白绮选人动画私有骨骼

## 消费契约

- `CharacterAssetProfile.Ui.CharacterSelectBgPath` 消费的是一个 `PackedScene`；132×195 的 `select.png` 与 `select_locked.png` 由另外两个 getter 单独消费，不能把小肖像误当作动态背景来源。
- 原场景的根 `Control` 固定为 2560×1200，`SpineSprite` 位于 `(-185, -20)`，缩放为 `0.46`。这套布局把大型英雄主体放在屏幕右半边，并给左侧说明 UI 留空间。
- 游戏随包的 `NSpineAutoPlayer` 要求自己是 `SpineSprite` 的直接子节点，并要求父骨骼恰好只有一个动画，否则运行时直接抛异常。因此白绮选人骨骼的动画集合必须精确等于 `{ "animation" }`，不能保留辅助动画或测试动画。
- 原版 3713×2427 atlas 是 10 个 region 的 packed spritesheet：`bg`、`fire`、`back arm`、`bod`、`top arm`、`hair 1/2/3`、`lil hair`、`eye shine`。这些名称和原排布不是游戏外部 API；它们只描述原战士私有骨骼。白绮采用自有 region、骨骼、网格和权重。

## 白绮构图与母源

- 选人页使用朝屏幕左侧转约 20–35° 的三分之四英雄姿态。近侧空手向左展开施法，远侧空手向下外展；两臂不交叉躯干，也不出现剑、法杖、书或其他武器。
- 第 0013–0016 次 EvoLink 付费生成均以原生透明 PNG、2:3、2K、high 完整归档。前三次用于探索构图和硬边缘提示；第 0016 次保留第 0015 次的稳定动作与身份并尝试模型内边缘重绘。
- 当前选择第 0016 次作为“整体英雄母源”，工作副本为 `assets/vivhite-ironclad/custom/character_select/sources/vivhite-character-select-hero-master-v1.png`。付费原图仍留在追加式归档，工作副本不覆盖原图。
- 母源周围仍有连续柔光。它可以作为完整英雄展示层保留，但不得把该柔光烘进后续关节切口。若改为多附件切片，每个活动部件必须由 EvoLink 原生透明链单独生成或重绘，并重新验收 Alpha；禁止程序抠图或 Alpha 修补。

## 私有 rig 方向

- 首个可运行版本使用自有多骨骼、多顶点 weighted mesh，不复制原战士的骨骼、网格、权重、region 名或持剑姿态。
- 动画约 5.33 秒无缝循环，只导出唯一的 `animation`：轻微呼吸、头部与身体的缓慢摆动、头发/蝴蝶的滞后运动，以及两只空手的细微漂移。
- 背景和魔法前景是独立视觉层，不能烘进人物关节图。完成后再按自有 atlas 确定性打包，并通过 Godot 4.5.1 + 游戏 Spine GDExtension 做真实加载与逐帧预览。

## 已落地与离线验收

- `tools/art/build_vivhite_character_select_rig.gd` 只读人物与魔法阵两个 EvoLink 原生透明母源，裁去透明留白后做等比缩小与透明画布排版；它不阈值化、不重建、不修补 Alpha。输出为 3713×2427 RGBA8 私有 atlas、一份 Spine 4.2.43 JSON、atlas wrapper 与 skeleton-data wrapper。
- 当前 rig 有 13 根白绮自有骨骼。人物 9×13 网格包含 117 个真正的加权顶点、246 个 influence、192 个三角形与 40 顶点 hull；每个顶点至少受两根骨骼影响，权重和为 1。骨骼分别控制躯干、头、两侧头发、蝴蝶、双臂、裙摆和双腿。魔法阵使用独立刚性 attachment 与独立骨骼，在人物背后缓慢旋转，不把辉光烘进人物关节。
- setup mesh 使用 `x=2213..4385`、`y=-2401..-121`；魔法阵中心为 `(3326,-1159)`，逻辑尺寸 2300×2300。按原场景 `(-185, -20)` / `0.46` 变换渲染后，五帧 Spine 非透明范围为 `x=1123..2199`、`y=53..1149` 的变化区间，四边均未触碰 2560×1200 画布。
- `tools/art/render_vivhite_character_select_preview.gd` 挂载原版 PCK 以取得游戏实际的 Spine GDExtension，但不启动或修改游戏。它用 Vulkan 在 `0%/25%/50%/75%/100%` 采样，检查资源版本、唯一动画、默认 skin、动画时长、非空帧、裁切和像素变化。
- 2026-08-28 最终离线实测为 Vulkan / Windows / Spine 4.2.43，动画时长 5.333333492 秒；五帧得到四个不同哈希，首尾相同形成闭环，全部非空且无裁切。人工检查确认人物与法阵层级正确，白绮完整、空手、无旧战士残片，轻微呼吸、头发/四肢形变与法阵旋转协调。
- Builder 改写 PNG 后必须让 Godot 编辑器执行一次 import；仅用 `--script` 启动预览会继续读取 `.godot/imported` 中的旧 `.ctex`，表现为 atlas 文件已有新 region、运行时却看不到它。应比较源 PNG 与 `.ctex` 的时间戳，并以 Godot 4.5.1 editor `--headless --editor --import` 重新导入后再预览。
- 独立 Mod 工程可加载原版 `NSpineAutoPlayer.cs` 资源路径，却不会把 `sts2.dll` 中的游戏 C# 类型注册成本工程脚本类。因此离线预览严格验证真实场景层级、脚本路径、唯一动画和 Spine 渲染，并显式选择唯一 `animation`；自动播放器的实际 `_Ready` 执行留给真机集成测试，不把这个独立工程限制误报成资源失败。
- 这次只证明选人英雄层自身可运行。完整战士换皮仍保持 fail-closed，必须等 combat、rest-site 与其余契约素材齐全后才允许发布或注册，不能把本次局部通过误报成整包通过。

## 真机验收边界

- 2026-08-28 曾用一次性局部预览分支验证选人 Spine 场景：临时 PCK 与 DLL 在 Vulkan 下进入原版铁甲战士选人页后，白绮人物正常显示和循环且没有启动崩溃。这只是历史验收记录，不是可发布运行模式。
- 一次性环境开关和局部 `CharacterAssetProfile` 注册现已移除。正常代码只有完整 26 文件的 fail-closed 注册路径；combat、merchant、rest-site、character-select、五张 UI 和四张多人手势必须同时通过加载与绑定检查，才会替换原版战士视觉。
- 后续若需单独检查选人场景，只使用离线 Vulkan 预览工具，不再向游戏运行时加入局部替换旁路。完整真机集成测试应在整包发布后进行。

## 踩坑

- 不能通过观察 packed PNG 的几个大块来推断它是一张场景图；必须同时读 atlas、骨骼和真正的代码消费者。
- “包含 `animation`”不足以证明可运行；这里需要精确的单动画集合。静态 publisher 与 Godot 真实加载校验都必须拒绝额外动画。
- 提示词中的“无光晕”不会保证模型遵守。每次返回后都要直接读取 PNG Alpha 并目视检查；失败结果仍须归档，不能用程序清理后冒充合格生成结果。
