# 白绮选人动画私有骨骼

## 消费契约

- `CharacterAssetProfile.Ui.CharacterSelectBgPath` 消费的是一个 `PackedScene`；132×195 的 `select.png` 与 `select_locked.png` 由另外两个 getter 单独消费，不能把小肖像误当作动态背景来源。
- 原场景的根 `Control` 固定为 2560×1200，`SpineSprite` 位于 `(-185, -20)`，缩放为 `0.46`。这套布局把大型英雄主体放在屏幕右半边，并给左侧说明 UI 留空间。
- 游戏随包的 `NSpineAutoPlayer` 要求自己是 `SpineSprite` 的直接子节点，并要求父骨骼恰好只有一个动画，否则运行时直接抛异常。因此白绮选人骨骼的动画集合必须精确等于 `{ "animation" }`，不能保留辅助动画或测试动画。
- 原版 3713×2427 atlas 是 10 个 region 的 packed spritesheet：`bg`、`fire`、`back arm`、`bod`、`top arm`、`hair 1/2/3`、`lil hair`、`eye shine`。这些名称和原排布不是游戏外部 API；它们只描述原战士私有骨骼。白绮采用自有 region、骨骼、网格和权重。

## 白绮构图与母源

- 选人页使用朝屏幕左侧转约 20–35° 的三分之四英雄姿态。近侧空手向左展开施法，远侧空手向下外展；两臂不交叉躯干，也不出现剑、法杖、书或其他武器。
- 第 0013–0016 次 EvoLink 付费生成均以原生透明 PNG、2:3、2K、high 完整归档。前三次用于探索构图和硬边缘提示；第 0016 次保留第 0015 次的稳定动作与身份并尝试模型内边缘重绘。
- 当前选择第 0016 次作为“整体英雄母源”，工作副本为 `assets/vivhite-ironclad/custom/character_select/sources/vivhite-character-select-hero-master-v1.png`。付费原图仍留在追加式归档，工作副本不覆盖原图。
- 母源周围仍有连续柔光。它可以作为完整英雄展示层保留，但不得把该柔光烘进后续关节切口。若改为多附件切片，每个活动部件必须由 EvoLink 原生透明链单独生成或重绘，并重新验收 Alpha；禁止程序抠图或 Alpha 修补。

## 私有 rig 方向

- 首个可运行版本使用自有多骨骼、多顶点 weighted mesh，不复制原战士的骨骼、网格、权重、region 名或持剑姿态。
- 动画约 5.33 秒无缝循环，只导出唯一的 `animation`：轻微呼吸、头部与身体的缓慢摆动、头发/蝴蝶的滞后运动，以及两只空手的细微漂移。
- 背景和魔法前景是独立视觉层，不能烘进人物关节图。完成后再按自有 atlas 确定性打包，并通过 Godot 4.5.1 + 游戏 Spine GDExtension 做真实加载与逐帧预览。

## 踩坑

- 不能通过观察 packed PNG 的几个大块来推断它是一张场景图；必须同时读 atlas、骨骼和真正的代码消费者。
- “包含 `animation`”不足以证明可运行；这里需要精确的单动画集合。静态 publisher 与 Godot 真实加载校验都必须拒绝额外动画。
- 提示词中的“无光晕”不会保证模型遵守。每次返回后都要直接读取 PNG Alpha 并目视检查；失败结果仍须归档，不能用程序清理后冒充合格生成结果。
