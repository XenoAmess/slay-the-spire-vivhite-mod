# Brain 启动握手可观测性复盘

## 背景

2026-09-01 的 Steam-on 冷启动中，游戏 API 最终可以就绪，但 Runner 多次报告
Brain 未在 `imported` 握手前完成启动。原实现把 Brain 子进程的标准输出和错误输出
直接继承给 Runner；子进程很快退出或被启动看门狗终止时，日志只剩一个超时/退出码，
无法区分 Python 环境、复盘 marker、模块导入慢，还是 Brain 自身异常。

## 当前契约

- Runner 用 `stdout=PIPE` 与 `stderr=PIPE` 启动每一代 Brain，并在两个 daemon reader
  线程中持续排空管道，避免子进程写满管道后反向卡死。
- 每个流只保留最后 8 KiB；超时、握手前退出、ready 超时或 Ctrl+C 收束时，诊断行会
  包含两个流的 bounded tail（如有）。捕获失败不会改变退出码或重试语义。
- 每次尝试会写一条 `Brain startup` JSON 诊断，记录 `exe`/`executable`、`prefix`、
  `base_prefix`、继承的 `PYTHONHOME`、绝对 `marker_path`、工作目录和本次 PID。
  `imported`、`ready` 事件额外记录从子进程创建到握手的 `elapsed_s`；失败事件还带
  `return_code` 与子进程输出尾部。
- `STARTUP_IMPORT_SECONDS` 从 5 秒提高到 10 秒，仅缓解已观测的 Windows Python/Git
  I/O 抖动；`OUTAGE_BUDGET_SECONDS` 仍固定为 115 秒，未扩大重试或断流预算。子进程
  仍会在有界期限内被终止，异常不会被吞掉。
- Runner 继续完整继承父进程环境；`PYTHONHOME` 的解析/校验由启动脚本负责，本改动不
  覆盖它，也不改变 Steam、UAC、GUI 或 `knowledge/.runtime` 状态。

## 验证

纯 Python 回归：

```powershell
& 'C:\Python314\python.exe' -B -m unittest discover `
  -s sts2-ascend/tests -p 'test_runner_handshake.py'
```

覆盖双流有界捕获、解释器/marker 字段、Popen 管道契约、`imported` elapsed 记录、
超时诊断以及 10 秒导入上限与 115 秒断流预算分离。测试使用临时对象，不启动游戏、
直播、UAC，也不写入在线 `knowledge/.runtime`。
