# 优雅停止游戏、brain 与播报员

日期：2026-08-26

## 停机顺序

1. 先停 brain，防止它在游戏退出后自动重启游戏。
2. 再停独立的播报进程与复盘悬浮窗。
3. 最后向游戏主窗口发送正常关闭消息，等待 Godot 自行退出。

## 关键机制

- `Start-Agent.ps1` 前台终端的 `Ctrl+C` 是 brain 的首选停机入口。`agent.py` 会捕获 `KeyboardInterrupt`、调用 `Knowledge.save()`，然后让 runner 随正常退出码结束。
- 若旧会话已脱离当前终端，控制台中断可能无法送达。此时必须先精确停掉 `py -> runner.py` 监督链，再停 `-m brain` 子进程；反过来会被 runner 重新拉起。知识库本身实时落盘，这是无法送达 `Ctrl+C` 时的安全兜底。
- 播报进程与 brain 是 detached 关系，停 brain 不会自动停它们。`quipper.py` 是永久循环，目前没有 shutdown 协议；`edge_speaker.py` 可在读到 `LIVE-END` 并播完队列后自然退出，但大量积压时不适合“立即安静”的场景。
- 停播报时要从 `voice_quipper.lock` / `voice_speaker.lock` 读取 PID，校验命令行后只终止对应的 uv/python 进程树。不能泛化杀掉所有 `python` 或 `opencode`。进程确认死亡后再删除陈旧锁，避免 PID 复用造成毒锁。
- 复盘悬浮窗有正常窗口退出路径，使用 `CloseMainWindow()` 可让它自行释放 `viewer.lock`。游戏也应优先使用同样的窗口关闭方式，超时后才考虑强制兜底。

## 本次验证

- 游戏通过主窗口关闭消息正常退出，未使用强制兜底。
- SlayTheSpire2、runner、brain、quipper、edge speaker 和 review viewer 匹配进程均为 0。
- 8080–8090 无监听，语音与悬浮窗运行锁均已清空。
