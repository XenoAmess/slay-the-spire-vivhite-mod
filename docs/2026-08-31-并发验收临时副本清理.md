# 并发验收临时副本清理

日期：2026-08-31

## 问题

白绮 Mod、Brain、PCK 与美术验收并发运行时，多个已完成的隔离仓和测试副本继续占用 D 盘，曾导致私有 Git index 在写对象前报 `No space left on device`。该次提交没有发生，真实 Git index 的 SHA-256 始终保持不变。

## 处理

- 先按目录逐项统计 `.tmp/` 下的实际文件体积。
- 只删除已经完成并关闭的审查/测试隔离副本；每个目标都先解析为绝对路径，并验证它严格位于仓库 `.tmp/` 下。
- 第一批删除 16 个已完成隔离目录，合计 `15.836 GiB`。
- 第二批删除两个已完成的独立审查副本 `rr3`、`rr4`，合计 `2.786 GiB`。
- 总计释放 `18.622 GiB`。

补丁、最终报告、请求参数、Prompt、AI 原图与运行时采用素材均保留。活动子任务目录、游戏、Steam 库、`knowledge/`、复盘取证与 `review_salvage/` 均未删除。

这些隔离副本本身不可恢复，但只包含可重新创建的临时仓和构建产物；其有价值的补丁与审计结论已单独保存在仓库 `.tmp/` 或受跟踪文档中。

## 后续注意

- 长时间并发验收时定期检查 D 盘剩余空间，避免 Git、Godot 或 .NET 在写入中途耗尽空间。
- 只有子代理已经完成并关闭、交付补丁与报告已经复制到根 `.tmp/` 后，才可删除对应隔离目录。
- 不得用广泛通配或递归清理整个 `.tmp/`；活动任务和失败取证必须保留。
