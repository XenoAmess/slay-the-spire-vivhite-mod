## 修复内容

PR 分支新增提交 `74858e1`：

- 用统一的 usability predicate 判断 Godot 对象有效、树中可见且启用。
- 反射候选不可用时继续遍历精确类型 `NUnlockConfirmButton` 后备节点。
- 对所有后备节点先过滤可用性，再选择第一个，避免不可用节点抢占。
- 每次状态轮询只记录一次最终解析结果，避免“反射失败/后备失败”两种签名交替刷日志。
- 日志签名加入 `NUnlockScreen.GetInstanceId()`，保证直接相继的新会话仍各有一条诊断。
- 抽取纯 C# `UnlockConfirmResolutionPolicy`，使候选选择和会话签名不依赖 Godot 真机即可回归。

完整代码复审还发现并处理了两个评论之外的问题：

1. 层级反射被接入原有卡牌状态读取热路径，但每次都会重复扫描类型层级。现在按 `(runtime type, member name)` 缓存不可变的 `MemberInfo` 或 miss，只缓存元数据，不缓存实例值。
2. 原实现遇到最派生同名属性 getter 抛错后会继续查找基类字段，可能把不兼容状态伪装成有效旧值。现在一旦找到最派生成员就保持其优先级；读取失败返回 `null`，不再偷回退到同名基类成员。

## 经验

- “对象有效”不等于“控件可操作”；Godot UI fallback 必须在选择候选前同时检查有效、可见、启用。
- 去重日志如果声称按会话记录，签名必须包含会话实例身份，只有类型和节点路径不够。
- 通用反射 helper 一旦复用于状态序列化热路径，就必须考虑元数据缓存，但不能缓存实例值。
- 最派生成员的读取异常是一种不兼容信号，不应静默暴露同名基类成员。
- 向已经包含旧实现的 fork 主分支同步审查修复时，只移植增量提交；整分支 cherry-pick 会重复引入旧 PR，并污染后续改动。
- 机器人自动标记 Addressed/Resolved 后仍需重新枚举全部评论入口，确认没有新 review、commit comment 或 check annotation。
