# Bilibili 每日定时下播巡检

## 需求与边界

每天北京时间 16:20 开始，持续到 16:40，每分钟检查一次本机是否仍在直播；若直播姬真实状态为
`Streaming`，立即走既有直播姬 GUI 下播流程。下播只改变 Bilibili 推流状态，不能停止游戏、
sts2-ascend、TTS、ASCEND-VISION 或任何其他服务。

时间窗口定义为半开区间 `[16:20, 16:40)`，对应 16:20 至 16:39 共 20 个一分钟槽。计划任务在每个
槽拉起一个短 worker；延迟启动时不补点已经错过的槽，也绝不在 16:40 后下播。

## 实现

- 安装器新增当前用户、`Interactive`、`Highest` 的固定任务
  `\Vivhite\BilibiliLive-DailyStopWatch`，与原 Start/Stop 任务共用受保护目录。
- 三份受保护脚本复制后先逐份验证 SHA-256，再注册或启动任何计划任务；校验失败时不会执行新副本。
- 触发时间先按 Windows `China Standard Time` 计算为北京时间 16:20，再转换成 UTC 写入每日触发器；
  重复间隔为 `PT1M`、时长为 `PT19M`，因此调度点恰好为 16:20–16:39 共 20 次。worker 每次仍重新
  按北京时间验证窗口，形成双重时间边界。
- `Invoke-BilibiliLiveDailyStopWatch.ps1` 是一次性检查。它在启动时、取得共享 GUI mutex 后以及调用
  下播流程前复核北京时间窗口；`Invoke-LivehimeStop` 在实际点击前还会检查同一截止时间，避免
  16:39 槽中的延迟处理越过 16:40 后才点击。每次状态采样只有精确 `Streaming` 才允许继续；`Idle`、
  `Starting`、`Stopping`、`NotRunning`、`Unknown` 和异常全部 fail closed。
- 下播失败不会密集重试，而是记录错误并等到下一分钟；下播成功后仍检查到 16:40，可处理窗口内
  被重新开启的直播。
- 受保护的 Start/Stop worker 与每日 worker 共享命名 mutex。每日检查抢不到锁时不与人工操作并发，
  直接交给下一分钟重试；下播后的游戏/viewer 层级恢复也在释放 mutex 前完成，避免刚启动的人工操作
  被后台恢复动作抢走前台。
- 每分钟都由计划任务重新启动短 worker；即使腾讯电脑管家拦截或终止某一次 PowerShell，后续分钟
  仍有独立调度机会，不存在单个 20 分钟常驻进程的当天单点故障。
- 每次真正进入下播尝试后，无论确认成功还是超时失败，都会复用既有游戏和 ASCEND-VISION 层级恢复
  逻辑。安装器把当前 `sts2-ascend` 根目录作为只读匹配参数传给受保护 worker，避免 Program Files
  副本把 viewer 错认成 `C:\Program Files\brain\review_viewer.py`；不会调用 `Stop-Agent.ps1`、杀进程、
  关闭端口或写入 sts2-ascend 生命周期目录。
- 审计日志位于 `%ProgramData%\VivhiteBilibiliLiveBridge\daily-stop-watch.log`，超过 1 MiB 时只保留
  一个 previous 文件，避免无限增长。

## 安全要点

该流程只使用本地直播姬进程、`bililive_debug.log` 与 Win32 GUI 自动化。它不访问浏览器或 Bilibili
私有 Web API，不使用 OBS 代推流，也不调用 LLM、OpenCode、Minimax 或 OpenRouter，token 消耗为 0。
计划任务动作固定指向 Program Files 中经 SHA-256 校验的 worker；普通工作区修改不能替换已安装副本。

## 验证方法

- PowerShell 5.1 AST 解析所有直播脚本。
- 用 UTC 边界夹具验证 08:20:00Z/08:39:59Z 映射到北京时间槽 0/19，08:19:59Z 与 08:40:00Z
  均在窗口外。
- 验证受保护任务参数携带精确 `ProjectRoot` / `GameDir`，且 deadline 检查位于 Livehime 点击之前。
- 静态禁区测试确认定时 worker 先判断 exact `Streaming`，且不包含服务停止、进程终止、Web API
  或浏览器路径。
- 安装后检查任务的用户、`Interactive`、`Highest`、每日触发器、`PT1M/PT19M` 重复模式、下一次
  运行时间、2 分钟单次执行上限和受保护脚本 SHA-256。
- 不通过伪造时间执行真实下播测试；真实行为由每日窗口与本地直播姬状态共同门控。
