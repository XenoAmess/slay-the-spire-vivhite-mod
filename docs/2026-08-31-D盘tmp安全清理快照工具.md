## 安全边界

工具执行时采用以下失败关闭规则：

1. 必须能独占打开 sts2-ascend/.runtime/lifecycle.lock，并在整个预检与清理期间持有，以避免与统一 Start/Stop 生命周期竞态。
2. session.json、任何运行时 PID 记录、viewer/TTS/review marker 或已知 Stack 进程只要存在，立即拒绝继续。历史 GUID stop sentinel 不作为活动 Stack 证据。
3. 每条相对路径必须以 .tmp/ 开头；拒绝绝对路径、反斜杠、空段、点段和 ..。计算绝对路径后还必须证明其位于当前仓库 .tmp 内。
4. .tmp、路径祖先或目标文件若为 reparse point，立即拒绝，防止 junction/symlink 改变边界。
5. 预检比较长度与 SHA-256；缺失文件记为 SKIP_MISSING，内容变化记为 SKIP_CHANGED。
6. Apply 阶段在每个文件删除前再次复验路径、长度和 SHA-256。只对仍匹配的文件逐个执行 Remove-Item -LiteralPath。
7. 不使用 -Recurse，不删除目录，也不顺手清理空目录。
8. Apply 必须提供固定确认短语；仍可结合 -WhatIf 查看逐文件 ShouldProcess 结果。

## 用法

先通过统一入口停止 Stack。若要保留游戏本体，可执行：

    powershell -NoProfile -ExecutionPolicy Bypass -File .\sts2-ascend\scripts\Stop-Agent.ps1 -KeepGame

停止完成后，先运行默认预览。预览也会验证 Stack 已停止并重新计算 283 项的长度与 SHA-256：

    powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\Remove-SafeTmpSnapshot-20260831.ps1

确认预览结果后执行实际逐文件清理：

    powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\Remove-SafeTmpSnapshot-20260831.ps1 -Apply -ConfirmationPhrase DELETE-SAFE-TMP-SNAPSHOT-20260831

若只想检查 Apply 的 ShouldProcess 路径，可追加 -WhatIf：

    powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\Remove-SafeTmpSnapshot-20260831.ps1 -Apply -ConfirmationPhrase DELETE-SAFE-TMP-SNAPSHOT-20260831 -WhatIf

实际释放量可能低于 29,862,516 字节：快照后缺失或内容变化的文件会被跳过，绝不会按目录模式替代删除。
