# 工作树未提交变更审计

日期：2026-08-30

## 结论

`git status` 显示的大量删除和十几万行变化主要是主 index 异常，不是真实工作文件被批量删除。
审计时共有 791 个“staged delete + 同路径 untracked”配对；791/791 的 clean-filter hash 都与
HEAD 相同。其中 542 个文件字节完全相同，249 个仅体现 CRLF 工作树转换。它们制造了约
228,831 行假删除，不能用 blanket `git add`、`git reset` 或 `git clean` 处理。

30 个 `MM` 路径中，26 个工作树 clean hash 与 HEAD 相同，同样只是 stale index。真正需要按
各自任务继续处理的独立变更为：

- Bilibili 每日定时下播巡检：8 个脚本、测试、技能说明和文档文件，约 +376/-13；
- `tools/art/render_ironclad_skin_preview.gd`：约 +8，属于独立美术上下文；
- 3 个在线 knowledge 日志：由运行中的 Brain 维护，不应手工提交或清理；
- `.tmp` 下 9 张已暂存 PNG，约 9.53 MB，不应混入当前智能体修复；
- `MOSS-TTS-Nano` gitlink 本身未变，其内部 48 个 untracked 文件属于子项目现场。

## 操作约束

- 当前任务只通过私有 index 或项目 autogit 精确提交目标路径；
- 不执行全仓 add/reset/clean，也不把上述独立变更混入 Luna、Edge 或复盘宿主修复；
- 在线 `knowledge/` 和 `.runtime/` 继续由生命周期机制维护；
- Bilibili 巡检、美术预览与临时图片应分别在其原任务上下文中验证和提交。

这份结论是运行中的动态快照；Brain 持续产生 checkpoint 时 HEAD 和在线日志会继续前进，但不会
改变“791 个删除主要来自 stale index、不可整体处理”的判断。
