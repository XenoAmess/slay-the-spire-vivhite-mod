# 白绮透明素材生成规则

## 问题

图像生成模型有时会把素材预览常用的灰白棋盘格直接画进 RGB 图层，同时把整张
PNG 保存为不透明图。界面看起来像“透明背景”并不能证明文件具有有效 Alpha。

## 固定流程（2026-08-28 起）

1. 所有透明素材只能调用 EvoLink `gpt-image-2`：
   `POST https://api.evolink.ai/v1/images/generations`，并固定传
   `background: "transparent"`。不得使用其他模型、供应商、内置生成器、绿幕、
   色键、传统抠图或备用透明化流程。
2. 提示词只写主体、姿势、构图、材质、光照和禁止元素，不写“透明背景”、
   “棋盘格”、“白底”、“灰底”或“绿幕”。透明度只由 API 参数控制；人物母版
   明确禁止主体外光晕、雾状辉光、地面投影和环境光雾。
3. API Key 只通过 `EVOLINK_API_KEY` 环境变量或交互式隐藏输入传入，不得进入
   命令行参数、脚本、日志、元数据、仓库文件或 Git 历史。Key、余额、网络或服务
   不可用时停止，不切换方案。
4. 每次模型返回的原始 PNG 立即另存到仓库，不覆盖、不删除；不合格结果也作为
   模型重试记录保留。
5. 读取实际 PNG Alpha 通道并视觉检查。必须是 RGBA PNG，四角 `Alpha=0`，主体
   内部接近不透明，四边有完整透明留白，非零 Alpha 包围盒不得触碰画布。
6. 棋盘格画入 RGB、外光晕触边、主体半透明或边缘异常时，不使用代码修改 Alpha；
   必须从干净设定图、头像或已验真的 EvoLink 透明参考继续调用同一路径重试。
7. 人物与大范围半透明魔法分层生成，但每一层仍必须使用同一 EvoLink 原生透明
   路径。旧棋盘格、绿幕、色键及其衍生链只作历史保留，禁止进入参考链、atlas
   或运行时素材。

## 经验

- 不要在提示词里模拟文件格式或背景；EvoLink 请求参数负责透明，提示词专注主体。
- 原生透明输出仍可能带大范围半透明光晕，不能只检查四角；必须检查四条边和整个
  非零 Alpha 包围盒。
- 模型重试适合保留发丝、眼镜和半透明魔法边缘；禁止用代码把不合格 Alpha 修成
  “看起来合格”。
- 最终运行素材必须无棋盘格、绿幕、外光晕触边和旧战士残片；每个有判断价值的
  EvoLink 原始版本分别保留，便于比较与继续精修。
