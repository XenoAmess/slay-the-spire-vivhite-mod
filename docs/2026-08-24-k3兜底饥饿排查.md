# 2026-08-24 k3 兜底被优先链永久饥饿排查

## 问题

ox-alpha 复盘路由不可用（exit=1 零输出挂死）时，按设计应"k3 每 5 局兜底"，
实际 **30+ 局（177~208）一次兜底都没触发**。第一轮修复后仍未触发，
继续深挖才发现更隐蔽的第二层根因——**两轮根因叠加，缺一不可**。

## 诊断过程（可复用的判据）

1. 看账：`knowledge/stats.json` 的 `global.runs` 与
   `knowledge/progression.json` 的 `last_llm_review_run` 贴死——
   每次入队都在刷新计数，fallback 的 5 局门槛攒不起来。
2. 看历史：`meta_review.md` 最近成功章节停在第 167~176 局；
   `review_live.stream` 的 LIVE-START 全是 preferred 源、LIVE-END 全 exit=1。
3. 看路由本身：手动 `opencode run --model openrouter/stealth/ox-alpha`
   60 秒零输出挂起——路由确实死了，不是复盘代码问题。
4. **看 brain.log 的 plan 解析行**（第二轮关键）：`优先模型 opencode/ox-alpha
   不在可用清单，看下一优先` 与 `openrouter/stealth/ox-alpha@max 记失败，
   5 分钟内不再尝试本条目` 交替出现——plan 永远落在 preferred。

## 根因（三层叠加）

1. **共用计数器饥饿**：`enqueue_review` 里 `last_llm_review_run` 被 preferred
   （every=1，每局都试）和 fallback（every=5）共用。preferred 每局入队即刷新
   `last`；ox-alpha 冷却仅 5 分钟，一局结束时早过期，下局又走 preferred、
   又刷新、又失败——fallback 门槛 `runs - last >= 5` 数学上永远不可能成立。
2. **执行时重解析抢回**：就算入队时两个优先条目都在冷却（fallback 入队），
   `_run_batch_review` 执行时重新 `resolve_review_plan`，冷却一过期就被
   抢回 preferred，再失败一次——入队决策不被尊重。
3. **plan 来源判兜底在实践中不可达**（第二轮发现，最隐蔽）：
   - 条目1 `opencode/ox-alpha@max` **永久不在 `opencode models` 可用清单**——
     每局只跳过、不记冷却（`preferred_model_state.json` 永远只有条目2 的记录，
     这就是判据）；
   - 条目2 `openrouter/stealth/ox-alpha@max` 在清单里 → 每局必选 → 失败 →
     冷却 5 分钟 → 一局 >5 分钟后过期 → 再选再失败；
   - 两条路"一个永久跳过、一个轮流失败"，`resolve_review_plan` 的 fallback
     分支**永远走不到**。只按 plan 来源决定兜底等于没有兜底。

## 修复（357d06b + 6d4850e + bea8278）

- fallback 源用**独立计数器** `progression["last_fallback_review_run"]`，
  preferred 的尝试（成败与否）不再刷新兜底节奏。
- 队列项携带 `{model, every, source}`；`_run_batch_review` 遇到批内含
  fallback 项时整场用兜底模型，不再无脑重解析。
- **成功复盘守卫**（第二轮核心）：新增 `progression["last_successful_review_run"]`
  ——复盘会话 exit=0（不论是否产生文件变更）即在 `run_review` 里刷新；
  `enqueue_review` 发现 `runs - last_ok >= review_every_runs` 时**无视 plan
  来源强制切兜底**。兜底判据从"瞬时计划"改为"累计结果"。
- 日志只在真实入队时输出守卫信息（原先被门槛拦截的局也记"强制兜底"，误导排查）。

## 验证

- mock 仿真：plan 永远 preferred + 从不成功 → 第 5 局兜底入队（k3）。
- **生产实测**：第 208 局结束守卫触发 → LIVE-START `kimi-for-coding/k3
  (fallback)` → 132k tokens 实干活（读文件/改代码）→ **exit=0** →
  meta_review.md 新增第 199~208 局章节、review_conclusion.txt 语音总结落盘、
  复盘变更提交（7fe3f5f）、`last_successful_review_run=208` 守卫复位。
- 第 209/210 局守卫条件仍满足但被兜底节奏门槛正确拦截（每 5 局一次，不刷屏）。

## 关联发现（未修，备忘）

- `review_active.flag` 在复盘 exit≠0 时**不清除**，反复出现陈旧残留——
  会卡住 autogit 的全量/窄量判断，需要单独修（失败路径补 finally 清理）。
- ox-alpha 路由死亡期间 preferred 每局都白试一次（每局一次无用进程+5 分钟冷却），
  失败次数阈值后拉长冷却（指数退避）可作为后续优化。
- 诊断口诀：**冷却状态文件里"缺记录"也是信号**——条目1 永远没出现在
  `preferred_model_state.json`，说明它根本没走到"记失败"那一步。
