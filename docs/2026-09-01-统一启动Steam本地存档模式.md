# 统一启动入口的 Steam 本地存档模式

## 背景

无人训练需要保留游戏的本地 `profile*/saves/current_run.save`。Steam 云同步在进程
异常退出或跨进程恢复时可能把云端状态同步回来，造成当前局存档被覆盖或删除。直接改
Steam 客户端、游戏目录或云文件既不可审计，也可能需要人工权限，因此本次只调整统一
启动入口的进程参数。

## 实现

`sts2-ascend/scripts/Start-Agent.ps1` 新增 `-SteamMode auto|on|off`：

- `auto`（默认）和 `on` 保留游戏默认 Steam 初始化，不追加命令行覆盖参数；
- 只有显式 `off` 才在冷启动 `launch_vulkan.bat` 时传入两个参数
  `--force-steam off`，使游戏跳过 Steam 初始化并使用本地存档路径；
- session 元数据记录 `steam_mode`、`steam_launch_arguments` 和
  `steam_mode_applied`，可核对请求是否实际作用于新游戏进程；
- 已运行的游戏不会被重启或修改。若需要切换模式，先用统一 `Stop-Agent.ps1` 停止整套，
  再以 `-SteamMode off` 冷启动；不执行 UAC、人工 GUI 或 Steam 文件写入。

## 使用与边界

生产训练基线是默认 `-SteamMode auto`（或显式 `-SteamMode on`）：保留游戏默认 Steam 初始化，
并沿用已完成原生模组同意的 Steam profile。`off` 不是生产训练的故障回退，也不是 Steam Cloud
修复，只能用于下述已完成独立 profile 同意的显式诊断/隔离实验。

```powershell
# 仅诊断/隔离实验（独立 profile 已完成原生模组同意后）
powershell -NoProfile -ExecutionPolicy Bypass -File .\sts2-ascend\scripts\Start-Agent.ps1 `
  -SteamMode off
```

该参数只控制本次游戏进程的 Steam 初始化，不伪造原生 Continue/存档证据，也不替代孤儿局
恢复门禁。它只适用于已完成本地 profile 原生模组同意、并明确接受独立存档命名空间的会话。
若启动时已有游戏进程，日志会明确标记 `steam_mode_applied=false`；不能把这种
附着运行误报为本地模式已生效。

### 首次本地 profile 的原生确认门槛

实机冷启动验证显示，`off` 会落到独立的 `user://default/1` profile；它不继承 Steam profile
的 `ModSettings` 或“已同意加载模组”标记。若日志出现 `user has not yet seen the mods warning`，
游戏会跳过 `STS2AIAgent`、RitsuLib、Vivhite，因而没有 API 监听。无人值守时不得自动点击确认框，
也不能把该状态当作 Brain/API 故障；必须保持训练和直播 fail-closed，待该 profile 已完成原生同意
后，再以真实 `/state`、动作回执和连续进展验收。

## 验证

新增 `sts2-ascend/tests/test_start_agent_steam_mode.py`，在不启动游戏的隔离 PowerShell 中
验证三种模式的参数映射、冷启动分支和文档约束：`auto|on` 输出空参数，`off` 输出
`--force-steam,off`。测试只读取脚本/文档，不触碰 `knowledge/` 或 `.runtime/`。
