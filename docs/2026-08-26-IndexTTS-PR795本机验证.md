环境：

- Windows 10 Pro for Workstations 10.0.18363
- Python 3.11.13
- pytest 9.1.1
- PyTorch 2.8.0+cu128
- 独立工作区：`D:\workspace\index-tts-low-vram-pr`
- 分支：`feat/reference-encoder-offload`

生产虚拟环境中已有 IndexTTS 依赖，但没有 pytest。为避免同步或污染生产 venv，pytest 由 `uv tool run`
放在隔离工具环境中运行，并通过 `PYTHONPATH` 只读复用生产环境依赖。

执行的测试节点：

```text
tests/test_v2.py::test_25_reference_embedding_uses_separate_reference_device
tests/test_v2.py::test_25_emotion_reference_cache_refreshes_only_when_path_changes
tests/test_v2.py::test_25_speaker_reference_cache_hit_skips_preprocessing
tests/test_v2.py::test_25_speaker_reference_cache_miss_routes_devices
```

最终结果：

```text
4 passed, 3 warnings in 21.47s
```

3 个 warning 来自导入的 SWIG/librosa 依赖，均为 deprecation warning，与本次改动无关。

第一次启动隔离 pytest 时只加入了生产 venv 的 `site-packages`，没有把 PR 根目录加入 `PYTHONPATH`，
因此测试在收集后全部因 `ModuleNotFoundError: No module named 'indextts'` 退出。加入 PR 根目录后，同一组测试
全部通过。这个失败属于测试启动环境配置，不是 PR 代码失败，也没有触发模型或 CUDA。

## 同卡真实合成证据的适用边界

本机直播 owner 使用 `upstream/main` 加 `sts2-ascend/tts/indextts_gpu.py`：它在 CPU 构造模型，生成并缓存
固定参考条件，移除 reference encoders，再把逐句推理模块移到 CUDA。该布局验证了“reference encoders
不常驻 GPU 后，6 GiB Pascal 仍可持续合成”的工程前提，但实现路径和精度设置都不等于 PR #795。

当前稳定 session（15:35:10 后）的日志统计：

| 项目 | 结果 |
| --- | ---: |
| 连续成功合成 | 99 次 |
| 合成/CUDA/OOM 失败 | 0 次 |
| 单进程峰值显存 | 3174–3289 MiB |
| 文本长度 | 2–16 个中文字 |
| 合成耗时中位数 | 17.2 秒 |
| 合成耗时 P95 | 56.7 秒 |

这组数据使用下游 FP16 wrapper 和固定缓存引用，只能标记为 downstream equivalent-layout soak，不能标记为
exact-branch checkpoint benchmark。PR 正文和评论均明确写出了这项限制。

## 为什么没有强行跑第二份 GPU 模型

测试时资源快照：

```text
GPU: NVIDIA GeForce GTX 1060 6 GB
GPU memory: 5512 / 6144 MiB used, about 518 MiB free
GPU utilization: 100%
System RAM: 32 GiB total, about 3 GiB free
CPU load: about 92%
```

PR 的完整 CUDA 验证至少需要为合成模块和新的 CUDA context 留出数 GiB 显存。此时并发加载第二份模型有很高
概率导致 OOM、游戏掉帧、TTS owner 退出或直播卡顿。停止现有 owner 又会直接违反直播期间不得干扰稳定项目的
约束，所以本轮只执行了不会加载 checkpoint 的精确提交测试。
