# 2026-08-22 复盘直播悬浮窗（ASCEND-VISION）

## 需求与实现

把每局后 LLM 复盘的推理过程实时展示在屏幕上（酷炫文本特效）。实现分两半：

1. **`llm_review.py` 直播化**：`subprocess.run(capture_output)` → `Popen(stdout=PIPE)` 行缓冲流式读，
   双写到 `knowledge/review_live.stream`（带 `[LIVE-START]/[LIVE-END]` 哨兵与元信息），
   并自动拉起 viewer 进程（`CREATE_NO_WINDOW|DETACHED_PROCESS`，stdout 全 DEVNULL）。
   加了 `--thinking` 让思维链进输出；`NO_COLOR=1` 减 ANSI（未全灭，viewer 端再正则剥离）。
2. **`brain/review_viewer.py`**（tkinter+ctypes，纯标准库）：无边框半透明置顶、点击穿透
   （`WS_EX_LAYERED|WS_EX_TRANSPARENT`，ctypes 设 GWL_EXSTYLE）、停靠屏幕右上。
   青色数字雨 + 打字机 + 事件着色 + HUD（模型/局数/耗时/字数/Loader）+ 结束横幅淡出。
   三模式：直播（tail stream）、`--demo`（假数据演示）、`--attach-current`
   （只读 `~/.local/share/opencode/opencode.db` 回放最近复盘会话）。

## 踩过的坑（本次调试全程实录）

1. **编辑把 `_frame` 的 `after()` 调度行切进了 `_debug_exc`**：现象是"窗口在、HUD 有、正文空、
   T+00:00"——帧只跑了一帧。reveal=264（恰好一帧的量）是定位关键。
   **教训：以既有代码行为锚点做 Edit 插入新方法时，必须事后通读该区域确认结构完整；
   帧循环的 reschedule 行被误移后没有任何报错，纯静默失效。**
2. **tkinter `font.measure(cur+ch)` 逐字测整串 = O(n²)**：attach 模式首个 part 是 39k 字符的
   复盘 prompt，直接导致 viewer 假死（CPU 狂转无窗口）。改字符宽度缓存（每字符只测一次）→ O(n)。
3. **打字机追平策略**：大 backlog 时线性 cps 永远追不上可见窗起点（base），正文长时间不可见。
   现改为 backlog>6000 直接跳到尾部只动画最后 1200 字符。
4. **可见行数遮罩**：底部结束横幅会盖住正文最后两行——max_visible 要扣掉横幅高度。
5. **opencode.db 捞取要跳过 user prompt**：`part` 里第一条是 39k 字符的提示词数据包，
   不是"推理过程"。用 `message.data.role != 'user'` 找首个非 user 消息的时间戳作为起点。
6. **Start-Job 起的 GUI 不可见**：PowerShell 后台 job 里的 tkinter 窗口在非交互窗口站，
   进程活着但屏上无窗；调试 GUI 要用 `Start-Process`（同站可见）。
7. **`py` 启动器 pid ≠ 实际 python 进程 pid**：Start-Process 拿到的是 py.exe，
   真正跑代码的是其子进程 python.exe；按命令行匹配杀进程才是稳的。
8. **时钟偏移**：opencode.db 里的会话时间戳与系统时钟存在数小时级 skew（原因未查明，
   可能与之前的会话时间记录方式有关），显示会话耗时时要防负值/僵值。

## opencode 侧关键事实

- `opencode run --format json`（原始 JSON 事件流）与 `--thinking`（思维链）可用于结构化直播；
  本期用 default 文本流 + viewer 端正则分类已够。
- 会话存储在 `~/.local/share/opencode/opencode.db`（SQLite，WAL）：`session`/`message`/`part`
  三表，data 列为 JSON；part.type ∈ text/reasoning/tool/patch/step-start/step-finish。
  只读连接 `file:...?mode=ro` 在 WAL 下工作正常。
- 本机 ox-alpha 的模型 id：`openrouter/stealth/ox-alpha`。
