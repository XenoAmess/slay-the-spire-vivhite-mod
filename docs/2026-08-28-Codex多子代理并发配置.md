# Codex 多子代理并发配置

## 目标

白绮拆件等可并行任务采用“一部件一子代理”，并尽量占满会话允许的并发槽位。这样每个部件都有独立上下文、提示词迭代和验收记录，同时仍由主代理统一把关整体一致性。

## 项目配置

项目级 `.codex/config.toml` 配置如下：

```toml
[agents]
enabled = true
max_concurrent_threads_per_session = 12
```

`max_concurrent_threads_per_session` 只统计子代理，不包含主代理。因此新会话最多可同时运行 12 个子代理；实际可用数量仍可能受产品或运行时配额限制。项目配置在新会话中读取，本次已经启动的会话不会热更新槽位。

## 调度规则

- 每个可独立验收的语义部件分配一个子代理。
- 部件多于槽位时逐个排队，槽位释放后立即补位。
- 同一部件最多八次的生成尝试由同一子代理串行迭代，确保后一轮能利用前一轮的视觉反馈，也避免并发烧掉 EvoLink 额度。
- 主代理先为各部件分配不重叠的输出路径和编号区间；子代理只写自己的部件目录。
- 公共清单、说明文档、整合测试、Git 提交与推送由主代理统一处理，避免共享文件冲突。

## 注意事项

- 并发上限是容量，不代表应把同一素材的多次昂贵生成同时发出；并行单位应是不同部件。
- 若当前运行时提供的槽位少于 12，继续保持“一部件一代理”，用队列分批执行，不把多个部件重新合并给同一代理。
- 改动配置后应开启新会话验证并发上限；旧会话继续沿用启动时的运行时上限。
