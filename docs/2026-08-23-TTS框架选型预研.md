# 2026-08-23 TTS 框架选型预研（含本机实测基准）

## 背景与评测环境

目标：复盘直播内容的语音朗读，尽量用克隆音色。硬件：i7-6700K（4C8T，无 AVX-512）+
GTX 1060 6GB（Pascal，游戏常驻占用）+ 老版本 Windows（无 DXCore）。

## 候选对比总表

| 框架 | 参数量 | 克隆音色 | 本机实测/判定 | 结论 |
| --- | --- | --- | --- | --- |
| **MOSS-TTS-Nano (ONNX)** | 0.1B | ✅ | **CPU RTF≈2.6**（4线程最佳） | **首选**：唯一"克隆+本机可跑" |
| IndexTTS-2.5 | 0.8B | ✅ | CPU 34字≈6分钟；GPU 病态 | 仅结论段都嫌慢，退役为备选引擎 |
| CosyVoice2-0.5B | 0.5B | ✅ | LLM AR + 声码器，同档重型 | 排除（与 index-tts 同类问题） |
| MeloTTS | ~0.2B | ❌ | 为 CPU 实时设计 | 不克隆场景的最优，但 SAPI 已覆盖且免费 |
| SAPI (Huihui/Zira) | - | ❌ | 即时 | 实时直播在用 |
| edge-tts | 云端 | ❌ | 即时、真人级 | 需联网；不接则已 |

## MOSS-TTS-Nano 实测基准（本机）

CPU（onnxruntime，4 线程，参考音频编码缓存后）：

| 文本 | 合成耗时 | 音频时长 | RTF |
| --- | --- | --- | --- |
| 11 字中文 | 5.4s | 1.8s | 2.93 |
| 26 字中文 | 15.5s | 6.0s | 2.59 |
| 85 字英文 | 18.1s | 7.0s | 2.57 |

- 模型加载一次性 ~18s；结论段端到端（含加载）~94s。
- 8 线程反而更慢（RTF 4.4，超线程与游戏争抢），**保持 4 线程**。
- 采样率 48kHz 立体声，克隆效果可用。

## GPU 加速四条路（全部实测失败，勿再试）

1. **onnxruntime-gpu + cu13**：`nvidia-cudnn-cu13` 等是 PyPI 占位包，装不了。
2. **onnxruntime-gpu 1.22 + cu12**：cudnn 9 已弃用 Pascal → `CUDNN_BACKEND_API_FAILED`（Conv 节点）。
3. **onnxruntime-directml**：需要 DXCore，本机 Windows 版本太老（"not available on this platform"）。
4. **onnxruntime-gpu 1.17 + cu11/cudnn8**：CUDA provider 静默初始化失败（DLL 链路不通）。

结论：这台机器 GPU 加速此模型不可行，**CPU 4 线程 ONNX 就是最优**。

## 踩坑记录（安装/运行时）

- MOSS-Nano 的文本规范化依赖 WeTextProcessing/pynini（Windows 难装）→ 用 `--disable-wetext-processing` 跳过，走自带 robust normalizer。
- `torchaudio.load` 在 torch 2.9 需要 torchcodec → 参考音频改用 **stdlib `wave` 读取 48kHz 立体声 PCM**
  （monkey-patch `_load_reference_audio`），彻底绕开 torchcodec/ffmpeg 依赖。
- ModelScope 可下全部模型：`openmoss/MOSS-TTS-Nano-100M-ONNX` + `openmoss/MOSS-Audio-Tokenizer-Nano-ONNX`
  （HF 镜像 hf-mirror 当天连不上时 ModelScope 是活路）。

## 最终架构（ASCEND-VOICE）

```
直播过程 → SAPI 实时读（Huihui/Zira 按句中英文切换）
复盘结论 → MOSS-TTS-Nano 克隆 reference_voice 音色读（后台 ~1.5 分钟）
index-tts → 仅作 speak_once.py --engine indextts 的手动备选
```
