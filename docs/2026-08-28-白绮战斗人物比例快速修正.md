# 白绮战斗人物比例快速修正

## 问题

原战士与白绮战斗场景都使用 `Visuals.scale = Vector2(0.28, 0.28)`，但同为
1920×1080 的真机截图中，原战士人物可见高度约 252 px，白绮约 504 px。
偏大来自白绮私有骨架的 authored world size，而不是场景、Bounds、血条或意图锚点。

## 修正

- 保留 combat 与 merchant 场景的 `0.28` SpineSprite scale。
- 将战斗人物世界矩形从 `1240×1860` 缩放为 70%，即 `868×1302`。
- 人体骨点随世界矩形自动缩放；人物整体向下偏移 61 个 Spine world units，
  对应屏幕约 17 px，用于恢复原战士脚底落点。
- 眼部、掌心魔法弧和法阵的骨骼锚点同步缩放并下移。
- 魔法弧和法阵 attachment 自身的世界尺寸不缩小，避免人物缩小后 VFX 失去力度。
- 场景 Bounds、CenterPos、IntentPos、血条及外部 VFX 节点均未修改。

这是一项比例快速修正，不解决整身连续网格造成的动作幅度小和死亡姿势僵硬；
后续仍需改为层级骨链、正常战斗拆件和死亡专用拆件。

## 验证与部署

- 重新生成私有 Spine 4.2.43 JSON，人物 attachment 为 `868×1302`。
- Godot 真实加载 combat、merchant、rest-site、character-select 四套 Spine 资源通过。
- Source 契约通过：26 个运行时文件、4 套 Spine。
- 候选 PCK 契约通过：93 个条目，Godot 4.5.1 pack format 3。
- `.NET 9` 完整构建通过，0 warning、0 error。
- 使用 `CopyModOnBuild=false` 在仓库 `.work/` 生成并验证候选包，未在构建阶段写入游戏目录。
- 停止统一自动游玩栈后备份旧三件套，再复制新 DLL/JSON/PCK，并用 `Start-Agent.ps1 -SkipDeploy`
  以 Vulkan 恢复游戏、brain 与 TTS；70% 版本实际游戏中断 49.9 秒。
- 新会话日志确认 `IRONCLAD` replacement 注册成功，API `/health` 返回 ready；未启动 Bilibili。
- 1920×1080 真机战斗截图确认人物约 350 px 高，脚底、血条和场景锚点保持对齐。

## 注意事项

- 以后调整人物尺寸，应继续修改骨架内部 world size，不要用 combat 与 merchant 两处场景 scale
  分别打补丁，否则共享骨架、掌心/眼部锚点和 VFX 很容易再次失配。
- 离线自动适配画布会掩盖真实游戏比例，最终尺寸判断必须使用相同分辨率、相同人物根节点、
  同动画采样的真机 Alpha 包围盒，并以脚底对齐为准。
