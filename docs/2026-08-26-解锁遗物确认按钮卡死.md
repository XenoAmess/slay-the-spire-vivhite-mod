# 解锁遗物确认按钮卡死：私有基类字段反射漏查

日期：2026-08-26
环境：Slay the Spire 2 v0.111.0，STS2-Agent v0.9.0 fork

## 现场与结论

第 551 局结束后，大脑在 01:12:47 选择时间线解锁项，01:12:51 确认弹层，
从 01:12:52 起永久停在“解锁遗物！”页面。实时 API 稳定返回：

```json
{
  "screen": "UNLOCK",
  "available_actions": [],
  "unlock": {
    "unlock_type": "NUnlockRelicsScreen",
    "items": ["红头骨", "纸蛙", "损毁头盔"],
    "can_confirm": false
  }
}
```

直接诊断调用 `confirm_unlock` 返回 HTTP 503 `state_unavailable`：
`Unlock confirm button is unavailable.`。画面上的确认按钮实际可见，因此问题不在动画时序，
而在 mod 的按钮解析。

游戏自带 `sts2.xml` 元数据给出了决定性证据：

- `_relics` 声明在运行时派生类 `NUnlockRelicsScreen`；
- `_unlockConfirmButton` 声明在基类 `NUnlockScreen`；
- 旧 `TryGetMemberValue` 只对 `instance.GetType()` 调一次 `GetField/GetProperty`。

.NET 反射不会从派生类型返回基类的 private 字段。因此遗物名称可以正常读出，确认按钮却必然
为 null，继而 `can_confirm=false`、`confirm_unlock` 不进入 `available_actions`。这也解释了
为什么 watchdog 的 `proceed/confirm_modal/abandon_run` 全部无从执行。

## 排除过的错误方向

- 不是部署被官方 release 覆盖：卡死现场的游戏 DLL 与 fork Release DLL 哈希完全一致，
  SHA-256 均为 `B9D7DCF08D19F143D663E7B3EE6BA0CEA9165915640EADDA9311D180CA980DD2`。
- 不是 mod 未识别页面：API 已返回 `UNLOCK` 和完整遗物列表，证明初始 PR #47 已加载。
- 不是按钮尚未就绪：状态持续约 40 分钟没有变化，且按钮在画面中可见。
- 游戏控制台的 `unlock relics` 不能用来安全复现：反编译确认它只写
  `Progress.MarkRelicAsSeen` 并保存进度，不创建 `NUnlockRelicsScreen`。

## 修复

STS2-Agent fork：

1. 新增 `ReflectionMemberAccessor`，从运行时类型开始沿 `BaseType` 逐层以
   `DeclaredOnly` 查找字段/属性，保持派生成员优先级。
2. `GetUnlockConfirmButton` 在反射字段之外，再精确查找后代节点
   `NUnlockConfirmButton`，抵御未来字段改名。
3. 按探针状态节流记录屏幕运行时类型、字段声明类型、按钮类型/节点路径、
   `visible/enabled`，以后能直接区分“没找到”和“找到了但未就绪”。

Python 大脑：

1. 为已识别的 `UNLOCK` 增加独立 `_unlock_stall`，不再只有 `UNKNOWN` 才能兜底。
2. API 连续 12 tick 没有 `confirm_unlock` 时，点击窗口底部确认区；日志记录
   `unlock_type/can_confirm/actions` 和点击结果。
3. 正常暴露 `confirm_unlock` 时仍优先走 HTTP，不影响确定性动作路径。

- C#：测试程序全部通过；新增 private 基类字段、private 基类属性、派生成员优先级三条回归。

  `67F972764FFE8CF24DC47648224700BA10A816AB22BECA647AEAF9C7561F623C`；游戏重启日志确认加载，

原始解锁页面会在强制重启时被游戏结算，当前档所有时间线槽位随后均为 complete；为避免污染存档，
没有使用会永久写进度的控制台命令强造第二次页面。根因由真实现场、游戏元数据、反射回归和部署日志
完整闭环。

## 经验与注意事项

- 反射游戏 private 成员时必须核对 declaring type；`NonPublic` 不等于能跨派生类型读 private 基类。
- 罕见 UI 修复不能只以“能编译”为闭环。至少要有继承结构回归，并给按钮解析留可观测状态。
- 兜底应覆盖“页面已识别但动作缺失”，不能只覆盖 `UNKNOWN`；识别半成功往往比完全未知更容易活锁。
- 游戏退出后 DLL 锁可能延迟数秒释放。部署脚本应等待锁释放并校验源/目标哈希，再启动游戏。
