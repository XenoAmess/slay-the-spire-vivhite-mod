## 实机暴露并修复的问题

### MSBuild 部署参数被尾随反斜杠吞并

Windows 命令行中带尾随 `\` 的引号目录会影响后续参数解析。构建脚本现在先规范化部署
目录，再传给 PowerShell；三件套只在全部产物通过后原子发布，避免 DLL/PCK/manifest
版本撕裂。

### Godot 导出的 GDScript 不是源 `.gd`

Godot 4.5.1 PCK 会把脚本导出为 `.gdc + .gd.remap`。PCK 验证器同时校验这对产物，
不再把正常导出误报为缺文件，也不会放宽到只看路径存在。

### 美术统计遗漏独立 VFX

旧统计只覆盖 89 项，漏掉 3 张独立 VFX。发布审计已把它们纳入同一消费清单，实际口径
改为 92/92。

### Steam 未运行导致平台初始化失败

直接启动游戏时平台初始化失败；启动 Steam 后再由统一 `Start-Agent.ps1` 以 Vulkan
启动即可。该问题应通过一次真实启动与 godot.log 判断，不应继续做静态推测。

### 原生继续返回同角色的新 run_id

轮换账保存了失联 ID `DWFYFTRFAB54`，游戏原生继续实际返回同一白绮存档
`N2T0XV4ARV3C`。旧逻辑只接受旧 ID 原样重现，因此永久阻塞。

修复后的事务只在 Brain 刚观察到并选择游戏原生“继续”后生效，并要求新旧角色一致：

- 原旧 ID 标为失联、排除学习，不计局数、胜负、楼层或 LLM 复盘；
- 活动轮换身份原子替换为游戏实际 run_id；
- 保留 scheduled character、4:1/1:1 阶段、catch-up index 与下一角色；
- 角色不同、旧 ID 不匹配或新 ID 已终局时继续阻塞；
- 主循环的预绑定阶段会等待该事务，避免先打印一次虚假的
  `observe_active_run_failed`。

针对轮换和失联存档的回归为 26/26；随后又单独验证恢复屏障 6/6。最终验收以真机日志
确认 Brain 已持续发送白绮动作，而不是继续扩大静态审核。

## 后续操作约定

- 完整启停只使用 `Start-Agent.ps1` / `Stop-Agent.ps1`；运行中人工接管只用 F9/F10。
- 遇到游戏状态机问题，优先一次可控实机复现并抓 API 状态、runner 日志和截图；只有日志
  指向数据契约缺口时再补相应窄测试，避免反复审计同一结论。
- 轮换与角色统计只能由终局持久化事务推进；任何失联、人工接管或恢复身份都不得伪造终局。
