# sts2-ascend 复盘成果保全与直播热切换

## 问题与根因

第 555～580 局间，ox-alpha 多次完成分析甚至通过隔离自检，却没有形成生产提交。排查确认并非
模型一直没有产出，而是宿主门禁和队列状态机共同造成：

- 当前 session 的 runner stdout/stderr 持续增长，被真实仓库指纹误判为模型越界写入。
- 失败诊断在“复盘后指纹”之前写进真实 `code_backups`，门禁会把自己的诊断写入再次判成越界。
- 提示词允许 ox-alpha 补回归测试，但宿主 allowlist 不允许 `brain/selfcheck.py`，有效补丁因此整批拒绝。
- `run_review()` 的失败在批处理层被当成“已完成”，`reviewing` 随后清空；队列上限还会截断旧积压。
- `last_successful_review_run` 在验证/提交前推进，使失败批次看起来已经成功复盘。
- 在线存档在复盘 active 时为保护 `origin/*` 指纹而延后 push；若 ox-alpha 随后失败且队列持续繁忙，
  没有可靠的“窗口关闭后补推”触发点，本地提交可能长期领先远端。

## 修复原则

- 只豁免当前生命周期 session 的两份 runner 流日志；`.runtime` 其他未知文件仍参与严格指纹。
- 先完成真实仓库前后指纹比对，再落失败诊断，避免观察行为污染被观察对象。
- 将 `selfcheck.py` 纳入复盘补丁 allowlist。ox-alpha 可以多交一份测试，最终仍由完整自检把关，
  不用脆弱的路径限制替代质量验证。
- 用 `failed`、`canceled`、`completed`、`changed` 四种显式结果驱动队列。合法无修改才算成功；
  失败整批放回队尾并按条目指数退避，新直播证据可越过冷却项；停止中的批次原样留在
  `reviewing` 供下次启动恢复。批次收尾若暂时无法落盘，会原地重试而非进入永久空转。
- `review_queue_max` 仅是单批容量，不再是存储上限；成功游标只在验证完成或提交成功后推进。
- 提供 `--requeue` 恢复入口，旧批次追加在最新证据之后并按局号去重。
- 每次复盘结束先清 active 标记，再在同一仓库事务锁下检查并补推本地积压；成功、失败、无改动
  三条路径都会触发，弱模型长期失败也不再阻断在线存档上库。

## 旧成果恢复

- 第 571～576 局的隔离仓库仍完整存在，已恢复“力量叠层敌人优先集火”策略及复盘报告。
- 第 580 局的完整差异曾在隔离目录消失前被捕获，已重建“不可格挡期间纯防牌视为死牌”和
  “深度输出饥饿时精英硬线也做重尾复核”，并补齐自检。
- 其余只剩报告、没有可验证代码的批次不凭文字猜补丁；报告结论保留，并通过恢复队列重新复盘。
  已在当前基线出现的同类修复不重复手工叠加。

## 直播上线纪律

所有编辑、测试、提交和推送都在旧 brain 在线时完成。最终只进行一次统一热切换：先用
`Stop-Agent.ps1 -KeepGame -GraceSeconds 30` 协作停止 Python 栈，立即恢复队列，再用
`Start-Agent.ps1 -SkipDeploy -ReadyTimeoutSeconds 45` 复用已运行游戏。断流计时从 Stop 开始，到
新 session 健康且出现实时决策为止；上线后还要核对游戏 PID 未变、API、brain/runner、复盘队列、
播报链、Git 同步和新日志，而不能只看一条 `Stack ready`。

## 回归重点

- 当前 session runner 日志变化不会拒绝复盘，其他 session 或未知 `.runtime` 文件仍会拒绝。
- `selfcheck.py` 可由复盘修改，但所有产出仍须通过完整 `selfcheck.py` 和宿主测试。
- 失败、异常与协作停止均不丢局；失败退避可跨重启持久化，新局也不会被队列上限裁掉。
- 历史恢复不会重复 pending/reviewing 项，也不会插到直播最新批次之前。

上线前在旧 brain 持续在线时完成验证：`brain/selfcheck.py` 输出 `SELFCHECK OK`，Python 编译通过，
`sts2-ascend/tests` 共 67 个测试全部通过；在线调用 `--requeue` 会被明确拒绝，避免跨进程覆盖队列。

  游戏进程 PID `14452` 全程未变。
- 最终 session 的 runner 与 brain PID 身份一致且存活，旧 session PID 全部消失；API `/health`
  返回 ready，实时日志在新 session 下持续完成战斗、奖励、地图与商店动作。
- IndexTTS 服务返回 `cuda:0/fp16` ready，悬浮窗完成首帧，edge 朗读器重新上线，复盘直播流持续增长。
- 恢复集合第 `555～570、577～579、581～591` 局在 pending/reviewing 中无缺失、无重复；
  第 `571～576、580` 局使用已恢复的验证过补丁，不重复排队。
- 最终代码提交后，在线存档又以线性提交推进；本地 `HEAD` 与 `origin/master` 保持同步。
