## 9. 推荐接手顺序

### 阶段 A：统一候选，不碰正式 runtime

1. 从 `hybrid_neutral_v3` 复制 neutral 基线；
2. 合入 attack 0104、heavy 0106、cast 0107、death 0029 的四个独立 atlas 页；
3. 保留 `hybrid_hurt_neutral` 的 neutral 网格受伤动画，不增加 hurt 图片页；
4. 合并所有 animation、event、slot reset 和 transition mix；
5. 输出到新的 `hybrid_v3_final` 候选目录，禁止直接写正式 skin；
6. 运行 source validator 和 Godot/Spine validator，确认严格五页/30 文件。

### 阶段 B：统一离线 Vulkan

至少覆盖：

- 八动画实际时长的边界前/中/后帧；
- `[.08,.20)`、`[.12,.32)`、`[.25,.60)`、`die@1.05` 的原子前后帧；
- attack/heavy/cast/hurt/die 互相中断和返回 idle；
- character-only 与 composite 分层；
- slash、EyeFire、sigil 的出现、pose-specific 锚点和 `clear_vfx`；
- merchant `relaxed_loop` 的随机 seek 与两个循环边界；
- 单人物、无空帧、无触边、无双影、无武器、无旧战士残片。

### 阶段 C：不部署的完整构建

代码/契约快速复验：

```powershell
cd Vivhite
dotnet build /p:RunPckExport=false /p:CopyModOnBuild=false
```

只有 `hybrid_v3_final` 已发布到正式候选输入并通过前两阶段，才显式测试五页 PCK：

```powershell
cd Vivhite
dotnet build /p:IroncladSkinRuntimeLayout=v3-five-page /p:CopyModOnBuild=false
```

不要省略 `CopyModOnBuild=false`，否则默认构建会复制到游戏 mods 目录。发布工具参数以
`python tools/art/publish_ironclad_skin.py --help` 和契约测试为准，不要凭记忆臆造路径。

### 阶段 D：真实游戏

离线全部通过后才进行：

1. 比对并备份当前 Vivhite dll/json/pck 三件套及 SHA-256；
2. 显式发布五页布局并完整构建；
3. 使用 Vulkan 启动，不启动自动点击；
4. 90 秒内主菜单失败、崩溃或人物不可见，立即恢复旧三件套；
5. 依次验收选人、战斗八动画/VFX、商店、伪商人、三章篝火、UI、多人离线尺寸；
6. 检查新会话日志中所有 `res://Vivhite/skins/ironclad/` 相关错误；
7. 用户真机认可后才把 V3 视为可发布版本。

严禁在上述流程中调用 Bilibili 开播。用户以后明确要求“启动整套游戏 + brain + TTS”时，才按
`sts2-ascend/scripts/Start-Agent.ps1` 统一入口执行；它与美术真机验收是两件事。

1. **把分项通过当成总装通过。** 当前最大缺口就是最终总装和跨动作状态污染。
