# ASCEND-VISION 直播驾驶舱升级

## 问题与目标

原悬浮窗主要服务赛后复盘：只有 OpenCode 复盘运行时才有足够内容，直播中的实时局势、长期表现和
决策依据不可见；viewer 若退出，也要等下一次复盘才可能重新出现。本次将它升级为随 brain 常驻的
直播驾驶舱，同时保持 400×760、右上角、点击穿透、不抢焦点和持续 TOPMOST。

驾驶舱现在同时回答三个问题：智能体长期走得多远、最近是否进步、当前一步为什么这样选以及是否执行成功。

## 数据口径

### 真实楼层与学习分隔离

旧聚合字段不是纯楼层：`floors_total` 累加 `final_floor + (victory ? 50 : 0)`，`best_floor` 同样保存
学习评分。如果直接展示，会把一次胜利抬高 50 层。

为此增加两个兼容字段：

- `floor_sum_raw`：所有有效完结局真实楼层之和；
- `best_floor_raw`：历史真实最高楼层。

原字段继续供学习估值使用，结果语义完全不变。旧库的 raw 总和按 `floors_total - 50 × wins` 迁移；
最高层不可只从评分反推，因此结合 `progression.best_floor_by_ascension`、活动 run 和归档 catalog 取可信最大值。

### 最近窗口与趋势

`FloorStatsProvider` 合并 `knowledge/archive/run_catalog.jsonl` 和 `knowledge/runs/*.json`：

- 按 `run_id` 去重，活动文件覆盖归档摘要；较新的零决策幻影副本不能抹掉已有真实证据；
- 胜利、`in_progress=false` 或存在 `GAME_OVER` 的局视为完结，兼容历史 `in_progress=true + GAME_OVER`；
- 真正进行中的局独立显示，不进入历史统计；零决策非胜利局排除；
- 根层数字段损坏时尝试使用决策轨迹中的有效层数，完全不可恢复时标记质量异常，不填假 0；
- “最近”默认 20 局，变化量为最近 20 局均值减去此前 20 局均值；趋势图取 40 局并计算 5 局滚动均线。

提供器按约 1 秒节流，只重读签名变化的文件。JSON 暂时损坏或替换失败时保留该组件最后一次正确值并标记
`stale`，恢复后自动清除；这避免正在原子换盘时让直播画面闪成全零。

## 实时决策可视化

决策图使用 `SCAN → GATE → RANK → LOCK → ACK` 五阶段：

1. `SCAN` 显示屏幕、楼层、回合、生命等观察结果；
2. `GATE` 显示合法性、生存、资源或规则闸门；
3. `RANK` 显示最多三个真实候选及 Policy 已计算分数；
4. `LOCK` 显示最终动作、目标和选择理由；
5. `ACK` 显示服务端回执或后续状态对账结果。

动作生命周期覆盖 `waiting → proposed → pending/uncertain → reconciling → applied/retrying/rejected/failed`。
相同等待决策复用 id 并增加重复计数，避免窗口持续重播动画；规则直达动作只显示实际命中的规则链，不伪造
候选、概率或隐藏推理。

这条遥测链是纯本地、确定性的 Python 标准库实现。它只复制本次 Policy 已经产生的观察、闸门、候选分数和
原因，不重新评分、不再次调用随机探索，也不参与动作选择或学习。它不调用 LLM、OpenCode、Minimax、
OpenRouter 或网络，token 消耗为 0。异步复盘是另一条数据链，复盘模型自身仍可能消耗 token；不能把
“决策遥测零 token”写成“实时复盘零 token”。

发布器在决策线程外使用有界队列，只保留最新状态，并原子替换当前 session 的：

```text
.runtime/live_dashboard.<SESSION_ID>.json
```

快照带 schema、session、序号、revision、心跳、连接状态、当前 run、decision 和最近三次动作。viewer 对
schema 和对象类型做校验，读到半成品或旧 session 时保留最后正确画面。

## 生命周期与复盘分工

- brain 启动时即创建遥测发布器，并启动驾驶舱监督器；监督器检查 viewer 单实例心跳，异常退出后自动重拉。
- viewer 是独立进程，brain 热重启或异步复盘切换不会让窗口消失；停止仍服从 session stop 哨兵和既有 PID 身份协议。
- `review_live.stream` 不承担实时决策数据，但会在同一窗口持续提供多行实时复盘流；OpenCode 与复盘 speaker 仍按需运行。
- viewer 故障不阻塞游戏和决策，遥测队列满时丢弃旧画面而不是卡住主循环。
- 启动提交号只用于后续健康回滚提示，不是游戏循环的前置条件；探针在 daemon 线程中执行，且不持有在线存档、
  复盘与策略热同步共用的 Git 事务锁。主循环立即继续；即使安全软件延迟 PowerShell/Git 子进程检查，也只能
  拖住该可丢弃线程，不能冻结决策、遥测、viewer 或实时复盘。
- 原有窗口层看门狗继续每约 500ms 无激活恢复 TOPMOST，因此游戏保持前台输入，驾驶舱仍位于游戏之上。

## 界面布局

窗口尺寸保持 400×760：顶部是局号、楼层和连接状态；随后是历史/近期四张统计卡与趋势图；决策区展示阶段机、
闸门、候选、最终动作及中文说明；复盘区显示多行实时正文，并保留音量和数据新鲜度。

界面采用同一 Canvas 内的状态驱动稳定布局，不按秒整页闪回：

- 对局状态：决策主区 + 多行实时复盘流；
- `GAME_OVER`：趋势主区 + 多行复盘流；
- 主菜单、等待或无新鲜决策：完整 REVIEW 视图；
- `--interactive`：可手动固定 LIVE、TREND、REVIEW，自动布局不得覆盖用户选择。

状态变化只调整各区域的空间权重和内容，不销毁整页再重建；数字雨限制在边缘与 HUD，避免压住关键数字或
造成直播画面持续闪烁。

## 验证与注意事项

- raw 楼层迁移、胜利 +50 分隔离以及旧调用兼容均有聚焦回归测试；学习字段仍按旧值累加。
- catalog/活动文件去重、缺失局号、脏楼层、进行中局、幻影局、少于窗口样本、坏 JSON 和压缩前后等价均被覆盖。
- 决策 trace 开关前后必须保持 `action/params/reason/tags/wait` 和随机状态一致；展示层不得成为策略输入。
- 启动回归测试会模拟 Git 子进程自身持续卡住，确认主循环不等待、探针使用 5 秒命令超时且失败后安全退出。
- 本机真实知识库只读验证中，合并后的有效完结局数与聚合总局数一致，另有一个进行中局和一个幻影局被正确隔离。
- 排障时先检查 `.runtime/live_dashboard.<SESSION_ID>.json` 心跳与 `knowledge/viewer*.log`，不要手改 `.runtime/`、
  `knowledge/` 或单独拉起第二个 viewer。

本升级不改变直播控制语义：开播仍先启动完整 sts2-ascend 栈、将杀戮尖塔2置顶，再通过本地哔哩哔哩直播姬
开播；下播只操作直播姬，不停止驾驶舱、服务、智能体或游戏。
