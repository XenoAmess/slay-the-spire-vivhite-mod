## 经验和适用边界

1. “CI failure” 不一定是测试失败：先核对是否有实际 job / log。本轮真正的上游阻塞是 fork workflow 的维护者审批，贡献者不能代为批准；个人 fork 的通过记录不能冒充上游状态已通过。
2. 审计要求保留两套重叠测试时，应合并其语义，不能任选一侧解决冲突。对应本轮是 duration 转发/控件测试与 reuse 开关测试全部保留。
3. 两个核心推理 PR 相互重叠时，显式记录依赖和合并顺序，复用同一个 reference helper，避免让维护者再次手工解决设备路由冲突。
4. 历史 GTX 1060 checkpoint 实测只对应旧 #795 SHA `7a72015226fbf1505fedd5835bb89f494a313077`；本轮正文保留其链接和主要结果，但明确不是新 head 的硬件回归。旧详细数据仍见 [原本机验证记录](2026-08-26-IndexTTS-PR795本机验证.md)。
