# D 到 G 工作区迁移

## 目标

将项目从：

`D:\workspace\slay-the-spire-vivhite-mod`

迁移到：

`G:\workspace\slay-the-spire-vivhite-mod`

迁移必须保留主仓暂存区、未暂存改动、未跟踪与 ignored 文件、Brain 学习数据、复盘取证现场、AI 美术原始资产、TTS 模型，以及 `STS2-Agent`、`MOSS-TTS-Nano`、`index-tts` 三个嵌套仓库。

## 已确认的兼容性结论

- Vivhite 构建、部署和 sts2-ascend 生产代码均从脚本或项目文件位置推导根目录，不需要因换盘修改生产代码。
- `Vivhite/local.props` 已指向 G 盘游戏和 C 盘 Godot，不需要改址。
- Python 虚拟环境、Godot 导入缓存、MSBuild `bin/obj` 与临时构建产物不能视为可移植缓存；迁移后需要冒烟验证或重建。
- `.runtime` 和在线锁是会话状态。历史文件可保留，但迁移后必须由 G 盘 `Start-Agent.ps1` 创建新会话。
- 历史日志、美术验收报告、复盘 salvage 中的 D 盘路径属于取证内容，不做全仓替换。
- `sts2-ascend/tmp_review_dump.py` 原有 D 盘输出硬编码已改为根据脚本位置生成输出。

## Paseo 交接

Paseo 0.4.0 将项目、workspace 和 agent 的 `cwd` 持久化在 `C:\Users\xenoa\.paseo`，当前会话本身绑定 D 盘。迁移采用保留旧会话历史、在 G 盘注册新项目和新 workspace 的方式，不批量改写 Paseo LocalStorage 或 Codex SQLite。

当前 D 盘会话完成：停机、复制、校验、G 盘配置、Paseo G 工作区注册和构建验证。随后必须从 Paseo 打开 G 盘项目并创建新会话；只有新会话确认工作目录为 G 后，才能删除 D 盘旧目录。

## 现有运行状态

- 迁移开始前已使用统一 `Stop-Agent.ps1` 完整停止 Brain、runner、驾驶舱、播报链和游戏。
- `character_rotation.json` 仍保留白绮活动局 `KXAY7W9F00ZD`。这是迁移前已有的中断局事务，迁移不会自行消除；重新启动 Brain 前必须按既有恢复逻辑处理。
- `knowledge/`、`review_work/`、`review_hold/`、`review_salvage/` 均为必须迁移的数据，禁止漏拷或手工重置。

## 验收门槛

1. D、G 两边主仓 HEAD、分支、`.git/index` 哈希和 `git status --porcelain=v2` 一致。
2. 三个嵌套仓库的 HEAD、分支和工作树状态一致。
3. G 盘完整构建能够部署 DLL/PCK/JSON 到游戏目录。
4. Paseo 新 workspace、agent 与 `PASEO_AGENT_CWD` 使用 G 盘路径。
5. G 盘新 Brain session 的根目录、PID、日志和锁全部使用 G 盘路径，并继续读取原有角色统计、轮换和复盘队列。
6. 最终实机验证完成后才删除 D 盘旧目录；任何时刻不得同时从 D、G 启动两套 Brain。
