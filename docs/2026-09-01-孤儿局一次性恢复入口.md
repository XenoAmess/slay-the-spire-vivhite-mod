# 孤儿局一次性恢复入口

`sts2-ascend/scripts/release_orphan_run.py` 是跨进程旧局无法找到原生
Continue/存档时的人工审阅边界。它不是开新局命令，也不是绕过存档屏障的快捷方式。
默认只读预览；只有显式 `--apply` 才会调用 `brain.agent.release_orphan_run_once`，
由现有事务负责写入 `knowledge`。脚本本身不发送游戏动作、不启动/停止进程、不请求
UAC，也不直接编辑 `knowledge` 或 `.runtime`。

## 两阶段流程（推荐）

### 1. 栈仍运行时只读捕获

捕获必须绑定当前 GUID session，并在同一个 `lifecycle.lock` 临界区内完成两次
`GET /state`、两次 `GET /actions/available` 交叉校验和原生文件探测。原生路径必须
明确指向同一 `profile1/saves` 根目录下的四类对象：

- `current_run.save`；
- `current_run.save.backup`；
- `history` 目录（或其下的历史文件模式）；
- `.stmp` 文件/模式（可用 `*.stmp`，无匹配会记录为明确 absent）。

例如（路径请替换为本机真实绝对路径；Windows PowerShell 5.1 的原生命令重定向默认是 UTF-16，下面显式转成 UTF-8）：

```powershell
$capture = & py -3 .\sts2-ascend\scripts\release_orphan_run.py `
  --capture --api-port 8080 `
  --native-save-path 'C:\...\profile1\saves\current_run.save' `
  --native-save-backup-path 'C:\...\profile1\saves\current_run.save.backup' `
  --native-history-path 'C:\...\profile1\saves\history' `
  --native-stmp-path 'C:\...\profile1\saves\history\*.stmp'
$capture | Out-File -FilePath .\orphan-capture.json -Encoding utf8
```

`--capture` 只允许在 session `running`/`foreground` 且尚未收到停止哨兵时运行。
捕获结果是 `sts2.ascend.orphan-release-result/v1` JSON，实际证据位于 `.evidence`，并带有
`evidence_sha256` 完整性绑定。不要手改该 JSON；必须使用完整的统一入口
`Stop-Agent.ps1` 停止 brain、runner 和游戏（`-KeepGame` 不满足 apply 的停栈条件），再进行第二阶段。

### 2. 停栈后预览和显式应用

```powershell
# 只读验证；不会写 rotation/Knowledge
py -3 .\sts2-ascend\scripts\release_orphan_run.py `
  --evidence-file .\orphan-capture.json

# 只有确认 JSON 中 run/character、API 两帧和四类原生探针均匹配后才应用
py -3 .\sts2-ascend\scripts\release_orphan_run.py `
  --evidence-file .\orphan-capture.json --run-id <exact-run-id> --apply
```

也可使用 `--evidence-file -` 从 stdin 读取。脚本会识别上一步的结果封装并取出
`.evidence`，但不会解包任意含有 `evidence` 字段的 JSON。

活动局的 `--apply` 拒绝没有 capture 元数据的旧文件，并校验 evidence body 的 SHA-256。
capture 必须带 32 位 session ID、
UTC `captured_at`/`captured_unix`，且停栈后仍能找到同一 `stop.<session>.request`；
哨兵的 `session_id`、`requested_at` 和文件时间必须晚于捕获时间。这是防止跨会话陈旧
证据误释放的本地绑定。已在 `orphaned_runs` 中的同一局重复应用仍由事务层做幂等校验。

## 证据门禁与输出

API 负证据必须包含完整字段：`screen`、`run_id`、显式 `run: null`、
`available_actions`、合法 `state_version`。`/state.available_actions` 必须与
`/actions/available` 的 GET 结果完全一致；任一字段缺失、帧顺序不单调、读错误、
二进制原生文件无法解释、路径类别缺失或发现匹配的旧 run-id，都会 fail-closed。
预期的负证据是两次有序 `MAIN_MENU/run_unknown`、没有 `continue_run`，以及完整的
`current_run.save`/backup/history/stmp 只读扫描。`Stack ready`、进程存活、dashboard
心跳、日志、零字节 `.stmp` 单独都不是恢复证据。

stdout 始终输出一个 JSON 对象（schema 为
`sts2.ascend.orphan-release-result/v1`）。失败返回非零退出码并保留错误原因；
预览返回 `applied=false`；成功应用返回事务结果。脚本不会清理 PID、创建 lifecycle
锁、复制/改名临时文件或触碰直播控制。任何证据不足时保持失败关闭，先修复机制并重新
采集，不得为了“继续训练”强行开新局或开播。
