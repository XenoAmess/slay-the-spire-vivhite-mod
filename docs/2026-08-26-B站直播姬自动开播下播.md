# 2026-08-26 B站直播姬自动开播下播

## 当前实现补充：受保护的无人值守桥

推流端只能使用本机哔哩哔哩直播姬。脚本不调用浏览器私有接口，不读取或解密登录 Cookie，也不使用 OBS 代替直播姬编码推流。

直播姬 8.2.0.10943 的 manifest 是 `requireAdministrator`；普通 PowerShell 向它发送鼠标、`WM_COMMAND`、`WM_HOTKEY` 等消息都会被 Windows UIPI 拒绝。直播姬的 `livehime_obs_plugin_ipc_channel` 也不是正常开播控制口：静态分析确认，主程序收到 `0x68` 后明确进入 `enter into obs stream mode`，再用 `0x69/0x6A` 向第三方 OBS 下发推流地址和停止命令，因此不符合“只能由直播姬直播”的约束。

最终方案采用两个经用户明确授权的固定计划任务。一次性安装器把 worker 和模块复制到普通用户不可写的 `C:\Program Files\VivhiteBilibiliLiveBridge`，校验源文件与保护副本的 SHA-256，然后为当前用户注册：

- `\Vivhite\BilibiliLive-Start`
- `\Vivhite\BilibiliLive-Stop`

两项任务均为 `Interactive` 登录类型、`Highest` 运行级别、无自动触发器，固定执行受保护目录里的 worker，参数分别固定为 `Start`/`Stop`。工作区普通权限脚本只能触发任务，不能替换高权限 worker。

一次性安装必须在人位于电脑前时批准 UAC：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\sts2-ascend\scripts\Install-BilibiliLiveBridge.ps1
```

安装后，原有 `Start-BilibiliLive.ps1` / `Stop-BilibiliLive.ps1` 入口无需再次 UAC。真实 smoke 使用 `Test-BilibiliLive.ps1`：要求初始 `Idle`，启动后验证 `Streaming` 与游戏 `TOPMOST`，并在 `finally` 中立即触发仅下播任务。当前会话尚未安装保护任务，因此用户离开电脑、无法批准首次 UAC 时不能安全完成真机 smoke。

以下直接 `RunAs` 的早期说明由本节的保护计划任务方案取代；GUI 校准、状态码、fail-closed 和下播不停止服务等技术结论仍然适用。

## 目标与最终行为

仓库新增项目级 skill `bilibili-live`、共享模块、受保护桥安装器/worker，以及开播、下播、smoke 三个入口。开播入口先通过统一的 `Start-Agent.ps1 -SkipDeploy` 幂等启动游戏、runner、brain、碎碎念及按需复盘/播报链，再触发固定计划任务控制本机哔哩哔哩直播姬开播，最后把精确路径匹配到的 `SlayTheSpire2.exe` 设为前台窗口和永久 `TOPMOST`。

下播入口只切换直播姬到空闲状态。它不调用 `Stop-Agent.ps1`，不关闭游戏、不杀进程或端口，也不写入 `.runtime`；结束后若游戏仍在运行，会再次确认其 `TOPMOST` 状态。

## 关键问题与解决方案

### 直播姬必须提权控制

本机直播姬 8.2.0.10943 的清单声明 `requireAdministrator`。普通权限 PowerShell 虽能把窗口带到前台，但鼠标注入会被 Windows UIPI 丢弃。入口因此分成两段：全套服务在调用者原权限下启动；只有受保护任务中的直播姬 UI worker 以最高权限运行。runner/brain 和游戏置顶逻辑都不会继承管理员权限。

### 自绘 UI 无可用 AutomationId

直播姬主窗体是 `Chrome_WidgetWin_0`，并主动关闭 CEF accessibility，UI Automation 树只有空 Pane，不能按按钮名称调用。脚本改用以下组合保证安全：

- 以进程名、窗口标题和窗口类共同锁定直播姬；
- 从 `bililive_debug.log` 的 `set_streaming_status` 读取状态码，`0/2/3/5/6/7` 分别映射为空闲、启动中、直播中和停止中；
- 点击前验证目标屏幕点仍属于 `livehime` 进程；
- 开播按钮还需通过粉色背景像素矩阵校验，布局不匹配时 fail closed，不盲点；
- 每个动作只点击一次，再等待日志状态闭环，超时不重试第二次。

### 下播残留弹窗

真机下播后会出现“直播已结束”报告，部分场次上方还有“违规提示”。这些模态层会挡住下一次开播。开播脚本先临时截取直播姬窗口，在临时目录用 Windows OCR 识别已知提示；检测到处罚提示时点击确认，随后关闭“直播已结束”报告，再校验开始按钮。截图只在本机临时存在，读取后立即删除，不进入仓库或日志。

### 游戏必须是顶部窗口

这里的“顶部窗口”按用户要求实现为 `WS_EX_TOPMOST`，不只是一次性的 `SetForegroundWindow`。脚本使用 `SetWindowPos(HWND_TOPMOST)`，处理最小化恢复与 Windows 前台锁，并在结束前同时验证前台句柄和 `WS_EX_TOPMOST` 位。直播姬操作期间会临时成为 topmost，操作完成后立即撤销，再把游戏设回顶部。

## 使用与注意事项

```powershell
# 开播：启动全套、直播姬开播、游戏 TOPMOST
powershell -NoProfile -ExecutionPolicy Bypass -File .\sts2-ascend\scripts\Start-BilibiliLive.ps1

# 下播：只让直播姬下播
powershell -NoProfile -ExecutionPolicy Bypass -File .\sts2-ascend\scripts\Stop-BilibiliLive.ps1
```

首次安装保护桥时会弹出一次 UAC；安装后的两条日常命令不再弹 UAC。自动化必须运行在为任务登记的当前用户交互式桌面会话中。直播姬升级或大幅改版后，需重新运行安装器更新保护副本，并重新真机校准按钮布局和日志状态码；校验失败时脚本会停止，不会猜测点击。

## 验证策略

默认测试只做 PowerShell 5.1 AST 解析、状态码映射、`-WhatIf` 零写入、开播顺序与下播禁区检查。真实开播/下播会改变外部直播状态，只在明确需要真机 smoke 时执行；下播前后还应记录 runner、brain 和游戏 PID，确认没有服务被停止。

明确授权真实 smoke 后使用 `Test-BilibiliLive.ps1`。它要求初始状态必须为 `Idle`，通过受保护 Start 任务开播、验证 `Streaming` 与游戏 `TOPMOST`，并在 `finally` 中立即触发受保护 Stop 任务；该脚本同样绝不调用全栈停止入口。
