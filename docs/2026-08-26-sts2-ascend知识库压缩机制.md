# sts2-ascend 知识库压缩机制

## 问题与结论

截至 2026-08-26，`knowledge/runs/` 已有 559 份逐决策日志，共 42,242,819 字节；
单份平均约 75.6KB，最大约 175KB。它们是重要的原始证据，但并不是在线决策的直接输入：

- `stats.json`、`policy.json`、`progression.json` 在 `Knowledge` 初始化时加载，供每次决策使用；
- `llm_review._recent_run_summaries()` 每次复盘会解析全部 active runs，最后只取最近 10 局；
- `Knowledge._repair_phantom_runs()` 只在一次性幻影局修复标记缺失时扫描全部 runs；
- `Knowledge.load_run_log()` 只按当前 `run_id` 恢复断线中的同一局；
- `lessons.md` 在复盘 prompt 中只读取最后 2,500 个字符；
- `meta_review.md` 没有在线读取路径，主要供复盘 agent 按需深读和追加。

因此应该 compact，但目标是缩小当前 active 工作集、文件扫描与 LLM prompt，而不是伪称能靠
普通删除缩小已有 Git 历史。`stats.json` 是在线学习的充分统计，不能为了体积裁剪字段。

## 实现

新增 `sts2-ascend/brain/compact_knowledge.py`，默认 dry-run，只有显式 `--apply` 才写入。
默认原始样本保留规则为：

- 最近 96 份；
- 全部胜局、全部 `in_progress` 局、全部 F33+ 深层局；
- 决策轨迹最长的 12 份、文件最大的 8 份；
- 每个终局层数一份代表样本、每个进阶最深一份；
- 损坏 JSON 与零决策异常样本。

其他 runs 进入 `knowledge/archive/batch-<内容哈希>.zip`。归档顺序严格为：

1. 读取源文件并计算 SHA256；
2. 以 `ZIP_DEFLATED` 写同目录临时文件；
3. 重开 ZIP，检查 CRC、成员集合、安全相对路径、大小和逐文件 SHA256；
4. `os.replace` 原子发布 ZIP，再次完整校验；
5. 原子发布 manifest；
6. 再次确认所有源文件哈希未变，才精确删除 active 副本；
7. 原子生成可检索的 `run_catalog.jsonl`。

ZIP member 拒绝绝对路径、盘符、反斜杠、NUL 与 `..`，防止未来读取/恢复时出现路径穿越。
批次名由内容指纹生成；若 ZIP 已发布但进程在 manifest 或删除前中断，下次会验证并复用，
不会重复制造不同归档。manifest 已登记但 active 副本仍存在时，也必须先从旧 ZIP 读回并验证
同一 SHA256，才清理重复副本。

`lessons.md` 保留所有 `🧠` 长期经验和最近 96 节；`meta_review.md` 保留最近 32 节。
被移出的 Markdown 原文在同批 ZIP 中保存完整压缩前版本。stats/policy/progression 不修改，
并随批次存只读快照。运行态 `*.log` 只报告体积，不进入二进制知识归档。

## Prompt 压缩

原复盘 prompt 约 120KB，其中：stats digest 约 64KB、最近 10 局摘要约 45KB。
本次不裁 stats digest 的任何字段和值，只去掉 JSON 格式空白；逐局摘要保留总数并内嵌最近
5 条战斗备注、3 条关键路线/事件理由，每条上限 200 字，完整轨迹仍可从 active run 或
`--show-run` 校验读取。实库 prompt 降至约 69~74KB，避免反复携带大量同构路线长句。

## 验证与数据量

真实知识库 dry-run 结果：

- 559 份中 active 保留 154 份，约 14.88MB；
- 405 份、27.37MB 原始 runs 进入归档；逐文件 deflate 预估约 2.41MB；
- `lessons.md`：618 节保留 155 节，725,905B 降至 232,667B；
- `meta_review.md`：76 节保留 33 节，464,958B 降至 215,012B；
- runtime logs 约 40.15MB，仅报告、不归档、不删除。

在系统临时目录复制完整 559-run 数据后执行 apply：ZIP 实际 2,837,641B，active 恰为
154 份，stats SHA256 前后相同。紧接着第二次 apply 返回 `idempotent_noop=true`，归档批次
仍为 1，catalog SHA256 也完全不变。首次 Windows 演练发现只读描述符不能 `fsync`，已改为
以 `rb+` 打开临时 ZIP 后提交刷新，随后完整镜像验证通过。

## 使用注意

```powershell
# 只读分析，可在运行中执行
py -3 sts2-ascend/brain/compact_knowledge.py

# 写入前必须先通过统一入口停止整套
powershell -NoProfile -ExecutionPolicy Bypass -File .\sts2-ascend\scripts\Stop-Agent.ps1
py -3 sts2-ascend/brain/compact_knowledge.py --apply

# 深读一份 active 或 archived 原始日志（归档文件会先校验）
py -3 sts2-ascend/brain/compact_knowledge.py --show-run 20260825-xxxxxx_RUNID.json
```

工具在检测到 brain/reviewer 生命周期 PID、`review_active.flag` 或活跃 reviewing 批次时拒绝
apply。不要手工改 manifest/catalog，也不要直接从 ZIP 覆盖 active 知识文件。
