# D 盘 Steam 缓存审计与清理

日期：2026-08-31

## 结论

D 盘 Steam 库没有已安装游戏。`D:\Steam` 的主要占用来自
`D:\Steam\appcache\librarycache`：约 15.66 GiB、18 万余个 JPG/PNG 商店与游戏库封面文件，
不是游戏本体，也不包含 `userdata`。

本轮在 Steam 完全退出后，逐个解析并确认目标不是链接或 reparse point，再删除以下可重建内容：

| 路径 | 删除字节 | 性质 |
| --- | ---: | --- |
| `D:\Steam\appcache\librarycache` | 16,813,338,211 | Steam 库图片缓存 |
| `D:\VS_TEMP` | 205,535,232 | 2018 年 Visual Studio 调试符号缓存 |
| `D:\Steam\logs` | 15,083,717 | Steam 日志 |
| `D:\Steam\dumps` | 834,172 | Steam 崩溃转储 |
| `D:\Steam\depotcache` | 38,791,699 | Steam depot 下载缓存 |

合计删除 `17,073,583,031` 字节，约 15.90 GiB。D 盘空闲空间从约 4.75 GiB 增至约
21.08 GiB。上述内容不能从回收站恢复，但都能由 Steam、Visual Studio 或调试器按需重新生成或下载。

## 明确保留

- `D:\BaiduNetdiskDownload`：约 11.89 GiB，属于用户下载数据。
- `sts2-ascend/knowledge/code_backups/review_salvage`：约 33.19 GiB；50 个失败包均未闭环，属于复盘取证。
- `sts2-ascend/knowledge/code_backups/review_work`：约 3.62 GiB；四个隔离仓仍含改动或失败证据。
- 当前项目 `.tmp` 中的精确补丁、私有 index 与美术验收证据。
- `D:\Steam\userdata`、Steam 客户端文件、更新状态与回收站内容。

复盘证据只能在对应条目完成重审/补合、台账提交并推送、远端确认后按单包精确删除；不得为了腾空间整目录清空。

## 经验

- Steam 根目录很大不等于安装了大型游戏；应先解析 `libraryfolders.vdf` 与 `appmanifest_*.acf`，再按子目录统计。
- 清理缓存前必须退出 Steam，避免 WebHelper 重新创建文件或持有锁。
- Windows 递归删除前应解析绝对路径、核对预期路径并拒绝链接/reparse point；只在同一 PowerShell 流程中删除已验证目标。
- “下载”“回收站”“复盘备份”不能仅凭目录名判为垃圾；可重建性、用户所有权和项目闭环状态必须分别核实。
