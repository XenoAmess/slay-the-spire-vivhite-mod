# STS2 v0.111.0 原生游戏知识提取经验

## 问题与结论

STS2AIAgent 的 `/data` 很适合导出实例化后的卡牌、遗物、药水和角色数据，但不能单独承担“全部原生知识”：v0.111.0 的怪物响应虽然有 `moves` 字段，实际 107 个怪物全部为空；端点也没有完整输出卡牌执行逻辑、遗物 hooks、事件分支、商店概率、地图规则等行为。

可靠方案必须组合三个来源：

1. runtime ModelDb 负责当前数值、升级信息、池和引用关系；
2. 本机 `sts2.dll` 的静态结构化 facts 负责字段/属性表达式、构造器、getter/setter/init accessor、递归嵌套类型和方法行为；
3. 官方 PCK 负责英中本地化、资源目录和原生模型类型基集。

最终 v0.111.0 快照使用游戏 commit `41cef1ea`，程序集 SHA256 为 `0861bfa1df347538d932f22d580e75420f08082792eb914e53b4882764acdbe9`，完整 PCK SHA256 为 `c60f672ee7804e6aefa1e19a582fa1c80b126a7b0eef4d084d3abf110df2eab7`。静态 facts v4 共得到 2,202 个类型、837 个构造器、2,132 个 accessor，失败为 0；嵌套类/结构/枚举/委托作为 `Outer+Inner` 独立记录。v4 在调用、创建、赋值、条件与返回、循环、throw/yield/await 以及 `++`/`--` 一元状态变异外，为每个构造器、accessor 和方法增加规范化的嵌套 `control_flow` 语句树，使 if/else 和 switch case 与各自效果不再失去对应关系。例如 Aeonglass 的 `WitherUpgradeCount++` 与 `AdditionalStrength++` 已作为 `mutations` 保存；TestSubject 的 `RespawnMove` 则明确保存 case 1 对应 SecondForm/PainfulStabs、case 2 对应 ThirdForm/Nemesis/移除 Power。除原生 Model 类型外，快照还覆盖 Commands、GameActions、Combat、卡牌引擎、Runs、Creatures、Players、ValueProps、Random、Core.Events 以及卡费/蛋遗物/GrabBag/Seed 等决策关键 helper。核心 runtime 基础集合为 596 卡、299 遗物、107 怪物、66 药水、57 事件、283 Power、5 角色。

## 最容易踩的坑

### localization 不能作为完整性的唯一基集

第一版以英文 localization ID 排除 Mod，误删了 3 个 `DECIMILLIPEDE_SEGMENT_*` 原生怪物和 24 个没有玩家可见文案的原生 Power。修复是优先从 PCK 的 `src/Core/Models/**/*.cs` 路径推导原生类型 ID；localization 只作类型清单缺失时的末级兜底。

PCK 中的 `.cs` 内容全是一字节 stub，但路径仍然是非常有价值且不受已加载 Mod 污染的原生类型清单。

### 官方双语资源本身可能不对称

v0.111.0 的 46 对英中 localization 文件共有 7,028 个 key，并非逐项齐全：6,937 个双语 key，另有 91 个只有英文。除了保留两套官方原文件，还应生成逐 key 并集，明确写 `missing_zhs` 和 `fallback_locale: eng`；不能静默丢 key，也不能把英文回退标成中文。

### runtime 数量和程序集类型数量不同并不必然是漏数

程序集包含 mock、deprecated、剧情专用和静态存在但未注册到 ModelDb 的类型。例如静态卡牌类型有 604 个，而 runtime 是 596 个。正确检查是确保每个 runtime ID 都能关联一个静态类型；静态独有项单独标为 `complete_with_static_only`，不能粗暴要求两边计数相等。

### ID 关联必须复刻游戏规则

游戏用 `StringHelper.Slugify(type.Name)` 产生 `ModelId.Entry`。连续大写字母也逐个插入下划线，例如 `ABCMonster -> A_B_C_MONSTER`。如果用普通 snake_case 库处理缩写，部分类型会静默关联失败。提取器重新实现该规则，并校验 C# 侧给出的 `entry_id`、唯一性和未匹配项。

### 来源必须绑定到同一版本

runtime 响应、PCK 和静态程序集可能来自不同安装版本。manifest 同时记录 `release_info.json`、程序集 SHA256、PCK directory SHA256、每个离线响应 SHA256和每个生成 artifact SHA256。静态 facts 的 assembly SHA 不匹配时直接拒绝导入，不能仅凭版本字符串继续合并。

## 完整性与版权边界

完整性校验包括 artifact 长度/哈希/记录数、从官方 eng/zhs 原文逐键重建双语目录、核心集合字段、ID 唯一性、基础角色初始内容引用闭包、1,724 个 PCK Model 顶层类型闭包、runtime-to-mechanics 覆盖、107 个 runtime 怪物的实质招式状态事实、程序集一致性和原始游戏文件复核。`validation.json` 还绑定最终 manifest SHA256 与实际 artifact-set SHA256；旧报告或快照被改写后，在线读取层会明确拒绝使用。

本方案不保存完整反编译源码、贴图、音频或 PCK，只保存字段/属性以及选定控制流、调用和状态变化的结构化事实摘要、运行时模型数据、短本地化文本和来源哈希。它能回答游戏决策逻辑，但不是可重新编译的完整源码替代品。游戏升级后应创建新版本目录，不覆盖旧快照，也不能把旧知识无版本地注入 AI。
