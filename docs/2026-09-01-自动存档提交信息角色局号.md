# 2026-09-01 自动存档提交信息补充角色与局号

## 背景

Brain 的复盘前在线存档曾生成
`[brain:auto] chore(sts2-ascend): 第1局后复盘前在线存档`。双角色轮换后，单看这个标题无法判断
“第 1 局”属于白绮还是战士，也容易把角色内局号误读为全局计数。

## 当前约定

- 在线存档标题追加 `（角色：白绮/Vivhite，第1局）` 或
  `（角色：战士/Ironclad，第N局）`；合批使用角色内局号范围。
- 局号优先取当前 profile 的 `profile_run_number`（复盘队列的 `run` 同样是 profile-local）；
  不从另一角色或跨角色聚合计数推断。
- 终局存档沿用同一角色/局号上下文，并保留胜负、楼层和生涯摘要。
- 缺少可信局号时明确写 `局号未知`，不伪造数字；旧调用未提供元数据时仍保留兼容的原标题。
- `autogit` 的机器提交识别器同时接受旧标题与带角色后缀的新标题，便于崩溃恢复和历史审计。

## 验证

`test_autogit_safety.py` 覆盖双角色、范围合批、缺省局号和机器标题识别；
`test_review_closure.py` 覆盖在线复盘前存档标题生成。运行：

```text
python -m unittest sts2-ascend.tests.test_autogit_safety sts2-ascend.tests.test_review_closure
```
