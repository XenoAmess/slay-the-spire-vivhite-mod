# 白绮战斗拆件层级骨链候选

## 结论

已在 `assets/vivhite-ironclad/candidates/split_mesh/combat/` 建立与当前运行时完全
隔离的“拆件 + 层级骨链”候选。候选包含 15 个可见 mesh 部件、33 根骨骼、普通
与死亡各 15 个 slot/attachment，并保留原战士消费方要求的 8 个动画、2 个
VFX slot 和 4 个事件。构建和检查均不会部署、重启或操作游戏。

这个版本只用于比较运动学，不能发布。现有 1680×2512 战斗母图经核对是一张
单帧完整人物，不是 spritesheet；它虽为 EvoLink 原生 RGBA 且四角透明，但非零
Alpha 边界已经触及画布左侧，人物周围的半透明光晕跨过所有关节。肩、肘、腕、
髋、膝、踝又都已经压平，源图不存在遮挡后的身体像素。直接打包成发布部件必然
产生切口、叠亮或缺像素。

## 候选实现

- atlas 只保存一次未改变创意内容的母图缩放结果；15 个 Spine mesh attachment
  通过各自 UV 子域读取对应部位。没有阈值、色键、蒙版、抠图或 Alpha 修补。
- 手臂使用 `upper_arm -> forearm -> hand`，腿使用
  `thigh -> knee -> ankle -> foot`；躯干使用 pelvis、上下躯干、颈和头的层级链。
- 普通攻击根位移 104 个 Spine 单位，重击 164，受伤后退 120；在场景 `.28`
  下分别是 29.12、45.92、33.6 像素，符合对照目标。父子旋转还会进一步扩大手掌
  的实际弧线，而不是只平移整个人。
- `die` 在 0 秒发出 `clear_vfx`，随后髋、膝、踝、躯干、头、双臂和头发错峰
  坍塌并有一次落地余震。根骨最大仅旋转 7 度，死亡不再依赖整张站姿旋转 76 度。
- 普通 slot 在死亡开始时切空，同时切换到独立命名的 `death_*` slot；当前死亡
  attachment 暂时读取同一母图 UV，仅验证切换与骨链，最终必须换成专门侧倒绘图。

## 素材与源码契约核对

素材侧核对了战斗母图、当前 `.spatlas`、`.spjson` 与原战士提取包。源码侧核对了
`IroncladReplacementAssets.cs` 的资源注册、当前和原版 `combat.tscn` 对
`NIroncladVfx`、`SlashVfxSlot`、`EyeSlot` 的绑定。因此候选继续保留：

- 动画：`idle_loop`、`low_health_loop`、`relaxed_loop`、`attack`、
  `attack_heavy`、`cast`、`hurt`、`die`
- slot：`slash_mesh`、`eye_attach_slot`
- event：`attack_slash_start`、`heavy_slash_start`、`cast_eyes_start`、
  `clear_vfx`

完整的部件矩形、slot/attachment 名、已知缺陷、消费证据和最终重绘输入契约记录
在候选目录的 `candidate.json`，以便离线比较器用 `Name=directory` 直接接入。

## 发布前必须补齐

最终版必须从干净参考图出发，使用仓库规定的 EvoLink `gpt-image-2` 原生透明路径
分别生成后发、头/前发/蝶饰、躯干、裙片、左右上臂/前臂/手、左右大腿/小腿/脚，
并生成独立的侧倒死亡套件。每个关节需要在相邻部件下方留出遮挡余量，切口区域
不得烘入光晕；魔法辉光继续作为独立特效层。所有独立图验收通过后才能替换本候选
的临时 UV attachment 并进入运行时 atlas。

## 2026-08-28 动画契约修订

- 以 `.work/ironclad-v0.111.0/combat/combat_skeleton_data.tres` 为唯一基准，
  在候选 `_skeleton_data.tres` 补回原版的 10 条逐 transition mix。四条非零覆盖
  分别为 `idle_loop -> attack = 0.1`、`idle_loop -> hurt = 0.03`、
  `hurt -> idle_loop = 0.1`、`idle_loop -> attack_heavy = 0.02`；attack、heavy、
  hurt 自切与交叉，以及 `hurt -> die` 保持 0，默认 mix 保持 0.05。
- 早期候选把左右 `shoulder` 与 `upper_arm` 放在同一 setup 坐标，导致 bind 段
  零长度。现在仅把 shoulder 移到锁骨内侧，上臂世界坐标和 attachment setup pose
  不变，并在 JSON 中为主要骨链写出明确 `length`。
- 线性关键帧改为 Spine 4.2 合法 Bezier：rotate 每段 4 个值，translate 的 X/Y
  各自一组、共 8 个值，控制点先按归一化曲线计算，再转换为该段的绝对时间和数值。
  该格式依据 Spine 官方 4.2 runtime 的
  [`SkeletonJson.cs`](https://github.com/EsotericSoftware/spine-runtimes/blob/4.2/spine-csharp/src/SkeletonJson.cs)，
  而不是沿用旧版归一化 JSON 格式。循环和强动作只改变插值速度，不改变关键姿势、
  动画时长、事件时刻或场景 `.28` 下的位移目标。
- 这次修订没有解除美术门禁：当前裁片仍来自带整身光晕的扁平母图，真实独立拆件与
  独立侧倒死亡图仍必须经 EvoLink 原生透明路径重绘后，才可能成为发布素材。

## 验证

生成脚本已经完成以下离线检查：

- 输出目录拒绝指向运行时 skin；付费生成调用数为 0。
- `.spjson`、`.spatlas`、`.tres`、PNG 和 `candidate.json` 自包含且可解析。
- atlas 为 3072×2304 RGBA8，三个 region 唯一。
- 33 根骨骼的臂/腿父子关系、30 个普通/死亡部件 slot、8 个动画时长及所有事件
  均通过静态契约检查；左右肩至上臂 bind 均为 20.844 Spine 单位。
- 10 条 transition mix 与原提取资源逐条一致；333 个 rotate/translate 动画段均有
  符合 Spine 4.2 维数与绝对时间范围的 Bezier，错误数为 0。
- 当前运行时目录无改动；没有部署或游戏进程操作。

Vulkan 逐帧对照由共享比较工具串行执行，避免多个 Godot editor 同时争用 Spine
GDExtension 临时 DLL。第一次并行预览在发现争用后立即中止，没有触碰游戏；后续
统一交由比较任务产生接触表与运动统计。
