# 白绮战斗拆件层级骨链候选

## 结论

已在 `assets/vivhite-ironclad/candidates/split_mesh/combat/` 建立与当前运行时完全
隔离的“拆件 + 层级骨链 + 整图落地”Hybrid 候选。候选包含 15 个可见 mesh
部件、33 根拆件骨骼、1 根隔离的侧卧落地骨、普通与死亡预览各 15 个
slot/attachment，以及 1 个最终侧卧 attachment；它继续保留原战士消费方要求的
8 个动画、2 个 VFX slot 和 4 个事件。构建和检查均不会部署、重启或操作游戏。

这个版本只用于比较运动学，不能发布。现有 1680×2512 战斗母图经核对是一张
单帧完整人物，不是 spritesheet；它虽为 EvoLink 原生 RGBA 且四角透明，但非零
Alpha 边界已经触及画布左侧，人物周围的半透明光晕跨过所有关节。肩、肘、腕、
髋、膝、踝又都已经压平，源图不存在遮挡后的身体像素。直接打包成发布部件必然
产生切口、叠亮或缺像素。

## 候选实现

- atlas 只保存一次未改变创意内容的母图缩放结果；15 个 Spine mesh attachment
  通过各自 UV 子域读取对应部位。没有阈值、色键、蒙版、抠图或 Alpha 修补。
- 手臂使用 `upper_arm -> forearm -> hand`，腿使用
  `thigh -> knee -> ankle -> foot`；躯干使用 pelvis、上下躯干、颈和头的层级链。
- 普通攻击根位移 104 个 Spine 单位，重击 164，受伤后退 120；在场景 `.28`
  下分别是 29.12、45.92、33.6 像素，符合对照目标。父子旋转还会进一步扩大手掌
  的实际弧线，而不是只平移整个人。
- `die` 在 0 秒发出 `clear_vfx`，先以 `death_*` 预览拆件驱动髋、膝、踝、躯干、
  头、双臂和头发错峰失衡下坠。根骨最大仅旋转 7 度，死亡不再依赖整张站姿旋转
  76 度。
- `1.05 s` 原子卸载全部 15 个预览拆件，并在同一帧挂上独立侧卧整图。实测
  交叉淡化会在中点同时显示两种不相似的轮廓，因此改用无空帧、无双影的离散切换；
  侧卧整图随后下落至 `1.17 s` 接触地面，在 `1.31 s` 轻微回弹，`1.80 s`
  回到最终落点并保持静止到 `2.3333335 s`。
- 最终源固定为
  `assets/vivhite-ironclad/custom/combat/sources/vivhite-combat-death-side-collapse-v2.png`。
  它经过原生 Alpha 验收后只做等比尺寸适配，完整放入独立的第二 atlas 页；没有
  阈值、色键、蒙版、抠图或 Alpha 修补。

## 素材与源码契约核对

素材侧核对了战斗母图、当前 `.spatlas`、`.spjson` 与原战士提取包。源码侧核对了
`IroncladReplacementAssets.cs` 的资源注册、当前和原版 `combat.tscn` 对
`NIroncladVfx`、`SlashVfxSlot`、`EyeSlot` 的绑定。因此候选继续保留：

- 动画：`idle_loop`、`low_health_loop`、`relaxed_loop`、`attack`、
  `attack_heavy`、`cast`、`hurt`、`die`
- slot：`slash_mesh`、`eye_attach_slot`
- event：`attack_slash_start`、`heavy_slash_start`、`cast_eyes_start`、
  `clear_vfx`

完整的部件矩形、slot/attachment 名、已知缺陷、消费证据和最终重绘输入契约记录
在候选目录的 `candidate.json`，以便离线比较器用 `Name=directory` 直接接入。

## 发布前必须补齐

最终版必须从干净参考图出发，使用仓库规定的 EvoLink `gpt-image-2` 原生透明路径
分别生成后发、头/前发/蝶饰、躯干、裙片、左右上臂/前臂/手、左右大腿/小腿/脚。
每个关节需要在相邻部件下方留出遮挡余量，切口区域不得烘入光晕；魔法辉光继续
作为独立特效层。侧卧死亡整图 v2 已满足本 Hybrid 方案的输入契约，不再要求额外
生成一套侧卧拆件。所有独立站姿部件验收通过后才能替换本候选的临时 UV attachment
并进入运行时 atlas。

## 2026-08-28 动画契约修订

- 以 `.work/ironclad-v0.111.0/combat/combat_skeleton_data.tres` 为唯一基准，
  在候选 `_skeleton_data.tres` 补回原版的 10 条逐 transition mix。四条非零覆盖
  分别为 `idle_loop -> attack = 0.1`、`idle_loop -> hurt = 0.03`、
  `hurt -> idle_loop = 0.1`、`idle_loop -> attack_heavy = 0.02`；attack、heavy、
  hurt 自切与交叉，以及 `hurt -> die` 保持 0，默认 mix 保持 0.05。
- 早期候选把左右 `shoulder` 与 `upper_arm` 放在同一 setup 坐标，导致 bind 段
  零长度。现在仅把 shoulder 移到锁骨内侧，上臂世界坐标和 attachment setup pose
  不变，并在 JSON 中为主要骨链写出明确 `length`。
- 线性关键帧改为 Spine 4.2 合法 Bezier：rotate 每段 4 个值，translate 的 X/Y
  各自一组、共 8 个值，控制点先按归一化曲线计算，再转换为该段的绝对时间和数值。
  该格式依据 Spine 官方 4.2 runtime 的
  [`SkeletonJson.cs`](https://github.com/EsotericSoftware/spine-runtimes/blob/4.2/spine-csharp/src/SkeletonJson.cs)，
  而不是沿用旧版归一化 JSON 格式。循环和强动作只改变插值速度，不改变关键姿势、
  动画时长、事件时刻或场景 `.28` 下的位移目标。
- 这次 Hybrid 修订解除了“死亡末帧复用站姿 UV”的问题，但没有解除站姿拆件的
  美术门禁：当前裁片仍来自带整身光晕的扁平母图，真实独立站姿拆件仍必须经
  EvoLink 原生透明路径重绘后，才可能成为发布素材。

## 验证

生成脚本已经完成以下离线检查：

- 输出目录拒绝指向运行时 skin；付费生成调用数为 0。
- `.spjson`、`.spatlas`、`.tres`、PNG 和 `candidate.json` 自包含且可解析。
- atlas 第一页为 3072×2304 RGBA8、第二页为 2048×1536 RGBA8，四个 region
  均唯一；侧卧图与站姿/魔法素材互不扰动。
- 34 根骨骼的臂/腿父子关系、30 个普通/死亡预览部件 slot、1 个侧卧整图 slot、
  8 个动画时长及所有事件均通过静态契约检查；左右肩至上臂 bind 均为 20.844
  Spine 单位。
- 静态检查强制 normal parts 在 `die@0` 隐藏、death-preview parts 在 `1.05 s`
  全部原子卸载、侧卧整图在同一帧挂载、`1.17 s` 到达实体接触落点，以及
  `1.80 s` 至动画末端完全静止。
- 10 条 transition mix 与原提取资源逐条一致；333 个 rotate/translate 动画段均有
  符合 Spine 4.2 维数与绝对时间范围的 Bezier，错误数为 0。
- 当前运行时目录无改动；没有部署或游戏进程操作。

Vulkan 逐帧对照由共享比较工具串行执行，避免多个 Godot editor 同时争用 Spine
GDExtension 临时 DLL。第一次并行预览在发现争用后立即中止，没有触碰游戏；后续
统一交由比较任务产生接触表与运动统计。

## Hybrid 死亡专项验收

最终候选使用游戏实际 Spine 4.2.43 GDExtension 和 Windows Vulkan，在固定
`1280×900` 画布、场景 `.28`、位置 `(325, 681)` 下完成两组离线验收：

- `.work/combat-rig-compare-preview/split-hybrid-v2-atomic-final/` 对 whole/split
  两个候选的 8 个动画各采 5 帧；`split_hybrid_atomic.passed = true`，没有空帧、
  触边、静态动画或契约错误。
- `.work/ironclad-render-acceptance/split-hybrid-death-v2-atomic-exact/` 使用手动更新
  模式精确采样 `die@1.04/1.05/1.11/1.17/1.31/1.80/2.3333335`。`1.04 s`
  仍只有拆件坍塌，`1.05 s` 已只有侧卧整图，切换中没有空帧或双影；之后依次可见
  下落、接地、单次回弹和静止。
- 无空帧/无双影不代表姿势已连续。精确 PNG 的 `1.04 s` Alpha bbox 为
  `237,445,242,250`，人物仍是近竖直蜷缩；`1.05 s` bbox 为 `176,464,332,174`，
  已是横躺。这一帧的左边界向左跳 `61 px`、宽度增加 `90 px`、高度减少 `76 px`，
  是尚未解决的 **preview candidate defect**。本候选只能保留为离线对照，不得宣称为
  最终动画自然度，不可发布，也不可接入运行时皮肤。
- 站姿 setup 的 Alpha bbox 为 `220×357`，死亡末帧为 `356×208`；侧卧实体宽度
  基本等于站姿高度，只能证明两张源图的人物总体长轴尺度相当，不能抵消
  上一条的原子切换姿势跳变。死亡末帧四边触边计数均为 0，画布没有裁切。
- v2 的淡光延伸到绘制实体下方，若按最淡 Alpha bbox 对地会让手和靴子明显悬空。
  因此死亡骨使用 `224.8` Spine 单位的实体接触补偿；人工复看确认绘制实体落地，
  允许的整体光晕仍留在同一个刚性 slot 内，不会产生关节叠亮。
- `die@1.80` 与 `die@2.3333335` 的 PNG SHA-256 均为
  `B3EC3FDB639E351EEE3306CCA229A7AE33D61D526913B940794267BBD5871EFE`，证明末段
  确实静止。`1.31 s` 哈希不同，证明回弹不是静态占位。

专项验收还修正了一个测试工具陷阱：单帧预览若让 `SpineSprite` 保持自动更新，等待
Vulkan 出图的两帧会悄悄把采样时刻向后推进。现在预览器显式使用 manual update，
并把窗口设为不可聚焦、移到屏幕外；记录的时间与实际 Spine 时间一致。
