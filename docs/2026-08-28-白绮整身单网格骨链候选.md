# 白绮整身单网格骨链候选

## 目的与隔离边界

此候选用于与“拆件 + 骨骼”方案并排比较。它继续使用一张完整白绮身体图，但不再把所有变形控制骨直接挂在同一个根骨下，而是建立真实父子骨链。候选不部署、不修改当前运行时皮肤，也不操作游戏、brain 或直播。

- 构建器：`tools/art/candidates/whole_mesh/build_whole_mesh_candidate.gd`
- 无窗口 Spine 校验器：`tools/art/candidates/whole_mesh/validate_whole_mesh_candidate.gd`
- 自包含候选五件套：`Vivhite/tools/candidates/whole_mesh/`（`.spjson`、`.spatlas`、两张 PNG、`.tres`）
- Godot 生成的 `.uid`、`.import` 只是被 Git 忽略的本地导入缓存，不属于候选包。

候选目录位于 Mod 工程已有的 `tools/**` PCK 排除范围内，因此普通导出不会把它误带进发布包。其 `.tres`、`.spatlas` 内部路径全部指向 `res://tools/candidates/whole_mesh/`，不引用或覆盖 `res://Vivhite/skins/ironclad/spine/combat/`。

## 素材与消费契约核对

输入的 `vivhite-combat-body-master-v1.png` 与 `vivhite-combat-death-side-collapse-v2.png` 都是单幅完整 RGBA 人物图，不是 spritesheet 或 packed atlas。构建产物使用两张 atlas 页：第一页保留站立整身网格、独立魔法弧和独立魔法阵三个 region，第二页只放独立侧卧死亡图一个 region。第二页隔离的目的，是以后替换死亡源时不重新打包或扰动已验证的第一页。`v1` 永久保留为预览历史，当前候选选用留白更足的 `v2`；其整体柔光只在一个完整 attachment 内渲染，不会产生拆件叠亮接缝。

实际战斗场景继续要求一个 `SpineSprite`，缩放为 `0.28`；源码与场景还要求 `slash_mesh`、`eye_attach_slot` 以及四个 VFX 事件。因此候选保留：

- 八个动画：`idle_loop`、`low_health_loop`、`relaxed_loop`、`attack`、`attack_heavy`、`cast`、`hurt`、`die`；
- 事件：`attack_slash_start`、`heavy_slash_start`、`cast_eyes_start`、`clear_vfx`；
- 插槽：`slash_mesh`、`eye_attach_slot`；
- 70% 骨架内部人物尺寸，即 `868 × 1302`，场景侧 `0.28` 不变；
- 单一 `vivhite_combat_body` 站立加权网格，345 个顶点、616 个三角形；仅 `die` 在落地阶段切换到独立 `vivhite_combat_death_side` region，其他七个动画不驱动这两个身体 slot。

## 新骨链

候选共 34 根骨，关键父子关系为：

- `pelvis -> torso_lower -> torso_upper -> neck -> head`；
- `torso_upper -> shoulder -> upper_arm -> forearm -> hand`，左右各一条；
- `pelvis -> hip -> thigh -> shin -> foot`，左右各一条；
- 头发、蓝蝶跟随头部，裙摆跟随骨盆；
- `slash_mesh` 的魔法弧锚点跟随右手，眼部 VFX 锚点跟随头部。
- 独立 `vivhite_death_pose` 直接挂在 root 下，只负责侧卧图的快速落地与余震，不参与站立网格权重。

网格每个顶点最多受四根邻近骨影响。与旧版全部平铺到 `vivhite_rig` 的结构相比，旋转肩膀会自然携带上臂、前臂、手和魔法弧，旋转躯干会携带头部和双臂，弯曲髋部会携带整条腿。

## 动作幅度

按战斗场景固定缩放 `0.28` 计算，构建门禁与 Spine 实际加载校验得到：

| 动作 | 校验口径 | Spine units | 场景像素 |
| --- | --- | ---: | ---: |
| 普通攻击 X | 从零点向前峰值 | 100 | 28.0 px |
| 重击 X | 从零点向前峰值 | 158 | 44.24 px |
| 受伤 X | 从零点向后峰值 | 100 | 28.0 px |
| 施法 Y | 全关键帧范围 | 62 | 17.36 px |
| 待机 Y | 全关键帧范围 | 19 | 5.32 px |

普通攻击增加预备后撤、向前发力、回弹和回正；重击使用更大的重心与手臂链摆幅。门禁必须读取相对零点的**方向峰值**，不能把“预备后撤最小值到冲刺最大值”的总 range 误报成前冲距离：旧口径曾把普通攻击的 `-22 → 76` 误报为 98 units，实际前冲只有 76 units；现在构建器和独立校验器都直接限制普通攻击为 `95–105`、重击为 `150–165`，受伤向后至少 `95` units。

所有骨骼的 rotate/translate 相邻关键帧都加入 Spine 4.2 格式的 Bézier 曲线。Spine 4.2 的控制点是绝对时间/数值坐标，不是简单写入归一化的 `[0.25, 0, 0.75, 1]`；构建器先按每段起止时间和值换算后再序列化。循环使用对称 ease-in/ease-out，攻击、施法、受伤与死亡使用稍快的动作曲线，在不改变关键姿势、动画时长和事件时刻的前提下消除线性匀速及拐点速度突变。当前共校验 `720` 个 Bézier 段。

施法让躯干上提、双臂经肩—肘—腕链明显展开。死亡不再做单段 `-76°` 翻牌：站立加权网格先用十个 root 位置关键帧和多组关节关键帧完成“预备失衡 → 屈膝弯腰 → 侧倒”。`0.94s` 开始明显侧倾，`1.0499s` 的最后可见站立帧达到 root `x=-360 / y=150 / rotation=-47°`；正 y 是围绕低位 bind 原点旋转时的对地反向补偿，画面里的实体重心仍向下。双臂与双腿都写入同一时刻的收拢键，但只推进到 kneel→fall 的 50%，大幅侧倾主要由 root 提供，避免单网格被局部关节拉成橡皮布。随后在 `t=1.05s` 用两个 attachment timeline 同帧完成原子切换。切换前只有站立网格，切换时及之后只有专用侧卧图；两个 slot 都不含 `rgba` timeline，因此不会再出现交叉淡化造成的双人重影。死亡专用骨随后在 `1.1666667s` 接地、`1.30s` 轻微回弹、`1.80s` 完全静止；总时长仍为 `2.3333335s`，`clear_vfx` 仍在 `t=0` 发出。

### 死亡落地对齐

不能用 v2 最微弱的整体柔光边缘代替实体接触边缘。首次按任意非零 Alpha 对地时，离线 Vulkan 画布的地面线约为 `y=698px`，实体底缘约为 `y=621px`，肉眼会悬空约 `77px`。最终采用两处等量补偿，并由构建器与独立校验器同时写死：

- `vivhite_death_pose` setup y 从 Alpha 基线 `412.8` 下移 `224.8` Spine units 至 `188.0`，对应场景 `62.944px`；
- `1.05s` 原子切换关键帧的局部 y 同时由 `74.0` 增加 `224.8` 至 `298.8`，因此初现世界 y 仍是 `486.8`，不会因最终对地校准而提前跳位。

这样侧卧图从 `1.05s` 切换帧到 `1.1666667s` 接地帧，在约 `0.1167s` 内可见下落 `298.8` units，即 `83.664px`，最终实体底缘约 `y=684px`、距地约 `14px`。柔光会延伸到实体下方，但 Vulkan 采样中所有 Alpha bbox 均未碰画布边缘；这属于已接受的单 attachment 整体柔光，不是拆件关节光晕。

## 已知限制

单网格方案仍有结构上限，不能仅靠增加骨骼完全消除：

- 手臂交叉身体时不能改变独立部件的前后遮挡顺序；
- 大角度肩、肘、膝弯曲会把原画像橡皮布一样拉伸，衣纹和轮廓可能剪切；
- 侧卧死亡图是独立重绘的完整 attachment，解决了把站立图卷曲成倒地轮廓的问题，但其内部肢体不能继续单独摆动；落地后的余震只能移动整张图；
- `0.94–1.0499s` 的最后一小段仍受单一加权整身图限制：虽然 root 侧倾和平移已把切换前后 bbox 左上误差压到 `5px / 5px`，但右侧垂腿和关节拉伸仍可见，且 `1.0→1.0499s` 的 bbox 顶边下移约 `42px`。它适合作为两套方案的离线比较候选，不应被描述为最终生产质量；拆件候选才有条件继续消除这类局部形变；
- v2 带有已接受的整体柔光。它不会在单 attachment 内产生接缝，但柔光会延伸到实体接触边缘以下，仍需在真机地面材质上复核观感；
- 母图自带的整身柔光会随网格一起弯曲。单网格不会产生拆件接缝，但强动作时柔光形状也会变形。

因此此候选适合用于确认“只加正确骨链”能提升到什么程度，不能替代后续 Vulkan 接触表与拆件候选的并排人工验收。
