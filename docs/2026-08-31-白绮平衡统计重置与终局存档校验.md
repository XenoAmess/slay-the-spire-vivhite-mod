## 原生进度保存误报根因

游戏的 `SaveManager.GetProfileScopedPath(...)` 返回 Godot 虚拟路径，例如：

`user://steam/<steam-id>/modded/profile1/saves/progress.save`

旧 Agent 把这个值直接交给 .NET `FileStream`，Windows 文件 API 不识别 `user://`，于是原生保存明明完成，读回验证仍持续抛出 `IOException`。

真机证据表明故障局的 `progress.save` 已正常写入：分数由 352 增至 554；日志中的“分数不足以升级”说明本局没有新解锁是正常结果，并非解锁丢失。

最终修复位于 STS2-Agent fork 提交 `99950d9`：验证与 `SaveManager` 使用同一 Godot `FileAccess` 路径读取，再交给纯 JSON 等价校验。Agent C# 测试 59/59 通过，fork 已构建并部署。

## Git 假脏状态

大量 `D + ??` 不是几千份文件漏提交，而是 Brain 私有 index 提交成功后，真实 `.git/index` 曾被 `index.lock` 阻挡而长期停在混合旧状态。

修复和迁移结果：

- 主仓与远端一直能正常推进；问题主要在真实 index，不在 commit/push。
- `e81da2c3` 为 review patch 增加耐久 index 恢复事务。
- 迁移前完整 index SHA-256：`F3001C3F6CA7ED089605B9FFCD5331E1112C00B9EA674F3B0C40AE97B36370CA`。
- 原 index 与 382,769,504 字节的 staged binary patch已保存到 `knowledge/code_backups/index_recovery/20260831-1618-stale-machine-index/`。
- 1039 个 staged 路径中，1008 个经工作树 blob 与 HEAD blob 相等证明为机器假暂存，已精确恢复。
- 旧占位资源的孤儿 index 条目也已解除；没有删除工作树文件。
- 9 张既有直播姬截图及 AGENTS/README/两份文档的真实 staged 内容原样保留。
- 三个高频 viewer/TTS 日志已停止 Git 跟踪，但本地运行文件保留。

禁止用 `reset --hard`、`clean` 或全仓 `git add -A` 处理这种状态；必须先备份 index 和 staged binary patch，再按精确 blob 证据迁移。
