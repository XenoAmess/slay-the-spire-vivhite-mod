# 复盘缓存误杀与历史补合

## 根因

隔离复盘完成后，宿主为了满足“失败时保留全部文件”的要求，以 `git add --all --force`
捕获 tracked、untracked、ignored 和被规则拒绝的全部现场。旧实现随后错误地把这份取证路径
再次当作自动合入验收路径。OpenCode 在分析或执行自检时产生的 `__pycache__/*.pyc` 因而被
判为越过 allowlist，已经通过自检的 Python 源码也随整批被拒绝。

正确模型是三条互不混用的链：

1. 允许源码 patch：只含模型真正要合入、且通过 allowlist 与自检的文件。
2. cache 临时产物：不合入、不阻断，但记录路径并保留原始字节。
3. 全量取证现场：失败时保留所有文件，供人工逐批分析和补合。

cache 分类兼容所有工具：任一层路径名只要包含 `cache`（大小写不敏感），或文件为标准
Python 字节码缓存后缀，都会进入第二类；是否写在 `.gitignore` 中不影响分类。非 cache 的
ignored 或越界文件仍然阻断自动合入。

## Windows 补合包发布

旧实现复制完整 sandbox 后，还会把内部临时目录改名为 `raw_sandbox`。Windows 杀毒、索引器
或刚退出进程的短暂文件句柄可能让目录改名报 `WinError 5`，留下未完成 `.tmp` 包。新实现直接
续拷到包内最终子目录，以外层包发布或 pointer + manifest 作为完成边界；已有半包会在下次
恢复时补齐，而不是因目标目录存在就误判完成。最终原子发布对短暂共享锁有有限重试。

## 历史补合审计

所有旧 `review_salvage/` 与 `review_work/` 批次按时间顺序逐项核查。每批只提取真实源码或
仍有价值的知识结论，排除 cache、`.runtime/rvtmp/`、viewer 日志和锁文件；通过隔离应用检查、
自检、提交和远端确认后，才删除对应失败包与重复 sandbox。最终处理结果会继续追加在本文。

拒合索引另设为受 Git 跟踪的 `sts2-ascend/REVIEW_REJECTIONS.md`。宿主在新失败包完成原子发布后
立即追加记录，并用精确 pathspec 单独 commit；常态同步推送，停止临界区先提交后补推。因此失败
原件即使后续按要求删除，批次、原因、处理状态和补合提交仍可从 Git 永久追溯。
