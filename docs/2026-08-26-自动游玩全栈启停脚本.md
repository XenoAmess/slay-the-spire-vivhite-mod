# 自动游玩全栈启停脚本

## 目标

此前 `Start-Agent.ps1` 是前台 runner 包装，停止主要依赖终端 `Ctrl+C`。游戏、runner/brain、白绮碎碎念，以及复盘期间临时出现的 OpenCode、悬浮窗和朗读器并不共享一个可靠的生命周期，因此容易出现 brain 被 runner 重拉、播报子进程孤儿化、游戏仍在运行等情况。

本次将统一入口定义为：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\sts2-ascend\scripts\Start-Agent.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\sts2-ascend\scripts\Stop-Agent.ps1
```

Start 默认后台启动整套；Stop 默认停止 Python/播报/复盘链并关闭游戏。需要保留游戏时显式传 `-KeepGame`。

## 生命周期协议

`brain/lifecycle.py` 和两份 PowerShell 脚本通过 `sts2-ascend/.runtime/` 协作：

- 每次 Start 生成 32 位 GUID session，并把 session、游戏路径、runner PID、PID 文件与 stop sentinel 路径写入 `session.json`。
- runner 和 brain 用 `pid_file(role)` 原子发布 JSON PID 记录。记录包含 session、PID、Python 路径、argv、Unix 创建时间和 Windows `creation_filetime`。
- 所有长驻 Python 组件继承 `STS2_ASCEND_SESSION_ID`、`STS2_ASCEND_RUNTIME_DIR`、`STS2_ASCEND_STOP_FILE`，用 `stop_requested()` 或 `wait_for_stop()` 响应停止。
- Stop 写 `stop.<session>.request` 后先等待协作退出。GUID sentinel 停机后故意保留，防止延迟运行的旧进程跨新 session 复活；新 Start 使用新 GUID，不清旧 sentinel。
- 全局 `stop.request` 只兼容 legacy 手动进程；确认 scoped 进程为零后可以清除，避免阻断 viewer demo 等手动诊断。

## 精确停止与误杀防护

不能只凭 PID 或进程名停止，因为 Windows 会复用 PID，开发机也可能同时运行无关 Python/OpenCode。Stop 的目标身份由以下信息组合确认：

- PID + Windows 创建时间/FILETIME
- 可执行文件绝对路径
- 完整命令行
- 作为独立 argv token 出现的工作区脚本绝对路径
- session PID 记录，或已验证父进程的同一时刻进程树后代

停止顺序是：协作 sentinel → runner 优先兜底 → 深层后代 → 最终静默复扫 → 游戏 `CloseMainWindow()` → 超时后只强停同一创建身份的游戏 PID。

脚本明确排除 `python -m py_compile <脚本>`，不会因为维护命令提到了 `runner.py` 或 TTS 文件就误判成运行组件。OpenCode 复盘必须同时满足本仓库 `--dir` 参数、`--auto` 和 `sts2-ascend` 标记；不会泛杀用户的其他 OpenCode 会话。8080–8084 只用于就绪探测和停止后的告警，绝不作为杀进程依据。

旧版相对路径 `py ... brain\runner.py` 没有 session 或绝对工作区身份。Stop 只有在祖先链能追溯到本工作区 `Start-Agent.ps1` 时才会处理；无法证明归属时保留 sentinel 并报告 incomplete，要求先关闭旧前台终端，宁可停不全也不误杀另一个项目。

## 复盘、队列与播报收尾

- 复盘 stdout 改为可中断轮询；停机时终止 OpenCode，超时再 kill。
- 中断复盘会保留复盘前备份点和待重试队列；停机路径不执行 `git restore`、commit 或 push，避免覆盖并发用户改动，实时增长的 `knowledge/` 也不会回退。
- `review_queue.json` 使用进程内锁和临时文件 `os.replace` 原子写；中断批次保留为 `reviewing`，下次 brain 启动立即恢复并优先保留，不等下一次 cadence。
- agent 退出前请求并 join 复盘 worker，再保存 Knowledge，避免两个线程竞争同一个临时文件。
- quipper、speaker 和 viewer 的锁只由记录中的 owner PID 释放；结构化语音锁使用真实进程创建时间抵御 PID 复用，同时保持跨 session 全局单实例。
- runner、agent、viewer、edge/nano/sapi speaker、quipper 和 stall-analysis 都会观察停止信号；Stop 的进程树仍作为外部库或阻塞播放无法及时返回时的兜底。

## 踩坑与解决方案

1. PowerShell 函数返回数组会被 pipeline 解包。零项可能是 `$null`，一项可能是标量；StrictMode 下直接 `.Count` 会失败。调用方必须写成 `@(Get-...)`。
2. `-WhatIf` 会传播给 `New-Item`，导致 `.runtime` 不存在时目录没有创建、锁文件打开反而报“并发操作”。WhatIf 路径现在完全跳过目录和互斥锁写入，只做发现与展示。
3. 本机 Python 3.14 会在 stderr 输出无害的 prefix 警告。`Get-PythonExe` 不能在全局 `ErrorActionPreference=Stop` 下把任意 stderr 当失败，改为局部静默 stderr、以退出码和 stdout 路径判断。
4. `session.json` 或锁文件可能损坏/残留。所有可写/删除的 runtime 路径都限制在 `.runtime`，session ID 只接受 GUID；游戏目标还要求文件名严格为 `SlayTheSpire2.exe`。
5. Stop 初始快照后父 PID 可能死亡并被复用。后续扫描只扩展“同一快照里仍具有相同创建身份”的父节点，不从已死/复用 PID 猜测 generic descendants。
6. 默认后台 Start 后，终端 `Ctrl+C` 已不再是完整停止方式；单杀 brain 还会被 runner 重拉。文档与 AGENTS 必须统一指向 Stop-Agent。

## 验证记录

- PowerShell 5.1 AST：Start/Stop 均无解析错误。
- Python：`brain/` 与 `tts/` 全量编译通过，`brain/selfcheck.py` 通过。
- `Stop-Agent -WhatIf`：无 `.runtime` 时成功，且 runtime 文件名、大小、mtime 均无变化。
- 空栈连续 Stop：两次均成功，验证幂等。
- 隔离 fake game 端到端：后台 Start → brain PID/session 精确记录 → 第二次 Start 复用原 runner → quipper/uv 多层子进程存在 → Stop 后 scoped 进程、session、PID、voice/viewer lock 全部为零。
- 就绪超时路径：API 不存在时只警告，runner/brain 保持后台自愈，未误报 Stack ready。

## 后续维护清单

新增长驻脚本或锁文件时必须同步维护：

1. Python 组件接入 `lifecycle.py`。
2. Start 的 residual component 清单。
3. Stop 的 scoped argv 清单、lockSpecs 与 markerSpecs。
4. AGENTS 和 README 的组件/参数说明。
5. 至少回归冷启动、重复 Start、启动中 Stop、重复 Stop、`-KeepGame`、活跃复盘/TTS Stop、无关 Python/OpenCode 与陈旧 PID/锁场景。
