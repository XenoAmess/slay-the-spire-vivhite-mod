# 异步复盘不可达 Git 树的终止与重建

## 现象与根因

失败包 `20260831-160236-1788163356144258200-8a06cee9` 的 `raw_sandbox/repo`
只保留了 `.git`，HEAD 指向无效分支，raw index 又依赖不可读的
`77c7e23af4c924ade2209c4d0c33887bb57c5971` tree。候选物化因此持续返回
`Needed a single revision / unable to read tree`。

原机制把任何物化失败都当作暂时未就绪：重审预检不启动 provider，而是把同一个 target
继续留在队首。对象图已经永久不完整时，这会形成无意义的无限重试。

## 修复

- 必需 Git 来源出现明确的对象图不可达错误时，只尝试一次，并在失败包中写入
  `retry_materialization_failure.json`。
- manifest 进入 `source_git_graph_unreachable_preserved` 状态，声明物化终止、禁止自动重试，
  但保留原始 raw clone、WIP、报告、changed-files 快照和其他根目录证据。
- 完整 lineage 挂载允许携带这种终止包。它不会伪造一个“空 candidate”，而是明确标注
  `candidate_materialization_complete=false`，同时把仍可恢复的 WIP、报告、快照文件及已知
  raw worktree 文件交给复盘模型。
- 若之后发布 `validated_candidate.patch`，或修复 raw clone 后显式使用
  `force_rebuild=True`，同一包可以重建为普通 schema 3 candidate；先前失败记录继续保留在
  历史与失败记录文件中。
- 无效 raw HEAD 不再单独阻断物化；真正需要终止的是候选所依赖的 Git 对象图不可读。

## 回归验证

- 新增损坏 loose tree 的真实 Git 仓库样本。
- 验证首次失败写入耐久终止状态，第二次调用不再执行 Git 命令。
- 验证终止 attempt 不再阻塞 target 的完整证据挂载，并保留 WIP、报告、快照与 raw worktree
  成果。
- 验证新增 validated candidate 后可以重建，且原始失败记录不丢失。
- 现有 failed-review evidence mount 测试与 raw index/ref/stash/private-object 回归继续通过。

本次按要求未调用全栈启停、部署或真机输入，也未修改真实失败包、提交或推送。
