# 白绮 NOPE 图标部署撕裂

日期：2026-08-31

## 已确认结论

游戏内出现红色 `NOPE` 状态图标的根因已经确认：游戏部署目录中的白绮 Mod 使用了新版 DLL，却仍搭配旧版 PCK，DLL 与 PCK 的生成时间和包内内容不一致，形成部署撕裂。

当前源码侧检查结果正常：

- 白绮的 23 个 Power 资源路径均正确。
- 白绮的 95 项内容注册均成功。
- 孤高冠冕及相关资源路径没有发现注册错误。
- 旧版 PCK 中缺少新版 DLL 已经请求的资源，包括 `InfiniteMarginPower.png`、`InfiniteDrainPower.png`、`ColorConservationPower.png` 等独立 Power 图标。

因此，新版 DLL 在运行时请求这些资源时，旧版 PCK 无法提供对应文件，游戏最终显示红色 `NOPE` 占位图标。

日志中出现的原生 `strength`、`dexterity` 等缓存警告属于游戏原生缓存路径，与本次白绮红色 `NOPE` 问题无关，不是根因。

## 禁止的错误修复方式

不得通过修改白绮 Power 的资源路径、改回共用占位图或增加静默回退来掩盖部署撕裂。源码中的资源路径和注册关系已经验证正确；这样修改只会隐藏 DLL 与 PCK 不一致的问题，并可能让后续资源继续错误加载。

## 正确修复步骤

1. 从当前同一份源码完整构建白绮 Mod，不能跳过 PCK 导出。
2. 确认 PCK 导出成功，并核对包内包含当前源码要求的全部 Power 图标，至少包括：
   - `InfiniteMarginPower.png`
   - `InfiniteDrainPower.png`
   - `ColorConservationPower.png`
3. 将本次构建产生的 DLL、JSON 和 PCK 作为不可拆分的同一批产物部署到游戏 Mod 目录。
4. 不得保留或复用上一次构建的旧 PCK，也不得只复制新版 DLL。
5. 启动游戏前，核对部署目录中 DLL、JSON、PCK 的构建批次、修改时间与预期产物一致，并再次检查 PCK 包内资源。

## 验收步骤

1. 完整停止游戏和自动游玩全栈，避免部署文件被锁定或部分覆盖。
2. 完整导出 PCK，并同批部署 DLL、JSON、PCK。
3. 启动前检查部署产物，确认不存在“新版 DLL + 旧版 PCK”的时间或内容差异。
4. 启动游戏并进入白绮战斗，逐项观察相关 Power 状态图标。
5. 确认 `InfiniteMarginPower`、`InfiniteDrainPower`、`ColorConservationPower` 等图标能够从新 PCK 正常加载，界面不再出现红色 `NOPE`。
6. 若日志仍有原生 `strength`、`dexterity` 缓存警告，应单独记录，不得将其误判为本问题复发；本问题的判定依据是白绮资源是否存在于部署 PCK，以及运行时是否仍出现白绮红色 `NOPE` 图标。

## 后续部署约束

以后每次新增或替换白绮图片资源后，必须执行完整 PCK 导出，并将 DLL、JSON、PCK 同批部署。启动前必须核对包内资源，禁止仅凭 DLL 构建成功判定 Mod 已更新完成。
