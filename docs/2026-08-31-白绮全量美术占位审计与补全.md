## 初始审计结论（历史基线）

本轮最初同时检查了素材布局和实际 C# / Godot 消费路径。当时活动资源中没有源码直接指向游戏的红色 `NOPE`，但存在大量“路径有效、语义仍是模板占位”的资源：58 张卡牌回退到 RitsuLib 卡图占位，23 个 Power 和孤高冠冕共用旧红色火焰遗物图，白绮能量球及能量标记仍是红色模板。此段只记录补全工作启动时的历史基线，不代表当前运行时完成度。

战斗五页 atlas、商店、休息、选人、顶栏头像、地图标记已经是白绮专属生产资源，不在本轮重画。`images/characters/` 下旧头像、旧选人图和旧地图标记已不被共享 V3 profile 消费，也不应为了“清目录”重复生成。多人四手势继续遵循 2026-08-28 用户批准的封闭运行时例外。

## 消费契约与生成路线

- 卡牌：每张一幅独立、不透明、完整场景图；运行时必须是 `1000×760 RGB8 PNG`。只使用 Codex 原生图像生成，源图经确定性中央 `25:19` 裁切与 Lanczos 缩放；不得走 EvoLink。
- 遗物、Power、能量球：独立透明 UI 消费者；运行时为 `256×256 RGBA PNG`，文本能量标记为 `24×24 RGBA PNG`。只使用 EvoLink `gpt-image-2` 原生透明请求，禁止抠图、色键、蒙版或 Alpha 修补。
- 每次付费透明生成保留原始返回图、完整 Prompt、脱敏请求参数和黑/白/游戏底 SourceOver 验收图。
- 所有图继续执行白绮身份、无武器和嘴部硬禁令。任何红线、猩红丝、液体、血迹或魔力不得接触或从嘴、唇、脸颊附近发出。

- `VivhiteCard.CustomPortraitPath` 按编译类型名解析 `images/cards/<CardType>.png`；不再允许 RitsuLib 占位回退。

## NOPE 图标部署诊断

红色 `NOPE` 的已确认原因是已部署 DLL 与 PCK 不属于同一构建批次：DLL 已请求新版独立资源路径，而落后的 PCK 尚未包含对应资源。该问题不是白绮资源注册或消费路径本身错误。静态资源通过不会自动修复游戏目录中的旧 PCK，因此当时制定的关闭条件是完整导出新版 PCK，并将 DLL、PCK 与清单按同一批构建结果一起原子安装。该条件现已满足：最终 PCK 哈希如“当前状态”所列，PCK 门禁为 `92/92`，游戏日志和实机 UI 均未再出现缺失资源、红色 `NOPE` 或裸本地化 key；此问题已经关闭。
