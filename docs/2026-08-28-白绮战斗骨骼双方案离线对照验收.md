# 白绮战斗骨骼双方案离线对照验收

## 目标

“不拆件只加骨骼”和“拆件并加骨骼”不能靠各自不同的自适应缩放预览比较。为此新增统一离线渲染器：所有候选都使用游戏实际 Spine GDExtension、Vulkan、相同 `1280×900` 画布、战斗场景 `.28` 缩放和 70% 制作比例契约。

工具位于 `tools/art/compare/preview/`。它不部署 Mod，也不操作、聚焦、停止或重启游戏及直播栈。

## 实现与踩坑

### 候选必须隔离导入

候选可能位于 Godot 项目外，也可能只有 `.spjson/.spatlas/PNG`。包装器会复制所需文件到被 Git 忽略、被 PCK 排除的 `Vivhite/bin/combat_compare_preview/stage/`，创建临时 skeleton-data wrapper，再用 headless Godot 导入。

Spine GDExtension 不是只按 `.spatlas` 文件所在目录找页图；它会参考包装器内的 `source_path`。拆件候选最初保留 `res://candidates/...`，导致页图加载失败并触发原生插件崩溃。最终方案只重写隔离副本的 `source_path`，让它指向 staged atlas，候选源保持逐字节不变。

### 同项目的 Spine 进程必须串行

两个 Godot 进程同时加载同一项目时会争用 GDExtension 自动建立的 `~libspine_godot...dll`。实测并发 import/render 会出现复制失败，甚至在扩展加载期崩溃。因此包装器复用项目级命名 mutex，并在 candidate import 到 Vulkan 捕获完成之间一直持有。

### 窗口不能最小化后等待逐帧信号

最初为了完全隐藏预览窗口，把 Godot 根 Window 设为 invisible/minimized。第一帧可以渲染，但之后 `frame_post_draw` 不再稳定推进，表现为一分钟只产生一帧。修正方式是：

- 进程用 `SW_HIDE` 启动；
- 窗口置于 `(-32000,-32000)`；
- 设置 `WINDOW_FLAG_NO_FOCUS`；
- 保持 Vulkan Window 可渲染，不再最小化。

这样既不会抢游戏焦点，也能连续捕获。

### 指标不应修改原帧

每张 1280×900 PNG 均直接保存 Vulkan SubViewport 输出。全分辨率 Alpha bbox 与触边由 Godot 原生 `get_used_rect()` 取得；质心和帧差使用最长边 256/320 像素的只读指标副本，再映射回原画布。这样保留可审计的原帧，同时把生产尺寸 synthetic 自测控制在约 5 秒。

## 2026-08-28 三方案实跑

最终产物：`.work/combat-rig-compare-preview/all-three-final-2/`。

共同条件：Windows DisplayServer、Vulkan、场景缩放 `0.28`、制作比例 `0.70`、每动画 5 帧。三套候选均通过：

| 候选 | 动画 / 帧 | 触边 / 空帧 / 静态动画 | 最大主体质心位移 | 最大像素变化率 |
| --- | ---: | ---: | ---: | ---: |
| 当前 runtime | 8 / 40 | 0 / 0 / 0 | 293.639 px | 0.05001 |
| 不拆件加骨骼 `whole_mesh` | 8 / 40 | 0 / 0 / 0 | 191.176 px | 0.05596 |
| 拆件加骨骼 `split_mesh` | 8 / 40 | 0 / 0 / 0 | 99.292 px | 0.05403 |

三套均真实加载 `default` skin、八个动画、`slash_mesh` / `eye_attach_slot`，以及 `attack_slash_start`、`heavy_slash_start`、`cast_eyes_start`、`clear_vfx`。共生成 120 张原始帧、24 张逐动画 contact sheet、3 张总 contact sheet，报告 `success=true`，无空帧、无画布触边、无静态动画。

最大质心位移包含独立魔法特效对整体 Alpha 质心的影响，适合做同条件量化对照，不能单独替代人工观察四肢、头发、裙摆和倒地姿态。总 contact sheet 仍需与逐动画帧一起人工验收。

## 人工视觉结论与边界

机器报告的 `passed=true` 只说明资源契约、逐帧渲染、非空、触边和变化检查通过，不代表动作已经达到最终美术质量：

- `split_mesh` 的死亡动作仍复用站姿 UV 部件。倒地后可见部件碎裂、尖刺和叠层异常；本轮只能证明拆件骨链能被 Spine/Vulkan 正常驱动，不能把死亡画面判为可用。
- `whole_mesh` 的死亡动作比当前整身刚体旋转多了变形，但最终姿态呈卷曲/折叠，仍不是自然、精细的侧躺倒地。
- 两套候选都只存在于制作候选目录和 `.work` 离线预览，从未部署到游戏。后续须分别修正死亡专用部件/网格与倒地姿态，再重复同一套机器检查和人工逐帧验收。
