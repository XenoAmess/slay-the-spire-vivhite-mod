# 2026-08-27 STS2-Agent PR #49 冲突解决

## 背景

上游 `CharTyr/STS2-Agent` 的 `main` 在合并 PR #48 后前进到 `bd6f106`，而 PR #49
仍基于旧的 `ca2a788`。两项改动同时触及 `GameStateService.cs` 和测试项目文件，GitHub
因此将 PR #49 标记为 `CONFLICTING`。

本地 fork 是 `sts2-ascend/third_party/STS2-Agent/` 下独立维护且被主仓库忽略的 Git
clone；冲突修复应提交到 fork 的 PR 分支，不能把 fork 工作树纳入 Vivhite 主仓库提交。

## 解决方案

1. 刷新 `upstream/main` 和 `origin`，确认 PR head 为
   `fix/unlock-confirm-private-base-field`。
2. 在该 PR 分支合入最新 `upstream/main`，使用 merge commit 避免重写已公开的 PR 历史。
3. `STS2AIAgent.Tests.csproj` 同时保留以下三个测试链接源码：
   `ReflectionMemberAccessor.cs`、`UnlockConfirmResolutionPolicy.cs` 和
   `CrystalSphereSettlePolicy.cs`。
4. `GameStateService.cs` 同时保留 unlock probe 签名，以及 Crystal Sphere 的 entity/button
   告警去重状态。三者职责独立，不能二选一。
5. 对比合并结果与 `upstream/main`，确认 PR 差异仍只包含 #49 的 7 个文件，没有覆盖
   #48 的 Crystal Sphere 行为。

合并提交为 `925fb3a`，已推送到
`XenoAmess/STS2-Agent:fix/unlock-confirm-private-base-field`。GitHub 随后将 PR #49 标记为
`MERGEABLE`。

## 验证

- `dotnet run --project STS2AIAgent.Tests/STS2AIAgent.Tests.csproj -c Release`：48 项通过。
- `python -m unittest discover -s tests -v`（`mcp_server/.venv`）：29 项通过。
- `dotnet build STS2AIAgent/STS2AIAgent.csproj -c Release`：0 warning、0 error。
- `git diff --check`：通过，且没有残留冲突标记。

本机 PATH 中优先命中的 `dotnet` 没有 SDK，验证时必须显式使用
`C:\Users\xenoa\AppData\Local\Microsoft\dotnet\dotnet.exe`。完整真机回归脚本会停止并重启
游戏；自动游玩栈活跃时不要仅为源码冲突处理运行它，避免中断当前对局。

## 注意事项

- 处理跨 PR 冲突时不能只删除冲突标记；需要从最新上游重新检查最终 PR diff，证明两边功能都在。
- 对公开 PR 分支优先合入上游；若无必要，不使用 rebase + force-push。
- 推送并确认 PR 可合并后，维护工作区应切回 fork 的 `main`，避免后续部署误在 PR 分支继续开发。
