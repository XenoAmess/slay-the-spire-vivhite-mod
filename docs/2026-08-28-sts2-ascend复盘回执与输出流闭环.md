## 本轮机制修复

1. 回执解析接受冒号行及两/三列 Markdown 表格；包 id 必须精确匹配，合法状态后允许括号、冒号或
   破折号说明（兼容 GLM 实际产出的 `integrated（明细见…）`）。正文子串、额外状态词和多余列不会误关包。
2. 对漏认的历史回执，只检查上游提交中新增的报告行。`integrated` 必须与同一提交里的生产实质改动
   同时成立，并在写 manifest 前再次确认提交属于 upstream。
3. 自动恢复保持单 worker 串行顺序：
   `committed receipt → replay queue reconcile → ledger/quarantine host closure`。启动和 60 秒维护都会走
   这条幂等事务；不会自动套失败补丁，也不会绕过清单直接删除取证包。
4. 输出流保留 `read1(8192)`。EOF 且队列为空时先正常结束；队列有待翻译 backlog 时不告警、不触发
   stall；真实静默写入 `qsize`、`reader_done`、`proc_poll`、`last_raw_idle` 供下次定因。
5. watchdog 统一为 15 分钟告警、30 分钟终止，8 小时整轮预算不变。
6. 队列批量单测隔离全部失败包维护入口，避免测试误读或改动真实 `review_salvage` 状态。
7. private Git 临时目录统一使用 Windows 只读解除与短重试清理；worker 启动只回收超过 5 分钟且名称
   精确匹配 `capture-index` / `validation-index` / `retry-index` 的直属目录。完整 sandbox、snapshot、
   失败包及其他目录不参与该扫描，持续被占用时仍保留并记录，而不是强删。
8. 隔离仓和 raw clone 的 Git 子进程通过临时环境启用 `core.longpaths=true`。这修复了深层
   `generated/.../output.request.json` 在 `add --all --force` 阶段的 `Filename too long`，仍将全部
   cache/rejected 路径写入 inventory；不修改 repo/global Git 配置，也不以忽略文件规避错误。

## 运行与监控注意

- 用户部署的其他服务可能短暂重启。巡检应结合 session id、PID 创建时间、health 和连续失败时长；
  短暂且自动恢复的抖动不触发第二套 Start，也不应被归为 GLM stall。
- Brain 运行中的 Python 模块不会因工作树 `.py` 变化原地 reload。优先等当前 GLM/当前局自然结束后的
  runner 热重启；确需主动加载时使用统一 `Stop-Agent.ps1 -KeepGame` 和 `Start-Agent.ps1 -SkipDeploy`，
  将断流控制在两分钟内。
- 临时 Git private-index 目录与完整失败取证包不是一类数据。前者可在确认前任 worker 已退出后按固定
  前缀回收；后者必须继续由 replay lineage 和最终清单事务决定是否删除。
