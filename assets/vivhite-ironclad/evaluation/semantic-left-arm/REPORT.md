# semantic-left-arm 组件级 Vulkan 验收报告

## 结论

该评估包证明灰盒消费者能够按白绮战斗场景的实际 `0.28` 缩放，在 Windows Vulkan 与
游戏使用的 Spine GDExtension 下加载并播放全部八个契约动画。40 个采样帧全部非空、未触碰
画布边缘，八个动画均产生可观测变化。

本结论只批准“屏幕左侧／角色远侧／解剖右臂”的消费结构和关节覆盖门禁，不批准灰盒图进入
正式 atlas，也不代表仓库已经拥有可发布的远侧手臂美术。

## 冻结的消费结构

- 默认两件：`far_upper_arm`、`far_forearm_hand`。
- 腕部只保留测量锚点；只有真实美术在极限姿势失败时才升级成三件。
- 固定后到前层序：远侧上臂、远侧前臂手、躯干肩盖。
- 蓝金肩饰由躯干肩盖持有，上臂只提供藏在肩盖下方的实体搭接，不得重复肩饰。
- 该手臂不持有 `slash_mesh`；攻击魔法弧属于屏幕右侧近手，眼部特效属于头部。

旧 `arm_left_*` 名称是屏幕侧别名。结合角色正面设定中的非对称蓝金肩饰、当前整身母版、
目标 split consumer 的 UV 与 draw order，可确定该组实际是角色解剖右臂并位于躯干之后。

## 源码与素材审计

运行时 `combat.tscn` 只消费一个 Spine skeleton、`slash_mesh` 和 `eye_attach_slot`，并不按名称
消费手臂 region。当前正式构建器使用单个 `vivhite_body` 加权网格；手臂名骨骼只是同级形变
控制，不能当作独立部件源。

仓库内 `0018` 与 `0022` 都是单帧整身图，只能提供身份、屏幕侧别和关节点证据。历史拆臂
region 位于污染素材链，禁止重新使用。因此灰盒 atlas 由确定性诊断色块构成，未使用付费生图，
也未从污染图创建或修补 Alpha。

## Vulkan 验收

测试环境和采样参数：

- Godot 4.5.1 / Spine 4.2.43；
- Windows Vulkan Forward+，NVIDIA GeForce GTX 1060；
- 画布 `1280×900`，场景缩放 `0.28`；
- `idle_loop`、`low_health_loop`、`relaxed_loop`、`attack`、`attack_heavy`、`cast`、`hurt`、
  `die` 各按 `0/25/50/75/100%` 采样五帧。

自动结果：八个动画全部通过，共 40 帧，空帧 `0`、画布触边 `0`、失败动画 `0`。最大质心
位移为 `12.0976037979126 px`（`die`），最大变化像素比为 `0.00170833333333333`（`cast`）。
灰盒本身只占完整战斗画面的一小部分，因此变化像素比只用于确认动画非静态，不作为动作质量分数。

人工极限姿势检查：

- `cast`：上臂 `-35°`、前臂手相对 `-48°`。肩根保持在躯干肩盖之后，肘部连续，空手未断开。
- `die`：上臂 `+71°`、前臂手相对 `+55°`。远臂折入躯干后方且无断缝，仅空手露出。
  该结果只通过遮挡门禁；最终死亡构图仍由独立死亡姿势工作线负责。

## 证据文件

- `contact-sheet.png`：组件八动画总接触表。
- `contact-sheets/*.png`：八个动画各自的五帧接触表，便于按动作放大复核。
- `vulkan-summary.json`：比较器原始 summary 的逐字节副本，保留每帧 Alpha bbox、帧哈希、
  变化指标、Spine 契约及 paired split reference 数据。
- `metrics.json`：从原始 summary 提取的组件必要指标和人工极限姿势结论。
- `SHA256SUMS`：本目录交付文件的 SHA-256 清单；清单不自包含自身哈希。

原始逐帧 PNG 继续保留在忽略目录 `.work/semantic-left-arm-vulkan-v2/`，本评估包只保留可读的
接触表和机器报告，避免把 40 张重复证据加入仓库。

## 范围声明

本轮未调用 EvoLink 或其他付费生成服务，未操作游戏进程、直播或正式运行时素材。灰盒及其
接触表均不得发布为角色美术；真实远侧手臂接入后必须重新执行同一静态与 Vulkan 门禁。
