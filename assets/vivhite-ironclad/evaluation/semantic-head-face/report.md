# 白绮头脸语义组离线验收报告

## 结论

- 下一道跨部件整合门禁推荐使用 `head0045-weighted` 的独立附件与权重，但总装时必须
  应用下文的蓝蝶/前发层序纠正，不能整份照抄当前候选 `.spjson`。0045 在批准的 `0.70`
  制作比例与场景 `0.28` 缩放下，银发、紫瞳和金色眼镜的身份辨识最稳定；加权前后发在
  八个动画中没有观察到头皮洞、额发/脸断层或翻面。
- `head0045-rigid` 是保守回退。它保留同一套 0045 头脸组合，但前后发整体跟随头骨，
  不提供发梢局部形变。
- `head0044-rigid` 仅保留为历史对照。它更紧凑，但游戏显示尺寸下脸和眼镜的辨识度
  明显弱于 0045。
- 三支都仍是研究候选，不得直接替换正式运行时资源。

## 证据边界

历史三层组合实际只证明了：

```text
0031 后发 -> 0044 头脸 -> 0033 前发
```

它不是 0045 的组合证据。本轮分别以记录过的变换重新构建并验证：

```text
0031 后发 -> 0044 或 0045 头脸 -> 0033 前发 -> 0030 蓝蝶
```

本证据包接触表实际渲染的候选层序为：

```text
后发 -> torso -> 头脸 -> 前发 -> 蓝蝶 -> 前景右臂
```

这只证明旧层序下三支候选能够加载、运动且没有明显断层，不是蓝蝶/前发顺序的 A/B
证据。后续 `semantic_butterfly` 专项完成了 16/16 Vulkan 对照，证明蓝蝶必须画在前发
下方，由前发遮住蓝蝶素材的深蓝/金色连接片。因此总装必须采用：

```text
后发 -> torso -> 头脸 -> 蓝蝶 -> 前发 -> 前景右臂
```

本目录保留旧层序的原始输出以维持证据真实性，不会篡改接触表或把它误报成已验证新
层序。总装完成纠正后必须重新做 Vulkan 接触表。

候选 atlas 中的四个语义象限是原生 RGBA 源图的逐像素副本；没有对源 Alpha 做阈值、
蒙版、色键或清理。详细源路径、变换与哈希位于候选目录各自的 `candidate.json` 及
`Vivhite/tools/candidates/semantic_head_face/consumer-contract.json`。

## Vulkan 结果

原始报告为 [summary.json](vulkan/summary.json)，其 SHA-256 为：

```text
22e24a49a6596506c2eb5a446e99ee78bd45f973ca9507cc14b71e0073b351af
```

验收环境与覆盖：

- Windows 显示后端、Vulkan 渲染器；
- 画布 `1280 x 900`；场景缩放 `0.28`；制作比例 `0.70`；
- 三个候选，每个覆盖八个战斗动画，每动画均匀采样五帧；
- 共 120 帧，空帧 `0`、触边裁切 `0`、失败帧 `0`、报告错误 `0`；
- 三支的 `relaxed_loop` 首末帧哈希分别相同，证明 0 与 `12.000001` 秒边界闭合，
  满足商店复用同一战斗骨架、从任意相位播放时的基本循环契约；
- `die` 在 `1.05` 秒同时卸载后发、头脸、前发和蓝蝶，交给独立倒地素材。

`vulkan/<candidate>/contact-sheet.png` 是该候选八个动画的原始总接触表；
`vulkan/<candidate>/contact-sheets/*.png` 是原始逐动画接触表。它们均由隐藏 Vulkan
渲染器直接输出，没有再次重绘；其中蓝蝶仍位于前发上方，不能作为纠正后层序的视觉
通过证据。

## 放大人工审查

`review/` 内的图片由已保存的 Vulkan 帧进行确定性裁切、SourceOver 到蓝灰底并放大，
只用于检查像素级叠层，不是新的美术源，也不会进入 atlas：

- `*-closeup.png`：三候选整身/上身并排；
- `*-face-pixels.png`：idle、relaxed、hurt 的头脸像素级并排。

人工复核重点包括银发轮廓、紫瞳、金镜、前发遮挡、后发与颈肩关系、蓝蝶固定点以及
hurt/cast/die 极端阶段。120 个标准采样中未观察到头皮裸露、前发穿脸、眼镜错层、
蓝蝶绕画布中心旋转、旧合并头残片或画布裁切。0045 加权支的额外运动在游戏尺寸下
非常克制，但其渲染像素确实不同于刚性支，且没有形成可见接缝。

上述观察不再用于认可蓝蝶的最终画序；蓝蝶专项发现的连接片暴露问题构成更直接的
跨组件证据，优先级高于本线非 A/B 的标准采样。

## EyeFire 未完成门禁

结构与坐标契约已经通过：

- 正式战斗场景消费 `Visuals/EyeSlot/EyeFire`；
- `EyeSlot.slot_name = "eye_attach_slot"`，并设置 `show_behind_parent = true`；
- `eye_attach_slot -> vivhite_eye_anchor -> vivhite_head`；
- 0045 眼中心从源像素 `[592, 474]` 映射到头局部 `[28.125, 13.359375]`；
- 0044 眼中心从源像素 `[565, 475]` 映射到头局部 `[18.6328125, 13.0078125]`；
- `cast_eyes_start` 保持在 `0.25` 秒。

但本证据包的比较器只实例化候选骨架，没有实例化正式战斗场景的 `EyeSlot/EyeFire`
子树。因此只能认定眼部结构和坐标契约通过，不能认定完整 EyeFire 场景合成通过。
整合后必须在正式 combat 场景的隐藏 Vulkan 预览中检查火焰是否覆盖双眼、是否被头发
错误遮挡，以及 `clear_vfx` 后是否完全消失。

## 晋级阻塞

1. 周围 split-body 仍包含临时 UV 拆片，当前组合不可发布。
2. 总装必须把 `semantic_butterfly` 移至 `semantic_front_hair` 下方，并重新渲染八个
   动画；当前接触表没有验证纠正后层序。
3. 所有相邻语义组件合并后，必须重新检查 setup pose 与最大旋转下的颈肩、前后发和
   前景手臂层序。
4. 必须补齐真实 combat `EyeSlot/EyeFire` 场景合成门禁。
5. 只有上述门禁全部通过，才能把 `head0045-weighted` 复制进正式运行时骨架。

完整文件清单与 SHA-256 位于同目录的 `SHA256SUMS.txt`；该清单不包含自身。
